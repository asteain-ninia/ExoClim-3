# 実験記録: 陸の対流・前線雲(R1b)— 主判定を満たす。較正へ進む

日付: 2026-08-07
事前登録: [docs/事前登録_陸の対流雲_2026-08-07.md](事前登録_陸の対流雲_2026-08-07.md)
道具: `scripts/exp_land_cloud.ts`
実装: b6c69a6(既定 `landCloudBoost = 0` で無効、旧結果と厳密一致)

## 埋めた欠落

雲アルベドの変調で、**ストームトラック雲・層積雲・海峡雲がすべて `oceanFrac`
倍で入っており、陸の雲は ITCZ 近傍しか増えない**構造になっていた。
夏の大陸は月 100mm 以上降っていても雲が基準値のまま。

前パスの降水を飽和させて雲の因子へ足す:

```
landCloud = landCloudBoost · 陸率 · min(1, 月降水 / landCloudSupplyNormMm)
```

## 結果

```
boost   40〜50°N  50〜60°N  60〜70°N   文字    v3      大分類  詳細   年較差  乾燥  熱帯
    0    +4.77    +5.38    +1.08    31.3%  85.769  75.22  44.07  8.97  3/3  2/2
 0.15    +3.40    +4.02    +0.04    35.8%  85.336  74.54  44.53  8.85  3/3  2/2
  0.3    +2.02    +2.66    −0.99    38.7%  83.597  73.03  43.67  8.74  3/3  2/2
  0.5    +0.16    +0.82    −2.38    36.4%  75.448  68.39  39.29  8.62  3/3  2/2
```

- **主判定(40〜50°N と 50〜60°N が両方 +3.0°C 以下)は boost 0.3 で成立。**
- 乾燥ゲート 3 件・熱帯ゲート 2 件はすべての設定で維持。
  予測どおり**砂漠には効かない**(降水がほぼ 0 なので飽和項が 0)。
- 数値的健全性は全設定で残差 5.9e-5。**この機構は収束を悪くしない**
  (R1 の帰還項が評価費用を 2.5 倍にしたのと対照的)。
- 年較差 RMSE が **8.97 → 8.62 と単調に改善**。
- 副判定の「第 3 文字の一致 45% 以上」は **未達**(最良 38.7%)。

**事前登録の棄却条件(3 段階試して主判定に届かない)には該当しない。**

## 読み取れること

### 機構は予測どおりに働いた

事前登録に書いた予測がすべて当たっている:

- 効いたのは**夏の中高緯度の陸**。
- **砂漠は動かない**(乾燥ゲート維持)。
- 熱帯も壊れない(二重に曇らせる懸念は外れた)。
- 大きさの見積り「boost 0.4 で 3〜6°C の冷却」に対し、実測は boost 0.3 で
  50〜60°N が 5.38 → 2.66 の **2.7°C**。桁が合っている。

### ただし全球成績は落ちる

v3 は boost 0.3 で −2.17、0.5 で −10.3。大分類も単調に低下する。
原因は**効きすぎる場所がある**ことで、60〜70°N が +1.08 → −0.99 と
行きすぎている(この帯はもともと合っていた)。

飽和量 80mm/月に対し、60〜70°N の夏の降水は 54mm/月なので 0.68 倍の雲が乗る。
50〜60°N(112mm/月)は 0.93 倍。**飽和量を上げれば両者の差が開く**ので、
`landCloudSupplyNormMm` は意味のあるつまみであり、較正の探索空間へ入れる。

### 詳細一致は boost 0.15 が最良

```
boost 0.15 で 詳細 44.07 → 44.53(+0.46)、文字 31.3 → 35.8(+4.5)、
              年較差 8.97 → 8.85、v3 −0.43
```

**単発でこれだけなら、それ自体が純増**である。主判定に届く 0.3 は
v3 を 2.17 落とすので、**適切な boost は 0.15〜0.3 の間**にあり、
他の定数と釣り合わせて決めるべき量になる。

### 第 3 文字が 45% に届かなかった理由

夏の気温をほぼ直しても文字は 38.7% までしか上がらない。
第 3 文字は最暖月だけでなく **10°C 以上の月数**でも決まり、
さらに冷やしすぎた帯では D 帯そのものから外れる(観測 D なのにモデル E)。
仮想実験の上限 84.8% は「最暖月と月数を**両方**観測に差し替えた」値なので、
最暖月だけ直しても届かないのは筋が通っている。

## 判断

**機構としては採用する。ただし boost の値は較正に決めさせる。**

理由:
- 主判定を満たす(事前登録の棄却条件に該当しない)。
- 地域ゲート(乾燥 3・熱帯 2)を壊していない。
- 数値的健全性を損なわない(残差・費用ともに不変)。
- 埋めたのは**構造的な欠落**であって、地球に合わせ込んだ補正ではない。
  「よく降る陸は曇る」は他の惑星でも成り立つ。
- v3 の低下は「効きすぎる場所がある」ことによるもので、
  飽和量と他の定数で釣り合わせられる性質のもの。

較正の探索空間へ入れる:

```
['landCloudBoost', 0, 0.45]
['landCloudSupplyNormMm', 40, 200]
```

出発点は **boost 0.2 / 飽和量 100mm**(単発で純増だった 0.15 と、
主判定を満たす 0.3 の間を取り、飽和量は 60〜70°N の効きすぎを緩める側へ)。

**最終採否は較正後に 5 点で総合判断する**(数値的健全性 / 新旧両目的関数 /
季節指標 / 地域ゲート / 未見評価)。単発の主判定成立は採用そのものではない。

## 教訓

- **片側にしか掛からない項を見つけたら、反対側の欠落を疑う。**
  雲の 3 項がすべて `oceanFrac` 倍だったことが、そのまま「陸の夏が暑い」の
  原因だった。しかも `stormSeason` には陸用の分岐が書かれているのに
  外側で 0 倍される**死んだ分岐**が残っており、意図と実装の食い違いが
  そのまま化石として残っていた。
- **診断が一変数まで絞れていれば、機構の当たりも大きさも事前に書ける。**
  「boost 0.4 で 3〜6°C」と書いて実測 2.7°C。事前登録が予測の検算になった。
- **主判定が通っても全球成績が落ちることはある。** 構造の欠落を埋めると
  他の定数の釣り合いが崩れるので、**単発の成績で採否を決めない**。
