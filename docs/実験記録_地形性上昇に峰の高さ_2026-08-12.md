# 実験記録: 地形性上昇に峰の高さを使う(段 13)— 棄却。格子が機構を殺していた

日付: 2026-08-12
事前登録: [事前登録_地形性上昇に峰の高さを使う](事前登録_地形性上昇に峰の高さを使う_2026-08-12.md)

## 掃引 1: 峰の混合率

```
混合率      0     0.3    0.6    1.0
v3      84.378 84.380 84.387 84.339
大分類   74.14  74.14  74.14  74.12
詳細     44.29  44.27  44.30  44.20
patagonia 年降水／観測  1.48  1.48  1.47  1.47
```

**まったく動かない。** 判定 1(patagonia を 1.15 以下)は完全に不成立で棄却。

## なぜ動かないか — 桁で分かった

地形性上昇は `1 + boost × min(2.5, 上昇流 / 基準勾配)` で、
基準勾配が **800(= 8 m/s × 100 m/km)** とベタ書きされていた。

```
                        勾配      基準800比   持ち上げ倍率
パタゴニア（平均 718m）  4.6 m/km    0.046      1.05
同（峰 1187m）          7.6 m/km    0.076      1.08
チベット（峰 4591m）    29.4 m/km    0.294      1.31
```

**100 m/km という傾斜は 1° 格子では作れない。** 実際の比は 0.05 前後で、
持ち上げは 5% の効果しか持たない。上限 2.5 には遠く及ばない。
峰を使っても 5% が 8% になるだけだった。

**格子の粗さが機構を殺していた。**

## 掃引 2: 基準勾配そのもの

名前を与えて(`orographicRefSlope`)掃いた。

```
基準勾配    800    400    200    100
v3      84.378 84.367 84.396 84.163
大分類   74.14  74.14  74.17  73.99
patagonia 年降水／観測  1.48  1.47  1.43  1.37
```

**持ち上げを 8 倍にしても 1.48 → 1.37**(目標 1.15)。しかも 100 では
大分類が落ちる。200 がわずかに最良だが差は数値の床の内で、採るに足りない。

**地形性上昇の強さではパタゴニアの過剰を説明できない。**

## 判定: 棄却(混合率 0・基準勾配 800 のまま)

配管と定数は残す。**「格子の粗さが基準値を無効にする」型の例**として、
他の機構にも同じ疑いを向けるために名前を残しておく価値がある。

## この後に分かったこと(重要)

パタゴニアのゲートは**そもそも降水の問題ではなかった**。
