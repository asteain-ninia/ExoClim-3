# 事前登録: 亜熱帯の冬雨機構(地中海型)— 境界を正しい場所に置く機構の第 1 弾

日付: 2026-08-23(実装前に書いた)
文脈: v32 採用(正しい風を優先)で大分類 −0.4 を受容した。失点の性質は
「風が変わって気候帯の境界が動いたのに、正しい場所へ置く機構が無い」。
その最も明確な欠落が**亜熱帯の冬雨**である。

## 根拠(2026-08-18 の分解診断、結果に依存しない事実)

冬雨型セル(亜熱帯)の月別分解:
```
観測ピーク 1.3 月 / モデル降水 8.5 月 / G(持上げの積)**平坦(振幅 0.10)**
```
中緯度は G の暦が正しい(12.4 月・振幅 0.57)のに、**亜熱帯は冬雨を作る
機構が実質届いていない**。雨は供給の暦(8 月)の写しになっている。
実物の地中海型は「夏 = 亜熱帯高気圧の沈降下、冬 = 高気圧が赤道側へ退いて
ストームトラックの南縁が届く」で成立する。モデルのストーム帯は
リッジ+4° から始まるため、リッジが冬に赤道側へ退いても
**亜熱帯(リッジより赤道側)には決して届かない**。

## 実装(既定 0 でビット一致)

新定数 `winterStormEquatorwardReachDeg`(既定 0)。冬(winterDepth01 > 0)の
とき、ストーム帯の赤道側の縁 `stLo = |ridge| + 4` を
`|ridge| + 4 − winterStormEquatorwardReachDeg × winterDepth01` まで下げる。
= 冬だけストーム帯が赤道側へ張り出す。地理中立(リッジ相対・季節相対)。

## 予測(結果を見る前に固定)

55. 亜熱帯の冬雨型セルの G の振幅が 0.10 → **0.25 以上**へ(分解診断で確認)。
56. 位相(帯別平均)が改善(v7b の位相項が下がる)。
57. 地中海ゲート(mediterranean_cs_present)の Csa/Csb 被覆が増える。
58. 大分類は −0.2 以内(冬に亜熱帯を湿らせるので B→C の巻き添えが出うる。
    出るなら量を測ってから較正に委ねる)。

## 判定

- 55・56 成立 → SPACE に [0, 8] で投入し v33 較正へ。
- 55 が外れ(G が平坦のまま)→ ストーム帯の位置ではなく強度側の問題。
  stormTrackWinterBoost との相互作用を分解してから再設計。
