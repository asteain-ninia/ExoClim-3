## なぜ棄却済みの機構を測り直すのか(理由を先に明記する)

`thermalLowHpaPerK = 0` は 2026-08-11 に**正規の手続きで棄却された**。
むやみに蒸し返さないのが原則である。それでも測り直すのは、状況が 3 点変わったから:

1. **判定に使った物差しが変わった。** 当時の判定は v3(ゲートの崖あり・分布形なし)。
   v3 が −1.37 という棄却理由は、いまの凍結目的関数では再計算しないと意味を持たない。
2. **照準が変わった。** 今日、失点の 32% が C→B 誤分類で、その 39% が米州東と
   確定した。当時の記録を読み直すと、**熱的低気圧は米南東をまさに 54% 改善していた**
   (−123 → −57)。最大の失点源に効く機構を、旧物差しの総合点で捨てていた
   可能性がある。
3. **悪循環の構造が見えた。** 今日の diag_monsoon_inflow で、C→B セルの夏の
   子午面風は**赤道向き**(−0.79 m/s)と分かった。熱的低気圧の深さは
   パス 1 の降水の湿りで決まり(段 9 第 2 版)、以後更新されない。
   乾いている→低気圧が浅い→南風が吹かない→乾いたまま、の**乾いた平衡に
   構造的に凍り付いている**。振幅 0 はこの悪循環の議論すらできない。

なお当時の「外れに転じたセルでは場も悪くなっている」(物差しの問題ではない)は
重い証拠であり、**この測り直しで覆るとは限らない**。覆らなければ棄却は維持する。

## 測ること

```
npx tsx scripts/sweep_lever.ts thermalLowHpaPerK 0,0.7,1.3 --parallel 3
```

v23 相当の現行定数の上で(2026-08-11 は v20 の上だった)。
測る量: 分位 8 点・分布誤差・連続部分・大分類・詳細・気温 RMSE・地域比・健全性。
有望なら追加で `diag_c_to_b` を係数 0.7 の定数で走らせ、**C→B の面積が
実際に減るか**を直接数える。

## 予測(結果を見る前に固定)

1. **気温 RMSE は単調に改善する**(当時 3.900 → 3.738 と同じ向き)。
2. **大分類は下がる**(当時 73.92 → 72.52 と同じ向き)。下げ幅は当時と同程度
   (係数 1.3 で −1.4 前後)と読む。定数が v20 → v23 に変わっても
   この機構の効き方の骨格は変わらないと見る。
3. **連続部分(continuousV3)は 0 が最良のまま**。つまり**棄却は維持される**と読む。
   測り直しの主目的は採否ではなく、**C→B への効き方の分解**を得ること。
4. 分布誤差はわずかに悪化する(内陸を湿らせる機構なので、過剰な乾いた端 1% 分位を
   さらに押し上げる)。

**予測 3 が外れたら**(v4 では 0.7 以上が勝つ): 棄却の根拠が物差しの歪みだった
ことになる。その場合は利用者に報告して、探索空間へ入れる裁定を仰ぐ
(凍結目的関数の下での探索空間の変更は較正のやり直しを意味するため)。

**予測 3 が当たったら**: 棄却維持。ただし米州東への効きが確認できれば、
「東アジアを壊さずに米州東だけ助ける」形へ機構を分解する設計
(例: 熱的低気圧の深さを湿りでなく**海からの湿潤流入の有無**で決める)の
根拠として実験記録に残す。
