# 事前登録: 貿易風帯の子午面成分をモンスーンで反転させる(段 41)

日付: 2026-08-16(実装前に書いた)
前段: [実験記録_夏の高気圧の西方張り出し](実験記録_夏の高気圧の西方張り出し_2026-08-16.md)

## 何を直すか

段 39 の追測で決定的な事実が出た。

```
C→B 誤分類セルの夏の極向き風   −0.79 m/s   ← 赤道向き
当たっている C の夏の極向き風   −0.44 m/s   ← **これも赤道向き**
```

**モデルの亜熱帯の夏は、どこも南風が吹いていない。**
特定の地域の欠陥ではなく、風の定義そのものに由来する。

`step04_airflow.ts` を読むと構造が確定する:

```ts
if (lat > itczLat && lat <= ridgeN) {          // 北半球の貿易風帯
  bu = -tradeWindMs * t * dirSign * zonalRev;  // 東西成分は crossEq で反転できる
  bv = -tradeWindMs * 0.4 * t;                 // **子午面成分は常に赤道向き固定**
}
```

- 子午面成分 `bv` は**季節にも海陸配置にも依存しない**。
  貿易風帯にいる限り、夏でも冬でも、大陸東岸でも海の真ん中でも赤道向き。
- 既存の `crossEquatorialMonsoon`(WL#29、既定 0)は
  **`zonalRev` を通じて東西成分しか反転させない**。子午面成分には触っていない。

実物の夏のモンスーンは、**下層で海から大陸へ吹き込む極向きの流れ**である
(インド洋 → インド亜大陸、南シナ海 → 華南、メキシコ湾 → 米南東)。
コリオリで西風成分も持つが、**水を運ぶのは子午面成分**のほうである。
モデルにはこれが無い。

## どう直すか

`crossEquatorialMonsoon` と同じ「ITCZ の赤道からの変位」を駆動源にして、
**子午面成分にも反転を掛ける**。既存の東西反転と対になる形にする。

```ts
// 既存: 東西成分の反転（crossEq は ITCZ 変位から 0〜1）
const zonalRev = 1 - 2 * crossEq;
// 追加: 子午面成分の反転（同じ crossEq に別係数を掛ける）
const meridRev = 1 - 2 * crossEq * K.monsoonMeridionalReversal;
...
bv = -K.tradeWindMs * 0.4 * t * meridRev;   // 1 で従来（赤道向き）、−1 で極向き
```

- `monsoonMeridionalReversal` の**既定は 0**。このとき `meridRev = 1` で
  **従来とビット一致**(較正 v24 走行中のため必須)。
- 駆動源は既存の `crossEq`(ITCZ が赤道からどれだけ離れたか)をそのまま使う。
  **新しい地理的な条件を持ち込まない** — ITCZ の変位は海陸配置と日射から
  決まる量なので、地理中立が保たれる。逆行自転でも ITCZ の変位で決まる。
- 東西の反転(`crossEquatorialMonsoon`)とは**独立の定数**にする。
  片方だけ効かせられるようにしないと、どちらが効いたか分からない。

## 予測(結果を見る前に固定)

`sweep_lever.ts monsoonMeridionalReversal 0,0.3,0.6,1.0` で測る。

1. **C→B セルの夏の極向き風が正へ動く。** −0.79 → 係数 1.0 で **−0.2 以上**。
   (段 39 は +0.06 しか動かせなかった。こちらは風の定義を直接変えるので桁が違う)
2. **インドが最も動く。** 0.45 → 係数 0.6 で **0.55 以上**。
   ITCZ の変位が最大になるのがインド洋〜南アジアで、駆動源がそこで最強のため。
3. **米南東も動く。** 0.37 → **0.42 以上**。
4. **コンゴ(対照)は 1.2〜1.35 に留まる。** 赤道直上で ITCZ 変位が小さいため。
5. **連続部分が 70.5 以上**(現行 70.322)。
6. 数値的健全性は全水準で保たれる。

**予測 1 が当たり、かつ 5 が当たれば採用候補**として利用者に裁定を仰ぐ
(探索空間へ入れる = 較正のやり直しを意味するため)。

## 判定

- **予測 1 が外れたら**(風が動かない): 子午面成分の係数 0.4 が小さすぎるか、
  気圧勾配風に上書きされている。風の合成の内訳を診断する。
- **予測 1 は当たるが 5 が外れたら**(風は動くが成績が落ちる): 
  水は運ばれるが別の何かを壊している。何が落ちたかを分解し、
  **段 39 と同じく「説明できる改善」でなければ採用しない**。
- **予測 4 が外れたら**(コンゴが壊れる): 赤道域まで反転が及んでいる。
  ITCZ 変位による窓の掛け方を見直す。

**どの結果でも目的関数の重みは動かさない。**

## 較正との関係

較正 v24 が走行中である。**既定 0 でビット一致**なので実装しても影響しないが、
採用する場合は探索空間の変更 = v24 の打ち切りになる。
その判断は利用者に仰ぐ(私の一存では動かせない)。
