# 事前登録: W の熱力学係留(RH フロア)— 飽和からの距離が凝結を駆動する

日付: 2026-09-02 朝(実装前に書いた)
文脈: [事前登録_Wの実寸化](事前登録_Wの実寸化_2026-09-02.md) の帰結。
W 監査で確定した第 2 の壁(W を RH·W_sat へ積む熱力学の錨が模型に無い)への処方。

## 機構(物理)

実物の可降水量は RH 70〜80% × W_sat(T) にほぼ普遍に係留される
(クラウジウス・クラペイロン)。凝結は「W の量」ではなく
「飽和からの距離」が駆動する。現行の線形凝結 C_lin = lin·W は
W=5mm の乾いた柱からも容赦なく取り立てるため、W は錨なしの配管算術に落ちる。

**変更**: C_lin = lin·W → **lin·max(0, W − floor)**、
floor = `condensationRhFloor` × W_sat(T)(セル別・月別)。
- rhFloor = 0 で floor = 0 → **従来と厳密一致**(max(0, W−0) = W)。
- 暖かい柱ほど床が高く W を溜める(CC の向き)。寒い柱は床が低く
  冬の凝結は保たれる。
- 床下の W は凝結を免除され輸送で生き残る → 移入の実効距離が伸びる
  (L×7 で実証した冬雨符号 88 日正転の効果を、東岸全滅の代金なしで
  狙う — L は水も運ぶが「どこでも降らせない」副作用があった。床は
  「乾いた柱では降らせない」だけで、湿った柱の凝結は不変)。
- cap(対流)経路・鉛直輸出・拡散は不変。

## 実装(src/sim/moisture_transport.ts + step06)

- ソルバに `linearFloorMm?: ArrayLike<number>` を追加。
  枝: W > floor で対角に lin・rhs に +lin·floor / W ≤ floor で lin を対角から
  除く(capacity の枝機構に相乗り。floor 指定時は掃引ごとに行分解)。
  残差・最終凝結も同じ式で整合(不変量テストの門を通す)。
- floor 指定時は直接解法(BiCGSTAB)を使わず緩和経路(非線形のため)。
- step06 が rhFloor > 0 のとき floor 場 = rhFloor·W_sat(T) を作って渡す。
- 新定数 `condensationRhFloor`(既定 0)。CPU のみ(EBM 非接触)。

## 掃引と測定

rhFloor ∈ {0, 0.5, 0.7}(1°・v42 定数・L は現行のまま)。測るもの:
W 帯別(対 観測)・帯×季節型・fitness・大分類・詳細・主要ゲート・分位 1%・
輸送ソルバの非収束数。

## 予測(実装前に固定)

84. W(海 15-35)7.0 → rhFloor 0.5 で **≥ 15mm**、0.7 で ≥ 20mm
    (床 26/37mm に向けて積む。輸出との綱引きで床の 6〜8 割と読む)。
85. **35-90 冬雨の符号 −76.6 → ≥ +15 日**(床下 W の長距離生存で冬の移入が
    立つ)。L×7 が出した +88 日と同符号・より穏やか。
86. 単独 fitness 損は −3 まで受容(全再分配。判定は 84・85 の物理の針)。
    ただし東岸ゲート(us_southeast・east_asia)が L×7 のように全滅
    (share < 0.1)するなら床の設計を疑う。
87. 健全性 PASS・輸送非収束 0 を維持(床の枝追加で収束が壊れないか)。

## 判定

- 84・85 ○ → `condensationRhFloor` を SPACE [0, 0.85] へ投入し、
  moistureDecay の範囲拡張([600, 6000]、L×3 相当まで)と合わせて
  v43 共較正(種 = v42 + rhFloor 掃引最良近傍)。生存性の測り直しつき。
- 84 ○ 85 ✗ → W は積めるが冬雨に繋がらない = 輸送の冬の風(熱風リンク、
  既実装)との組を掃引してから v43 の構成を決める。
- 84 ✗(床があっても W が積めない)→ 輸出(発散風)が支配。風の発散の
  監査へ(気圧勾配風の質量非保存の疑い)。
- 87 ✗ → ソルバの枝振動。緩和係数・枝凍結の追加を先に。
