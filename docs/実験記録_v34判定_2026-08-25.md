## 発見: これは機構の敗北ではなく**探索の失敗**

突合(いずれも較正と同一条件 2°):

```
較正の収束点(925 評価)          68.158(a=0.208)
種 + a=0.6 だけ(掃引の既知の点)  68.335(+0.18 上)
```

**単独レバー 1 本の点が、925 評価の収束点より高い。**1° でも同じ
(68.360 対 68.031)。降下は a を 0.208 まで動かしたところで他の定数との
綱引きに入り、a 方向の一段深い盆地(0.6 近傍)に到達しないまま停滞則で
終了した。v33 の「較正自身の裁定」という読みは、**降下が実際にその点を
訪れている場合にしか成立しない**。今回は訪れていない。

対処: `--seed-file` を optimize.ts に追加(新規 run の初期点を JSON で
与える。再開時は無視・SPACE 外キーは拒否・範囲へクリップ)し、
**v34b を種 = v33 + a=0.6/decay=1500(評価値 68.335)から再降下**。
判定条件は v34 のものを引き継ぐ(合格線 68.258 は種 67.758 基準のまま。
v34b の種はすでにこれを超えているので、条件 1 は「v34b の収束点 ≥ 68.335 +
停滞則収束」に読み替える — 種より下がらないことの確認)。
