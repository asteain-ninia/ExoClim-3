# 事前登録: 偏西風を上げたときの代償は**気温**か。それは補償できるか

日付: 2026-08-16(前段の結果を見た直後。この掃引はまだ走らせていない)
前段: [実験記録_拡散を移流で補えるか](実験記録_拡散を移流で補えるか_2026-08-16.md)

## 前段で分かったこと

偏西風を 9 → 12 m/s にすると:

```
                  偏西風 9   偏西風 12   向き
中位(50%)分位       532       564      観測 596 へ**近づく**
インド 年降水比     0.45      0.46      改善
米南東              0.37      0.40      改善
欧州                0.92      0.97      改善
--------------------------------------------------
気温 RMSE          3.797     4.095     **悪化 (+7.8%)**
大分類            74.15     73.85      下がる
詳細              43.65     43.02      下がる
連続部分          70.314    69.897     **下がる**
```

**降水は軒並み改善するのに、成績は下がる。**
差を分解すると、主因は大分類 −0.30 と詳細 −0.63 で、
その背後にあるのは**気温 RMSE の +0.30**である。
ケッペンは気温で気候帯を切るので、気温場が崩れれば一致率は下がる。

これは段 38 の読みの**訂正**にあたる。あのとき「較正が `westerlyWindMs` を
下端 6.5 へ戻すのは、目的関数が『均す』方を報酬にしているため」と書いたが、
**実際には気温が悪化するのを避けていた**可能性が高い。

既知の構造と整合する: 陸の気温は移流結合が支配しており、熱容量はほぼ無効
(`docs/引き継ぎ_2026-08-14.md`)。**偏西風は陸の気温を直接支配している。**

## 測ること

偏西風 12 m/s に固定したうえで、帯状移流の結合係数を掃引する。

```
SWEEP_OVERRIDE='westerlyWindMs=12'
掃引: zonalAdvectionCouplingWm2PerK = 57.3(現在) / 50 / 43 / 36 / 30(探索空間の下限)
```

風が速くなったぶん結合を弱めれば、**運ぶ量は増やしたまま熱の受け渡しだけ戻せる**か。

## 予測(**結果を見る前に固定する**)

1. **結合を下げると気温 RMSE は下がる。** 57.3 → 30 で 4.095 → **3.85 以下**。
   偏西風 9・結合 57.3 の 3.797 までは戻らないと読む
   (風速そのものが移流量を決めるので、結合だけでは完全には打ち消せない)。
2. **降水の改善は保たれる。** 中位分位は 564 から **555 以上**を維持すると読む。
   結合は熱の受け渡しであって水蒸気の輸送ではないため。
3. したがって **連続部分は 69.897 から上がり、70.314(現行)を超える**。
   **70.4 以上**を出すと読む。
4. 数値的健全性は全水準で保たれる。

**予測 3 が当たれば、「偏西風 12 + 結合を下げる」が現行を上回る組**である。
その場合は偏西風を 12 に固定し、新しい run 名で較正をやり直す。

## 判定

- **予測 1 が外れたら**(結合を下げても気温が戻らない): 気温悪化の主因は
  帯状移流ではない。偏西風が気温に効く別の経路を探す
  (雲・海氷・蒸発冷却のいずれか)。
- **予測 2 が外れたら**(結合を下げると降水も落ちる): 熱と水が同じ係数で
  結ばれていることになる。**それ自体が構造の問題**なので、分離を設計する。
- **予測 3 だけが外れたら**(個々は良いが合計で届かない): 2 定数では足りない。
  偏西風を 12 に固定して**較正に 61 定数の補償を探させる**へ進む
  (掃引では組の同時最適化を測れない)。

**どの結果でも目的関数の重みは動かさない。**

## 実行

```
SWEEP_OVERRIDE='westerlyWindMs=12' npx tsx scripts/sweep_lever.ts \
  zonalAdvectionCouplingWm2PerK 57.3,50,43,36,30 --parallel 4
```
