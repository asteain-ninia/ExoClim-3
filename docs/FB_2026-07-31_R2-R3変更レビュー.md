## 2. P0-1 — 土壌水分と再循環を同じ周期解へ収束させる

### 問題

現在の結合計算は `recyclingIterations = 2` の固定回数である。

1. `precipEst` から土壌水分と実蒸発散を計算
2. 実蒸発散から陸面水蒸気供給を計算
3. 供給から次の降水を計算
4. 2 回で終了

最終降水は最後の水蒸気供給から新しく計算される一方、返される土壌水分・ET・
流出は一つ前の `precipEst` に対する解である。さらに結合反復中の降水更新は
`supplies2[m]` を直接使い、最終段で適用する R2 の月ブレンドと同じ演算子に
なっていない。

したがって、バケツ単体で

```text
入力降水 = ET + 流出 + 貯水変化
```

が成立しても、その入力降水はモデルの最終降水ではない。

### 再現

`ca5fded` の 4° 地球を診断つきで実行し、陸域面積重みで最終降水と
土壌診断を比較した。

```text
最終降水             825.32 mm/年
実蒸発散             460.34 mm/年
流出                 314.13 mm/年
全球平均残差          50.86 mm/年
セル別絶対残差の平均  58.62 mm/年
```

全球平均で降水の約 6.2% が閉じていない。浮動小数誤差ではなく、結合反復の
入力と最終出力が異なることによる構造的残差である。

### 修正方針

- 土壌水分 → ET → 陸面供給 → R2 月ブレンド → 降水、を一つの結合演算子とする。
- 最終出力と同じ演算子を反復内でも使う。
- 固定 2 回で打ち切らず、降水場または水収支残差に対する収束判定を持つ。
- 発散・振動を防ぐ必要があれば、事前固定した緩和係数で減衰更新する。
- 最大反復回数へ到達した場合は黙って採用せず、診断へ未収束を記録する。
- 物理結果に使う最終土壌診断は、最終降水と同じ周期解のものにする。

反復回数を新しい較正つまみにしない。これは周期解を求める数値パラメータであり、
結果を見て止める回数を変えず、許容誤差と上限を先に固定する。

### 受入条件

- 0.5° / 1° / 2° / 4° の地球で、面積重み付き年水収支
  `P − ET − runoff − ΔS` の絶対値が 1 mm/年以下。
- セル別年収支の絶対残差平均が 2 mm/年以下。
- 最大反復回数へ到達せず、収束回数と最大残差を診断へ出す。
- 反復上限を増やしても、最終降水・ET・流出が所定許容差内で不変。
- 全海・全陸・無降水・高傾斜でも有限かつ決定的。
- 統合テストは `solveSoilWater` 単体ではなく、最終 `PipelineResult` の降水と
  同じ実行で得た土壌診断を比較する。

## 3. P0-2 — 当月降水を加えてから蒸発散を決める

### 問題

地域降水 FB §7 の更新順は次である。

1. 前月貯水へ当月降水を加える
2. 温度・日射・貯水率から蒸発散可能量を求める
3. ET と流出を差し引く

現実装は利用可能水量の上限には `s0 + P` を使うが、ET の貯水率には
降水追加前の `s0 / capacity` を使う。

```ts
et = min(s0 + P, PET * (s0 / capacity));
```

空の土壌へ雨が大量に降っても、その月の ET は 0 になる。雨季の水を機械的に
翌月へ送るため、アマゾン乾季改善の一部が意図した土壌記憶ではなく
1 か月の位相ずれで生じる可能性がある。

### 修正方針

少なくとも次の順序にする。

```text
available = previousStorage + precipitation
wetness   = clamp(available / capacity, 0, 1)
ET        = min(available, PET × wetness)
remaining = available − ET
runoff    = max(0, remaining − capacity)
storage   = clamp(remaining, 0, capacity)
```

月平均モデルとして別の更新順を採る場合は、アマゾン結果を見る前に式と理由を
事前登録し、降水インパルスに対する位相応答を比較する。

### 受入条件

- 貯水 0、気温 > 0、当月降水 > 0 のセルで、同月 ET が正になる。
- 年水収支が閉じる。
- 12 月の降水が翌年へ持ち越される循環境界をテストする。
- 初期貯水 0 / 50 / 100% から同じ周期解へ収束する。
- アマゾン最乾月と Af+Am の改善を、修正後の式で再測定する。

## 4. P0-3 — 土壌診断を捨てず、統合水収支を標準報告する

### 問題

`computePrecipitation` は `diagOut.soil` を生成するが、
`runPipelineWithPrecipDiag` は `box.fields` だけを返し、土壌診断を捨てる。
また `WaterBudget` 型は定義されているが使われていない。

このため、地域降水 FB §7 が要求する全球の降水・ET・流出・貯水変化を、
現在の診断スクリプトから報告できない。

### 修正方針

- 診断つき実行から `SoilWaterResult` を返す。
- 面積重み付きの全球陸水収支を機械可読 JSON へ出す。
- 少なくとも次を含める。
  - 年降水
  - 年実蒸発散
  - 年流出
  - 年貯水変化
  - 符号付き残差
  - セル別絶対残差平均
  - 結合反復回数
  - 収束指標
- 土壌水分無効時は `null` または明示的な `disabled` とし、ゼロ収支を
  成功したように表示しない。

## 6. P1 — 学習曲線を v3soil と今後の run に対応させる

### 問題

`scripts/optimize_chart.ts` の系列は v1 / v2 の固定配列である。
現在の `log_v3soil.jsonl` は読み込まれず、`progress.svg` も学習開始前のまま。

### 最小対応

- `v3soil` を第 3 系列として追加する。
- 現在も目的関数は v2 系なので、v2 と同じく
  `fit + 0.3 × ITCZ RMSE` で v1 共通基準へ換算する。
- v1 / v2 / v3soil の生試行とベスト曲線を同じグラフへ重ねる。
- 実行中の不完全な JSONL 最終行は従来どおり無視する。
- `progress.svg` を再生成する。

### 再発防止

run ごとにコードへ系列を追加し続けない。最適化開始時に、例えば
`run_<name>.meta.json` を生成する。

```json
{
  "runName": "v3soil",
  "label": "v3 soil",
  "objectiveBasis": "v2_itcz",
  "gitCommit": "ca5fded",
  "gitDirty": false,
  "startedAt": "..."
}
```

チャートはメタデータのある `log_<name>.jsonl` を列挙し、比較基準を
`objectiveBasis` から決める。v1 / v2 の既存ログだけは互換表で扱ってよい。

実行中プロセスは開始時のコードを読み込んでいるため、学習中に物理コードを
変更しない。チャート修正も、現在の run 終了後に独立コミットとする。
