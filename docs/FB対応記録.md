## P0-1. 手続き地形の解像度不変化 — 完了

1. **根本原因**: 値ノイズの格子を出力セル数(`grid.widthCells / cellsPerLatticeX`)で
   定義し、乱数を逐次消費していたため、解像度変更で格子の寸法と乱数割当が両方変わり、
   同じ種子が別惑星になっていた。
2. **変更ファイル**: `src/domain/terrain.ts` — 逐次乱数(mulberry32 消費)を廃止し、
   `hash(種子, オクターブ番号, 固定角度格子座標)` の座標ハッシュ方式へ。オクターブは
   角度定義(90/45/22.5/11.25/5.625° — 360 を割り切る値)で経度周期を厳密化。
   海水準の面積重み付き分位点方式は維持。
3. **追加テスト**: `tests/unit/domain/terrain.test.ts`(6 件): 決定性(配列一致)、
   種子差で別惑星、陸面積率 ±1pt(3 種子 × 3 解像度)、1° vs 0.5° の Jaccard ≥ 0.95、
   1° vs 2° の Jaccard ≥ 0.9、経度継ぎ目の連続性。
4. **修正前に失敗 → 修正後に通る証拠**: 修正前の実測 Jaccard = 0.198(1° vs 0.5°)/
   0.153(1° vs 2°)で 2 テスト FAIL(FB の実測 0.196/0.152 と一致 — 相互検証)。
   修正後 6/6 PASS。
5. **地球主要指標の前後**: リーン採点がビット一致
   (fit 93.09 / 大分類 73.93 / 詳細 42.74 / ゲート 14 / ITCZ 8.33)。
   地球・仮想大陸プリセットは手続きノイズを使わないため不変。
6. **0.5°/1°/2° の差**: Jaccard(2° 集約)= 0.983〜0.988(1° vs 0.5°)、
   0.977〜0.984(1° vs 2°)。陸面積率は全組合せで 30.0%(指定 30%)。
7. **空間保留検証**: 未導入(P1-1 で対応)。
8. **残る制約**: 手続き惑星の見た目は種子ごとに旧実装から変わる(乱数割当の
   置換に固有)。既存種子の惑星を保存する後方互換は仕様外とした。
   procedural42 の流線検証は陸横断 0 件を維持。

1. **根本原因**: ログはバッチ内の評価ごとに追記、state はバッチ末尾保存のため、
   バッチ途中停止 → 再開で古い `state.evals` から重複採番していた
   (v1 ログの 364〜366 が実例)。state 書込も非原子的だった。
2. **変更ファイル**: `scripts/optimize_store.ts`(新設: readEvalLog /
   nextEvalNumber / saveStateAtomic / loadStateStrict)、`scripts/optimize.ts`
   (採番の正本をログ最大値に変更・原子的保存・起動時照合警告)、
   `scripts/optimize_chart.ts`(重複番号の検知警告)。
3. **追加テスト**: `tests/unit/scripts/optimize_store.test.ts`(7 件):
   363/366→367 採番、ログ無し採番、切れた最終行の許容、中間行破損の明示エラー、
   重複検知、原子的保存(途中書込みで本体不変)、state 破損の明示エラー。
4. **証拠**: 歴史的重複(v1 の 364-366)をチャート側が警告として検知
   (既存ログは制約どおり不変更)。新テスト 7/7 PASS(計 41)。
5. **地球主要指標の前後**: 採点経路に変更なし(不変)。
6. **0.5°/1°/2° の差**: 対象外(最適化基盤)。
7. **空間保留検証**: 未導入(P1-1)。
8. **残る制約**: 再開は「完了評価はログに保持、未確定バッチは再評価」
   (FB の指示どおり較正記録の「無損失」表現を訂正済み)。バッチ途中の
   再評価は新番号で採番されるため重複しないが、計算は再実行される。
