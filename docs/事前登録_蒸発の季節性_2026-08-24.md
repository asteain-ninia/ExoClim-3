# 事前登録: 蒸発の季節性 — 海上の湿度を定数から「モデル自身の水」へ(台帳 項目 3)

日付: 2026-08-24 未明(実装前に書いた)
診断: scripts/diag_evap_seasonality.ts(2026-08-23)—
**北半球の海の蒸発ピークが 8.9〜9.2 月(初秋)**。実物の中緯度・亜熱帯の海は
**冬に蒸発が最大**(冷たく乾いた大気が暖かい海面上を吹き、湿度差が開く)。
モデルは逆位相。これが W の季節性を殺し、位相 70 日の残り(中緯度・亜熱帯の
冬雨)の真因と絞り込まれた(λ を変えても W の振幅は ±7% のままだった)。

## 原因(式から)

`E = ρ · C_E · |V| · q_s(T_s) · (1 − RH)`、**RH = 0.8 の定数**。
大気側の湿度が季節を持たないので、E は海面温度 q_s(T_s) だけで決まり、
海が最も暖かい初秋にピークが来る。

## 実装(既定 0 でビット一致)

大気側の湿度を**モデル自身の可降水量 W**で季節変調する:
```
RH_m(i) = RH_const × clamp( (W_m(i) / W̄(i))^k , 0.5, 1.2 )   W̄ = 12 か月平均
```
k = `evapHumiditySeasonalExp`(既定 0 = 従来と厳密一致)。冬に W が少ない
(= 乾いた空気)海では RH が下がり蒸発が増える。年平均の RH はほぼ保たれる
(W/W̄ の平均 ≈ 1)ので、全球蒸発量は大きく動かない。
W は前の結合反復の解(warmStart)を使う(コンベアと同じ作法)。初回は変調 1。
W/W_sat を直接使わないのは、モデルの W が実物の 1/6 で絶対湿度としては
使えないため(相対変調だけを借りる)。地理中立・季節相対。

## 予測(結果を見る前に固定)

63. k = 1〜2 で北半球中緯度の海の蒸発ピークが **9.2 月 → 12 月側へ 2 か月以上**動く。
64. W の相対振幅が増える(中緯度 0.28 → 0.4 以上)。
65. 位相(帯別平均)が **2 日以上改善**(v7b の位相項が下がる)。
66. 全球の海上蒸発の年合計は ±5% 以内。大分類は −0.3 以内。

## 判定

- 63・65 ○ → SPACE に [0, 3] で投入し、冬雨機構(winterStormEquatorwardReachDeg)
  と**組で**掃引 → v33 較正。
- 63 ○ だが 65 ✗ → 蒸発は冬へ動いたが降水の位相に届かない = 輸送の経路で
  季節性が消えている。W の位相を段階ごとに追う診断へ。
- 63 ✗ → W の季節性が弱すぎて変調が効かない。k の上限を上げる前に
  W の季節振幅の出所(供給か凝結か)を分解する。
