# 設計: 海氷を潜熱と伝導で表す(双安定の解消)

日付: 2026-08-04
根拠: `docs/実験記録_高緯度の冬_2026-08-04.md`(診断)

## 直す対象

現行の海氷断熱は**その時刻の気温だけ**から決まる:

```
iceW   = clamp((seaFreezeC − 気温) / iceRampWidthC, 0, 1)
capEff = heatCap × (1 − seaIceInsulationFactor × iceW × 海率)
```

実測(`scripts/diag_sea_ice_timing.ts`)で、これが**両極を逆方向に壊している**:

- 北極海: 7〜11 月に iceW = 0.00。混合層の熱容量を抱えたまま秋を過ごし、
  9 月の海面が +6.9°C。陸の秋のバイアス +8〜+12°C の原因。
- 南大洋: 一年中 iceW = 1.00。海の熱が入らず南極が寒すぎる。
  セル温度が −32〜−40°C まで落ちており、**水としてはあり得ない値**。

原因は**正帰還**である。冷たいほど断熱が強まり、断熱が強いほど冷える。
2026-07-30 に「0 層海氷が双安定だから温度ランプへ戻す」と判断したが、
ランプ側も同じ双安定に落ちていた。

## なぜ単純な「凍結点で温度を止める」では駄目か

「氷があるならセル温度を凍結点に張り付ける」と、極の冬が実物より遥かに暖かく
なる。実在の海氷の**表面**は放射平衡で −30°C にもなる一方、その下の**海水**は
−1.9°C に留まっている。**単一温度の EBM は、この 2 つを同時に持てない。**

現行の「断熱で熱容量を落とす」という細工は、まさにこの 2 つを分けるための
代用だった。表面は薄い板として自由に冷え、下の海は切り離される。
問題は切り離しの**強さが温度で決まる**ことで、そこが正帰還になっている。

## 設計: 表面と海を伝導でつなぐ(0 層海氷)

氷の厚さ h を状態として持ち、表面(EBM が解く T)と海(凍結点に固定)を
**氷を通じた熱伝導**でつなぐ。

```
氷がある場合(h > 0):
  capEff = heatCap × (1 − seaIceInsulationFactor × 海率)   ← h に依らない一定
  伝導フラックス F = k_ice × (T_freeze − T) / h              [W/m²]
  氷の成長      dh/dt = F / L                                （F > 0 = 海が熱を失う）

氷がない場合(h = 0):
  capEff = heatCap(混合層まるごと)
  T が凍結点を下回ったら、超過分の熱を氷に変えて T を凍結点へ戻す
```

- `k_ice` … 海氷の熱伝導率 ≈ 2.0 W/(m·K)
- `L` … 融解潜熱 × 密度 ≈ 3.0×10⁸ J/m³(水等価 mm あたり 3.34×10⁵ J/m²)
- `T_freeze` … `seaFreezeC`(海水の凍結点 −1.9°C)

### なぜこれで双安定が壊れるか

F ∝ 1/h なので、氷が厚くなるほど海からの熱供給が細り、表面は自由に冷える
(極の冬の −30°C が出る)。同時に成長速度も 1/h で鈍るので、**厚さは
√t で頭打ちになる**(Stefan の成長則)。青天井の正帰還にならない。

夏は正味フラックスが上向きになり、まず氷を融かす。氷が残っている間は
海が凍結点に留まるので、翌秋の出発点が毎年同じになる — **周期解が一意に決まる**。

### 実装上の要点

- **F は T の関数なので陰的に扱う**。線形解の対角へ `k_ice/h` を足し、
  右辺へ `k_ice/h × T_freeze` を足す。既存の緩和(赤黒ガウス=ザイデル)の
  構造をそのまま使える。
- h が薄いと `k_ice/h` が発散するので、**下限 h_min を置く**
  (物理的にも、薄氷は割れて開水面が残る)。h_min は較正定数ではなく
  数値の下限として扱い、値を変えても答えが変わらないことを確かめる。
- **CPU 経路と GPU 経路(WGSL)の両方に入れる**。片方だけだと
  `EXOCLIM_GPU=0` と有効時で物理が変わり再現性が壊れる(既存の注記どおり)。
- 状態 h は時間ステップをまたいで持ち越すので、**周期定常の判定に含める**
  必要がある。いまの判定は気温の年次ドリフトだけを見ているので、
  氷厚のドリフトも同じ許容差で見る。

## 事前に登録する判定

**数値的健全性(必須。ここが崩れたら採用しない)**

- h_min を 2 倍・1/2 にしても、気温場の面積重み平均の差が 0.1°C 以下
- 氷厚の年次ドリフトが、気温の周期定常判定と同じ許容差を満たす
- 全球のエネルギー収支が閉じる(潜熱で出入りした熱の総量が氷厚の変化と一致)

**物理(この 3 つを同時に満たすこと)**

1. 北極海の iceW 相当(= 断熱の効き)が **10〜11 月に立ち上がる**
   (現行は 7〜11 月がゼロ)
2. 南大洋 60〜70°S の氷が**夏に後退する**(現行は一年中 1.00)
3. 50°N 以北の陸で、**秋(10〜11 月)の +10〜+12°C と春(3〜4 月)の
   −3〜−4°C が両方とも縮む**。片方だけなら位相ではなく水準を動かしただけ

**総合(採否)**

- 大分類・詳細・地域ゲートを下げないこと
- 年較差 RMSE と季節位相 RMS が悪化しないこと
- 新旧どちらの目的関数でも悪化しないこと
- 未見評価(5 フォールド)で同じ傾向が出ること

**棄却する場合**

- 南大洋が夏に融けない → 断熱の強さか海洋熱輸送の側に別の欠陥がある
- 秋は直るが春が悪化 → 位相ではなく水準を動かしただけ。設計を組み直す

## 作業の順序

1. CPU 経路に実装(参照実装)。定数 `seaIceModel` で切り替え、既定は現行のまま
   → 無効設定で従来と**厳密に一致**することを先に確かめる
2. `EXOCLIM_GPU=0` で上の物理判定を測る(較正が GPU を使っている間も回せる)
3. 通れば WGSL へ移植し、CPU/GPU の一致を `scripts/check_accel_parity.ts` で確認
4. 較正へ入れる(`seaIceInsulationFactor` の意味が変わるので探索範囲を見直す)

## 補足: 2026-07-30 の判断について

当時「0 層海氷は双安定で暴走した(南極海リングが夏に融け残り −60S が −14°C へ)」
として温度ランプへ戻した。今回の実測で、**ランプ側も同じ双安定に落ちていた**
ことが分かった(南大洋は一年中 iceW = 1.00、セル温度 −32〜−40°C)。

つまり当時の対処は問題を解いておらず、症状を見えにくい場所へ移しただけだった。
0 層海氷が暴走した原因も、おそらく潜熱と伝導が無いまま断熱だけを入れたことに
ある。**今回は潜熱と伝導を先に入れる。**
