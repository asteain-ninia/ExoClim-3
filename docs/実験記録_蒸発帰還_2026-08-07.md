# 実験記録: 蒸発冷却の陰的化(R1)— 事前登録の主判定に不成立。棄却

日付: 2026-08-07
事前登録: [docs/事前登録_蒸発帰還_2026-08-07.md](事前登録_蒸発帰還_2026-08-07.md)
道具: `scripts/exp_evap_feedback.ts`
実装: 72ca204(既定は無効。`evapFeedbackFrac = 0` で旧結果と完全一致を確認)

## 何を試したか

蒸発冷却は前パスの蒸発散から冷却量を作って EBM の**右辺へ定数として**足していた。
気温が上がっても冷却が増えないので、負帰還として働いていない。
前パスの気温 T_ref のまわりで線形化し、**対角**へ入れた:

```
LE(T) ≈ LE(T_ref) + k·(T − T_ref)
k = frac · λ · α(T_ref) · (E − Ē)     λ = 28.4 W/m²/(mm/日)、α = L_v/(R_v·T²)
diag += k ／ rhs += k·T_ref
```

## 結果

```
frac   v3      大分類  詳細   文字   40〜50°N   50〜60°N   乾燥ゲート
   0   85.769  75.22  44.07  31.3%   +4.77      +5.38      3/3
 0.5   85.304  74.73  43.66  30.5%   +4.98      +5.47      3/3
   1   85.293  74.62  43.78  30.7%   +4.77      +5.25      3/3
   2   85.316  74.53  43.84  31.9%   +4.30      +4.81      3/3
```

主判定は「40〜50°N と 50〜60°N の最暖月ずれが**両方 +3.0°C 以下**」。
frac = 0.5 では**逆方向へ動き**、その後 frac を上げると少しずつ下がるが、
frac = 2 でも +4.30 / +4.81 で判定の 3.0°C にはまったく届かない。

**事前登録の棄却条件に該当。棄却する。**

## なぜ届かなかったか — 線形化の基準点がパス 1 だった

実装ではなく**基準点の選び方**が間違っていた。

```
k·(T − T_ref)     … T を T_ref へ引き戻す項
```

T_ref は **モデル自身のパス 1 の気温**である。そしてパイプラインのパス 1 は

```ts
computeTemperature(context, itcz, windBelt, ocean, airflow, undefined, o)
                                                    ↑ 陸面の状態を渡さない
```

と呼ばれており、**蒸発冷却も熱容量の土壌依存も入っていない**。
つまりこの項は「パス 2 の答えを、陸面結合を持たないパス 1 の答えへ引き戻す」
働きをする。**パス 2 で足した物理を打ち消す方向**である。

数字がそれを裏付けている:

- frac = 0.5 で **40〜50°N が +4.77 → +4.98 と悪化**した。パス 1 のほうが暑いので、
  引き戻せば暑くなる。
- v3 は frac 0.5 / 1 / 2 で **−0.465 / −0.476 / −0.453 とほぼ一定**。
  引き戻しが飽和して「パス 1 の答え」に張り付いた形で、
  frac を上げても悪化が増えないのはそのため。
- frac を上げると最暖月のずれ自体は少し下がるが、これは
  帰還が正しく効いたのではなく**パス 1 の季節振幅が小さい**ことの反映で、
  全球成績を 0.45 犠牲にして買っている。

線形化そのものは正しい形式だが、**基準点が最終解から遠く、しかも別の物理で
計算されている**ので、ニュートン法の 1 歩目としては意味を成さない。
正しくやるならパス数を増やして外側の反復を収束させる必要があり、
費用に対して見返りが読めない。

## 副産物: 費用が 7 倍に膨らんだ

frac > 0 のとき 1 回の評価が 6 分 → 15 分になった。周期定常の年次ドリフトが
許容差 0.05 に収まるまでの年数が増えたためで(年数の梯子が 24 → 48 → 96 と倍増)、
**帰還項が平衡を動かさないのに緩和は遅くする**という、最も割の合わない結果である。

## 配線は残す

`evapFeedbackFrac` の口は残す(既定 0 で完全に無効、旧結果とビット一致)。
将来、**気温に依存する蒸発散を本気で解く**(E を T の関数として陰的に解く)
段階に来たら、線形化の枠組みは再利用できる。そのときの基準点は
**モデル自身の前パスの気温であってはならない** — そこが今回の教訓である。

## 教訓

- **線形化の基準点が「別の物理で解いた前のパス」だと、答えがそちらへ引き戻される。**
  ニュートン法の形をしていても、基準点が最終解から遠く、しかも項を持たない
  物理で計算されていれば、1 歩目は改善ではなく後退になる。
  **基準点がどのパスの、どの物理で作られたかを必ず確かめること。**
- 答えを変えたいなら、項の**置き場所**(陽的/陰的)ではなく
  **フラックスの大きさか、その依存する物理量**を変えなければならない。
- **「較正が物理値の 1/7 に落ちている」は、置き場所の間違いの証拠にならない。**
  そう読んで実験を組んだが、単に「その形では大きくできない」だけだった。
  定数が物理値から外れている理由は複数あり、一つに決め打ちしてはいけない。
- **効かない機構が費用だけ増やすことがある。** 帰還項は平衡を動かさないのに
  緩和時間を伸ばし、評価費用を 2.5 倍にした。棄却の判断材料に費用も入れること。

## 次に何をするか

診断そのもの(冷帯の夏が +5°C 暑い、水は届いている)は変わらない。
`step05_temperature.ts` の雲アルベドを読み直したところ、
**ストームトラック雲・層積雲・海峡雲がすべて `oceanFrac` 倍で入っており、
陸の雲は ITCZ 近傍しか増えない**という構造的な欠落が見つかった。
夏の大陸は月 100mm 以上降っていても雲が基準値のままになる。
