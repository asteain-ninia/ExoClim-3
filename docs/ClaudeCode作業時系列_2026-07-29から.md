## 採用しなかった主な案

- ITCZ 半幅 9° → 12°: 大分類が 61.2% → 55.3%へ低下。
- 赤道横断モンスーン風: 条件を絞っても純減。
- 蒸発冷却フィードバック: 現在の降水誤差を温度へ正帰還させるため係数 0 で保留。
- R4 湿潤収束の沈降緩和: 供給到達可能性を水蒸気量として扱えず棄却。
- 稜線プロミネンス推定: 高原の縁まで山脈扱いし熱帯を破壊。生標高 p95 へ置換。
- 水蒸気供給の渦拡散: 事前予測 4 件中 3 件が外れたため、小幅なスコア改善が
  あっても採用せず。
- 前時刻からの線形外挿: 反復数が減らず、複雑さに見合わないため棄却。
- 素朴な Aitken 外挿: 複数時定数の混在により短い緩和では悪化するため棄却。

## 監査結果 — 気になった点

### 1. 悪意ある変更や広範な破壊は見つからない

ログ、Git 履歴、現ワークツリーから、リポジトリ外への不審な送信、広範な削除、
履歴の強制巻き戻しは確認できなかった。巨大な JSON の行数減少は、30 秒角 Beck
データの集約や地形データの再生成によるもので、意図は記録されている。

### 2. コミットの責務が混ざった箇所がある

- `8784348` は「Beck 検証フィクスチャ修正」という件名だが、GPU デバイス、
  風上追跡、土壌水分 GPU の下準備も含む。
- `15e7ed6` は「GPU 風上追跡」という件名だが、UI 用 Beck データ、再構築
  スクリプト、観測 UI テストも含む。

内容自体は後続テストと表示確認で救われているが、原因追跡や revert の単位として
は良くない。今後は観測データ修正と GPU 実装を分けるべきである。

### 3. Beck の最初の修正は表示まで届いていなかった

最初は `tests/fixtures/earth_koppen_1deg.json` だけを高解像度 Beck から作り直し、
UI が読む `src/domain/data/earth_koppen_1deg.json` が旧版のままだった。その後、
両方を書き出すよう再構築スクリプトを直し、モデル陸マスクを適用して Caspian Sea
などの水面セルを除外し、UI テストを追加した。現在は解消済み。

### 4. v7clean は再開・採用してはいけない

`out/optimize/run_v7clean.meta.json` は基準コミット `805d270`、clean 開始を記録する。
しかし run は 2,247 評価で止まり、その後 HEAD と観測フィクスチャ、GPU/EBM 数値が
変わった。best も地域ゲート 13 である。成果物は実験記録としてのみ保持し、現在の
モデルへ定数を移植しないこと。

### 5. 標準 `out/validate/report.json` は現状を表していない

現在置かれている標準レポートはコミット `15e7ed6`、`gitDirty=true` の時点のもの。
その後の南極・EBM 数値修正を含まない。現行モデルの成績として引用しないこと。
数値高速化と再較正が確定した後、clean HEAD で再生成する必要がある。

### 6. 「作業が止まる」現象には複数の実因があった

- Windows 強制再起動
- ユーザー入力の途中送信による interrupt（較正プロセスは生存）
- cron/自動再開側の不調
- GPU アダプタの GC に起因する segfault（デバイス寿命管理で解消）
- 2026-08-02 03:46 の OAuth 失効
- 長い較正を止め、報告文や別実験へ移った場面

最後の項目は利用者の「文書を出すと止まる」という観察と一致する。以後のログでは
連続作業を意識しているが、v7clean は実際に途中停止したままである。
