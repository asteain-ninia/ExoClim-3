# 事前登録: 循環の暦の遅れ(段 46)— 天文直結の雨季に熱慣性を与える

日付: 2026-08-18(実装前に書いた)
前段: `diag_phase_sign.ts` の実測 — モデルの雨季は系統的に早い
(熱帯 −28.6 日・早い側 77%、亜熱帯 −20.3、中緯度 −12.9)

## 何を直すか

降水位相(72 日ずれ)は 56 定数のどれでも動かない剛体だった。原因は
**ITCZ と風帯の季節移動が赤緯(太陽の位置)を遅れゼロで追う**こと。
実物の循環は海の熱慣性を介して太陽を追うため、雨季は夏至から 3〜6 週遅れる。
モデルには「暦の遅れ」を表す量が 1 つも無い。

符号の分布(早い側に 49〜77% が偏在、極側ほど弱い)は、
一様な遅れの欠落と整合する。

## 実装

ITCZ(step01)と風帯の季節シフト(step02)が参照する赤緯を、
**`circulationLagMonths` か月だけ遅らせた赤緯**に置き換える:

```
decl_lagged(m) = monthlyDeclinationDeg を (m − lag) で線形補間(円環)
```

- 新定数 `circulationLagMonths`。**既定 0 = 従来とビット一致**。
- 日射(EBM の強制)には触れない — 太陽そのものは遅れない。
  遅れるのは**循環の応答**だけ。
- 遅れの物理は海の混合層の熱慣性なので、将来的には
  `oceanMixedLayerDepthM` から導出する形(τ = C/B 型)へ拡張できるが、
  まず定数 1 つで効果を測る。地理・季節に一様、逆行や高離心率でも壊れない。

## 予測(結果を見る前に固定)

`sweep_lever.ts circulationLagMonths 0,0.5,0.75,1.0` で:

1. **降水位相が単調に改善**: 72 日 → lag 1.0 で **50 日以下**。
   熱帯の −28.6 日がほぼ消えるため(28.6 日 ≈ 0.94 か月)。
2. **気温位相(34 日)は悪化しない**(±3 日以内)。気温は EBM の熱慣性が
   決めており、この変更は気温側に直接触れない。
3. **大分類は下がらない**(−0.3 以内)。B の夏雨/冬雨判定が正しい暦に
   揃うのでむしろ上がる可能性(+側は予測しない — 楽観を登録しない)。
4. 数値的健全性は全水準で維持。

## 判定

- **1・2・3 がすべて当たったら**: 採用候補。SPACE へ入れるか固定かは
  最良水準の形(単調か头打ちか)を見て決め、利用者に報告。
- 1 が外れたら(位相が動かない): ITCZ の暦以外に位相を固定するものがある。
  供給の月ブレンドの復元力・土壌の記憶を疑い、分解する。
- 2 か 3 が外れたら: 暦の遅れが別の何かを壊している。分解してから再設計。

**目的関数は動かさない。既定 0 のまま(採否は判定後)。**
