# 事前登録: 循環の暦の遅れ(段 46)— 天文直結の雨季に熱慣性を与える

日付: 2026-08-18(実装前に書いた)
前段: `diag_phase_sign.ts` の実測 — モデルの雨季は系統的に早い
(熱帯 −28.6 日・早い側 77%、亜熱帯 −20.3、中緯度 −12.9)

## 何を直すか

降水位相(72 日ずれ)は 56 定数のどれでも動かない剛体だった。原因は
**ITCZ と風帯の季節移動が赤緯(太陽の位置)を遅れゼロで追う**こと。
実物の循環は海の熱慣性を介して太陽を追うため、雨季は夏至から 3〜6 週遅れる。
モデルには「暦の遅れ」を表す量が 1 つも無い。

符号の分布(早い側に 49〜77% が偏在、極側ほど弱い)は、
一様な遅れの欠落と整合する。

## 実装

ITCZ(step01)と風帯の季節シフト(step02)が参照する赤緯を、
**`circulationLagMonths` か月だけ遅らせた赤緯**に置き換える:

```
decl_lagged(m) = monthlyDeclinationDeg を (m − lag) で線形補間(円環)
```

- 新定数 `circulationLagMonths`。**既定 0 = 従来とビット一致**。
- 日射(EBM の強制)には触れない — 太陽そのものは遅れない。
  遅れるのは**循環の応答**だけ。
- 遅れの物理は海の混合層の熱慣性なので、将来的には
  `oceanMixedLayerDepthM` から導出する形(τ = C/B 型)へ拡張できるが、
  まず定数 1 つで効果を測る。地理・季節に一様、逆行や高離心率でも壊れない。

## 予測(結果を見る前に固定)

`sweep_lever.ts circulationLagMonths 0,0.5,0.75,1.0` で:

1. **降水位相が単調に改善**: 72 日 → lag 1.0 で **50 日以下**。
   熱帯の −28.6 日がほぼ消えるため(28.6 日 ≈ 0.94 か月)。
2. **気温位相(34 日)は悪化しない**(±3 日以内)。気温は EBM の熱慣性が
   決めており、この変更は気温側に直接触れない。
3. **大分類は下がらない**(−0.3 以内)。B の夏雨/冬雨判定が正しい暦に
   揃うのでむしろ上がる可能性(+側は予測しない — 楽観を登録しない)。
4. 数値的健全性は全水準で維持。

## 判定

- **1・2・3 がすべて当たったら**: 採用候補。SPACE へ入れるか固定かは
  最良水準の形(単調か头打ちか)を見て決め、利用者に報告。
- 1 が外れたら(位相が動かない): ITCZ の暦以外に位相を固定するものがある。
  供給の月ブレンドの復元力・土壌の記憶を疑い、分解する。
- 2 か 3 が外れたら: 暦の遅れが別の何かを壊している。分解してから再設計。

**目的関数は動かさない。既定 0 のまま(採否は判定後)。**

## 追記(段 46b): 判定と、遅れの ITCZ/風帯への分離

### 掃引の結果(段 46 一括遅れ)

```
lag=0    大分類 74.70  詳細 43.51  位相 72.0 日
lag=1.0  大分類 74.43  詳細 42.91  位相 67.7 日
```

**予測 1 は外れ**(50 日以下に対し 67.7)。ただし符号分布は仮説の核心を支持:

```
帯          lag=0 平均      lag=1 平均
熱帯        −28.6(早77%)   −5.8(早27%/遅18%) ← 系統誤差ほぼ解消
亜熱帯      −20.3          −7.4(早39%/遅21%) ← 大幅改善
中緯度      −12.9          −18.4(早55%)      ← 悪化
```

読み: 天文直結は**熱帯・亜熱帯では真犯人**(遅れ 1 か月で平均が消える)。
中緯度の雨の暦は風帯シフトに遅れを掛けると逆に悪くなる — 中緯度は
別の時計(前線・気温)で動いており、風帯の暦は触るべきでなかった。
RMSE が 4.3 日しか動かなかったのは、(a) 中緯度の悪化が熱帯の改善を
相殺、(b) 平均消滅後も帯内のばらつき(±方向が混在)が残るため。

### 実装(46b)

遅れを 2 定数に分離: `circulationLagMonths`(ITCZ、step01 のみ)と
`windbeltLagMonths`(風帯、step02)。両方とも既定 0 でビット一致。

### 予測(結果を見る前に固定)

`sweep_lever.ts circulationLagMonths 0,0.75,1.0,1.25`(windbelt=0 固定)で:

1. **位相 RMSE は一括遅れより良い**: 最良水準で **65 日以下**
   (中緯度の悪化 −5.5 日分が乗らないため)。
2. 大分類は lag=1 一括の 74.43 より高い(中緯度の B/C 判定が壊れないため)。
3. 中緯度の符号分布は lag=0 と同じ(−12.9 付近)に留まる。

### 判定

- 1〜3 が当たったら: 採用候補として利用者へ報告。SPACE 追加は
  [0, 1.5] を候補とし、次回較正(v27)から。
- 1 が外れたら: ITCZ 経由で中緯度へ漏れる経路がある(トラフ・吸い込み)。
  分解してから再設計。

## 追記 2(段 46b の判定): **予測 1 がまた外れた — 主犯は風帯側だった**

### 掃引の結果(ITCZ 単独遅れ、windbelt=0 固定)

```
lag=0     位相 72.0  大分類 74.70  連続部分 70.88
lag=0.75  位相 71.0  大分類 74.58  連続部分 71.02
lag=1.0   位相 70.8  大分類 74.57  連続部分 71.05
lag=1.25  位相 71.1  大分類 74.50  連続部分 70.98
```

- 予測 1(位相 ≤65)**外れ**: ITCZ 単独では 70.8 止まり(−1.2 日)。
- 予測 2(大分類 > 74.43)当たり(74.57)。ただし差は僅少で意味は薄い。
- 一括遅れ lag=1 の位相 67.7 と比べると、**改善 4.3 日のうち約 3.1 日は
  風帯側の遅れが生んでいた**ことになる。段 46 設計時の想定
  (熱帯の雨=ITCZ の暦)と逆で、位相 RMSE を握るのは風帯の暦。

### 解釈(次の測定の前に書く)

位相 RMSE の重み(面積 × 季節性あり)は亜熱帯〜中緯度の乾湿境界に厚く、
そこの雨の暦は ITCZ 本体でなく**亜熱帯リッジの季節移動**(沈降の緩む時期・
偏西風帯の届く時期)が決めている可能性が高い。一方、一括遅れの符号分布で
中緯度平均が悪化(−12.9→−18.4)したことと矛盾しない説明が要る
(例: 亜熱帯の改善が大きく中緯度の悪化を上回る、または夏雨型/冬雨型で逆符号)。

### 追加測定(実行前に登録)

符号分布を「ITCZ だけ lag=1」「風帯だけ lag=1」で測り、季節型(夏雨/冬雨)
の内訳も出す。予測:

4. ITCZ 単独では熱帯の平均 −28.6 は**あまり動かない**(−20 より早いまま)。
5. 風帯単独で熱帯・亜熱帯の平均が大きく縮む(一括遅れの改善の主因)。
6. 風帯単独でも中緯度は悪化する(一括遅れで見えた悪化は風帯由来)。
   悪化が夏雨型・冬雨型のどちらに集中するかで、風帯の遅れを
   「リッジの極側の縁だけに掛ける」等の分解が要るか判断する。

## 追記 3: 予測 4・5 は真逆に外れた — 主戦場は「冬雨の暦」

### 符号分布の実測(lag=1 を片方ずつ)

```
                ITCZ だけ            風帯だけ           (基準 lag=0)
熱帯 平均       −6.8(夏雨 −3.8)     −27.6              −28.6
亜熱帯 平均     −9.7                −16.4              −20.3
中緯度 平均     −14.1               −16.8              −12.9
中緯度 夏雨型   +4.7 (75%)          −10.3
中緯度 冬雨型   **−72.1** (25%)     **−36.8**
```

- 予測 4 外れ(逆): 熱帯の平均は ITCZ 単独で消える(−28.6→−6.8)。
- 予測 5 外れ(逆): 風帯単独では熱帯は不動。RMSE 改善の主因は
  **中緯度・冬雨型 −72 日 → −37 日**(二乗和なので怪物集団が支配)。
- 予測 6 部分的に当たり: 風帯遅れは夏雨型を悪化させる(+4.7→−10.3)。

### 構図(確定)

1. 熱帯の夏雨 = ITCZ の暦。lag 1 でほぼ完治。**副作用も小さい**
   (大分類 −0.13、気温 RMSE 不変)。
2. 中緯度の夏雨 = すでにほぼ正しい(+4.7 日)。遅らせると壊れる。
3. **冬雨型(地中海型ほか、重み 22〜25%)= 2.4 か月早い。** 風帯の遅れ 1 か月で
   半減するが夏雨型との綱引きになる。**冬雨の暦だけを狙って遅らせる機構**
   (winterDepth01 系のゲートに独自の遅れ)が本命候補。

### 追加測定(実行前に登録): 風帯遅れの深掘り

`SWEEP_OVERRIDE='circulationLagMonths=1'` で
`sweep_lever.ts windbeltLagMonths 0,0.5,1,1.5,2`。予測:

7. 位相 RMSE は U 字。最良は belt 1〜1.5 のどこかで **66 日以下**
   (ITCZ 遅れ 1 の熱帯改善 + 冬雨半減の合算。一括 lag=1 の 67.7 より良い)。
8. belt 2 では夏雨型の悪化が冬雨型の改善を食い、反転する。
9. 大分類は belt ≤1 で 74.4 以上を保つ。
10. これが当たっても冬雨型は −20〜−40 日残る。**完治には冬雨専用の遅れ
    (段 46c 候補: step06 の winterDepth01 が参照する赤緯に独自 lag)が要る**
    — ここまで含めて次の設計判断とする。

## 追記 4(段 46c): 冬ゲート専用の遅れ — 実装済み・測定前に予測を固定

### 機構(コードから読めた、結果に依存しない根拠)

モデルの冬雨 = 帯の被覆(秋分直後から掛かる)× 冬ゲート winterDepth01
(赤緯そのまま)× 供給(EBM の熱慣性で晩夏〜秋ピーク)。積の調和ピークが
秋に落ち、観測(12〜1 月)より 2 か月余り早くなる。風帯ごと遅らせると
夏雨型が壊れる(春の雨が増えて調和ピークが前へ引かれる)ため、
**winterDepth01 の参照する赤緯だけ**を `winterGateLagMonths` で遅らせる。
既定 0 でビット一致。step06 の冬の床(winterFloor)の decls は今回触らない。

### 測定(実行前に登録)

`SWEEP_OVERRIDE='circulationLagMonths=1'` で
`sweep_lever.ts winterGateLagMonths 0,1,1.5,2`(windbelt=0)。予測:

11. 冬雨型の平均(−72 日)が lag 1.5〜2 で **−40 日以上浅くなる**方向に動く
    (符号分布は最良水準でだけ測る)。
12. 夏雨型(中緯度 +4.7)は ±5 日以内で不動 — 冬ゲートは夏はほぼ 0 のため。
    ここが風帯遅れとの決定的な違いで、この予測が外れたら設計を捨てる。
13. 位相 RMSE の最良は **67 日以下**(ITCZ lag1 の 70.8 から冬雨改善分)。
14. 大分類は 74.4 以上(冬季の総量は保たれ、時期だけずれるため)。

### 判定

- 12 が成立し 13 が出たら: 風帯遅れ(windbelt)は 0 のまま、ITCZ+冬ゲートの
  2 時計構成を v27 の SPACE 候補にする。
- 11 が外れたら: 冬雨の位相はゲートでなく帯の被覆×供給の積が支配。
  供給の秋ピーク(海の蒸発の暦)の側を測る。

### 追記 3 の判定(風帯遅れの深掘り、ITCZ lag=1 固定)

```
belt=0    位相 70.8  大分類 74.57  気温RMSE 3.668  分布誤差 0.424
belt=0.5  位相 69.6  74.36  3.685  0.422
belt=1    位相 67.7  74.43  3.709  0.429
belt=1.5  位相 66.8  74.28  3.758  0.438
belt=2    位相 66.2  74.23  3.789  0.447
```

- 予測 7 部分外れ: U 字にならず belt=2 まで単調改善。ただし 66 日以下には
  届かず(66.2)、改善は減速(−1.2/−1.9/−0.9/−0.6)。
- 予測 8 外れ(範囲内では反転せず)。予測 9 当たり(belt≤1 で 74.4 以上)。
- **より重要な観察**: 位相 1 日の改善につき大分類 −0.07・気温 RMSE +0.025・
  分布誤差 +0.005 を払っている。冬雨を直すために夏雨と気温を巻き添えに
  する道具であり、**風帯遅れは採用しない方向**。判定は段 46c の結果と比べて。

### 追記 4 の判定(冬ゲート遅れ、ITCZ lag=1 固定)

```
gate=0    位相 70.8  大分類 74.57  気温RMSE 3.668
gate=1    70.3  74.55  3.664
gate=1.5  70.0  74.52  3.666
gate=2    69.6  74.53  3.668
```

- 予測 11・13 **外れ**: 2 か月遅らせても −1.2 日。副作用ゼロだが効き目もない。
- 予測 12・14 当たり(夏雨型・大分類は不動)— 「狙い撃ちで安全」は正しかったが
  狙った的が位相の主因ではなかった。
- 登録済みの判定に従い: **冬雨の位相はゲート(強度変調)でなく
  帯の被覆 × 供給の秋ピークの積が支配**。次は供給(海の蒸発)の暦を
  冬雨型セル上で直接測る(分解診断)。
