## §0 何を解いているか — 支配方程式と記号

実装: `computePrecipitation`(step06 915-2250)→ `conservativeMonthCore`(1422-1770)→
`solveMoistureTransport`(moisture_transport 184-)。`conservativeMoisture = 1` が本経路。
可降水量 W(mm)を状態とする**定常収支**を月ごとに解き、その凝結項 C を降水とする。

```
0 = S_i − C_i(W) − (1/A_i) Σ_f Φ_{i,f}                        [mm/月]
Φ_{i→j} = L_f { u_n⁺ W_i + u_n⁻ W_j − κ_f (W_j − W_i)/d_f }   風上流束 + 渦拡散
C_i     = lin_i·(W_i − fl_i)⁺ + conv_i·(W_i − cap_i)⁺         凝結の二成分閉包
P_i     = C_i                                                  降水 = 凝結量
```

| 記号 | 意味 | 節 |
| --- | --- | --- |
| S | 源 = 海面蒸発 + 陸面蒸発散 ± コンベア | §1 |
| Φ, κ | 面フラックスと渦拡散 | §2 |
| lin, conv, cap, fl | 閉包の 4 係数 | §3 |
| G | 凝結率の係数(持ち上げ積 × 沈降残存)。診断名 `condRateG` | §4 |
| λ | 凝結寿命の逆数 = U_ref/L [1/月]。v47 で海 13.4・陸 10.6 | §3 |
| W | 可降水量 [mm]。診断名 `waterMm` | §2 |

**降水は倍率の積ではない。** 因子分解が意味を持つのは G までで、降水量は輸送方程式の解である
(同じ G でも上流から水が来なければ降らない)。計算に入る場は 5 つ: 地表温 T_s(2 温度場のうち
**地表側だけ**。減率補正済みの `monthlyTemperatureC`)・地表風 (u,v)・気柱輸送風 V_q(§2.1)・
供給場(§5)・W。W から放射への逆帰還は既定 0。

## §1 源 S — 水はどこから入るか

実装: step06 1503-1510。`src[i]` = 陸なら土壌の実蒸発散、海なら海面蒸発。

### 1.1 海面蒸発(バルク式)

実装: `computeOceanEvaporation`(evaporation 164-231)。

```
E     = ρ · evapBulkCoef · V_eff · Δq · SECONDS_PER_MONTH     [mm/月]
ρ     = 1.225 · p_bar · 288.15/(T_s+273.15)
V_eff = max(evapMinWindMs, |V_10m|)                  静穏時の自由対流の下限
Δq    = q_s(T_s) − evapOceanRelHumidity · q_s(T_bl)  境界層温を解くとき
      = q_s(T_s) · (1 − evapOceanRelHumidity)        τ = 0 のとき
```

T_s ≤ `seaFreezeC` の海面と陸セルは 0。T_bl は診断的境界層温で、`solveBoundaryLayerTemp`
(evaporation 100-162)が V·∇T_bl = (T_s − T_bl)/τ を風上差分で解く(τ = `airSurfaceThermalRelaxationDays`)。
全セルで解く — 冷気は陸で生まれて海へ流出するため陸を飛ばすと移流源が消える。**バルク係数と
海上相対湿度は探索空間に入れない**(源泉を目的関数で動かすと、保存則が「源泉の誤りを増幅する
装置」から「隠す装置」へ変わる)。

### 1.2 陸面蒸発散

土壌バケツの実蒸発散をそのまま S に入れる。式と定数は §6。

### 1.3 モンスーンコンベア(源泉・シンクの対)

実装: `buildConveyorPrep` / `applyConveyor`(step06 1054-1290)。`conveyorStrength` = 0 で準備ごと飛ぶ。
[事前登録_コンベア接続_2026-08-18](../事前登録_コンベア接続_2026-08-18.md)。月平均風では表せない
「暖流上の水蒸気の帯」を、**保存する取水・給水の対**で表す。

- 取水(海): 自転の逆向きに陸まで走査した距離が `conveyorFetchKm` 以内で SST 正偏差のある海。
  取水量 = min(0.5·S_i, `conveyorStrength`·anchor·W_prev)。**前反復の W に比例**(在る水しか運べない)、
  S は負にならない。
- 給水(陸): 自転方向の海までの距離で exp 減衰(`conveyorCoastKm`)する海岸帯。R-H 位相因子
  (自転方向 5〜60° の加熱が強いほど給水を許さない)を掛ける。
- 緯度窓: ITCZ 中心の極側 〜 リッジ + `conveyorLatPolewardDeg`、外は `conveyorLatSoftDeg` で線形に落ちる。
  夏ゲートは日射の季節偏差で作る。
- **保存**: 経度 10° ビン × 半球のセクターごとに Σ取水 = Σ給水(面積重み)。給水先の無いセクターは
  取水もしない。初回の結合反復は W_prev が無いので不発。実測は `CONVEYOR_STATS`。全球の S は変えない。

## §2 輸送 — 水はどう動くか

実装: `solveMoistureTransport`(moisture_transport 184-916)、呼び出しは step06 1594-1610。

**2.1 気柱輸送風 V_q**(step06 1580-1592)。**輸送ソルバだけ**が
V_q = `moistureWindSurfaceBlend`·V_10m + (1−blend)·V_free を読む。蒸発・G の判定・風の採点は
地表風のまま。blend = 1 で従来と一致。
[事前登録_気柱輸送風の分離_2026-08-25](../事前登録_気柱輸送風の分離_2026-08-25.md)。

**2.2 渦拡散** κ = `moistureEddyDiffusivityM2PerS`(スカラー)。面の値は両側セルの平均(共有面で
一意 = 保存的)。セルごとの場を渡す口はあるが既定では使わない(§8)。

**2.3 数値の作法**

- 移流は**風上流束**(中心平均は負の W を作る)。共有面で一度だけ計算するので Σ A_i div = 0 が
  厳密に成り立つ。経度は周期境界、極の辺長は 0。凝結項は陰的(λG が大きくても無条件安定)で、
  凝結で除いた水は必ず同じセルの降水へ計上する。
- 解法は自動選択。閾値凝結が無ければ Krylov 法(前処理 = 線緩和 2 掃引)、あれば線緩和 SOR。
  ω は 1.6 から始め発散を検知したら 1.0 へ落として解き直す。**どちらも同じ不動点**なので探索空間
  には入れない。
- 収束判定は**方程式の残差** max|S − C(W) − ∇·(WV)| / 平均S(既定 1e-5)であって「1 反復あたりの
  変化量」ではない(緩和の遅い系で嘘をつく)。上限 `TRANSPORT_MAX_ITERATIONS`。前反復の解を
  `initialGuessMm` に渡す温間開始は反復数だけを変える。未収束の月は `CONSERVATIVE_STATS` に数え、
  §7.2 の関門で失格にする。

**2.4 未接続の口 — 鉛直輸出。** `verticalExportRatePerMonth` / `exportedMm`(moisture_transport
100-165, 894)は実装済みだが **step06 は一度も渡していない**。2 次元の柱収支は「乾いた収束」(地表で
収束した水蒸気が逆転層の下に閉じ込められ、中層は沈降して乾く)を表せず、収束した水は必ずどこかで
降るしかない。その唯一の口が塞がっている。繋ぐなら抜けた水を上昇域へ返して全球で閉じること。

## §3 凝結の閉包 — 水はどう落ちるか

実装: step06 1526-1570。[事前登録_凝結閉包の二成分化_2026-08-26](../事前登録_凝結閉包の二成分化_2026-08-26.md)。

```
c    = condensationClosureBlend                    v47 で 0.132。c = 0 なら C = rate·W
rate = max(0.05, λ·G),  λ = condensationRefWindMs·SECONDS_PER_MONTH / L
       L = 陸 moistureDecayLandKm / 海 moistureDecayOceanKm
lin  = (1−c)·rate + c·(30.44 / backgroundCondensationTimeDays)   層状の背景凝結
conv = c·(30.44 / convectiveAdjustmentDays)                      湿潤対流
cap  = criticalColumnRelativeHumidity · W_sat(T) / max(0.05, G)  除算形(既定)
     = W_sat(T) · max(0.05, RHcrit − capLiftSubtractGamma·G)     減算形(γ>0)
fl   = condensationRhFloor · W_sat(T)                            線形項の床(既定 0)
```

W_sat は `saturatedColumnMm`(evaporation 72)。**線形項**は W に比例してゆっくり降る背景で、床 fl を
置くと「凝結を駆動するのは W の量ではなく飽和からの距離」になり床下の W は輸送で生き残る。
**対流項**は閾値超過分だけを速く降らせる — 持ち上げ(G 大)は cap を下げて発火させ、沈降(G 小)は
cap を上げて対流を止める(水は降らず下流へ輸出される)。C = rate·W だけでは凝結率を下げても水は
消えず下流で降るだけで、「抑制」が総量を動かせなかった。`max(0.05, …)` が 2 か所(rate の床と cap の
分母)あるのは G → 0 の発散止め。

**λ と G は互いに縮退している**(αG と λ/α は同じ方程式を与える)。意味を持つのは G の空間的な幅
だけで、平均は λ 側に吸える。独立の物差しは **W の絶対値**しかない(`CONSERVATIVE_STATS.meanWaterMm`、
実物は約 25mm)。これが現在の最大の欠陥で、蒸発と降水は実寸なのに W だけ 1/5・滞留 1.2 日(実物 9 日)
である。解体の計画は [計画_W実寸化章_2026-09-02](../計画_W実寸化章_2026-09-02.md)。G を全球年平均で
割って規模を λ へ移す機構(`snapshotGNorm`)は実装済み・既定 0(§8)。

## §4 凝結率の係数 G — どこで凝結しやすいか

実装: `convertToPrecip`(step06 2445-3004)。出力は 2996 行で `G = blockFactor × lift × crhFactor`。
lift は下記の因子の積(積なので順序は答えを変えない)。判定に使う量はすべて位相・トポロジー
(リッジ緯度・極前線緯度・ITCZ 中心・海岸距離・海盆幅・自転方向・標高勾配)で、緯度帯や地名の
決め打ちは無い。

### 4.1 上げる因子

| 因子(行) | 式 | 主定数 |
| --- | --- | --- |
| ITCZ 傘(2668) | `1 + itczLiftBoost·gI·marineW`。gI = max(帯の影響, 赤道常湿帯)、marineW = min(1, 供給/`itczLiftSupplyNorm`) | `itczLiftBoost`, `itczPrecipWidthFactor` |
| 赤道常湿帯(2663) | `equatorialItczResidual·exp(−d²)`、d = (緯度 − 年平均 ITCZ 中心)/(半値幅×0.55) | `equatorialItczResidual` |
| 湿潤収束(2693) | `1 + convergenceLiftBoost·wetConv`。wetConv = 飽和した収束強度 × 湿潤ゲート | `moistureConvergenceNorm`, `convergenceWetnessNorm` |
| 前線収束(2700-2735) | `1 + frontalLiftBoost·frontW`。極向き風 > 0 かつ湿りの極向き勾配 > 0、窓は \|リッジ\| − `frontalWindowEquatorwardDeg` 〜 \|極前線\| | `frontalLiftBoost` |
| ストーム帯(2745-2752) | `1 + (stormTrackBoost + stormTrackWinterBoost·1.4·冬深さ)·帯重み`。台形帯 \|リッジ\|+4 − `winterStormEquatorwardReachDeg`·冬深さ 〜 \|極前線\|+12 | `stormTrackBoost`, `winterStormEquatorwardReachDeg` |
| 地形性上昇(2755) | `1 + orographicBoost·min(2.5, 上り勾配/orographicRefSlope)` | `orographicBoost`, `orographicRefSlope` |
| 高温湿潤の対流(2858) | `1 + warmHumidConvectiveBoost·warmth·供給ゲート²`。陸のみ、warmth = clamp((T−22)/8) | `warmHumidSupplyNorm` |

`moistureConvergenceIndex`(step06 445)は供給場を 1.5° 平滑してから −∇·(q̃V) を有限体積で取る。
`convergenceStrength01` は x/(1+x)、`wetnessGate01` は smoothstep で、**乾いた収束は降水を作らない**。
地形性の勾配は `orographicCrestBlend` でセル内 p95 標高(稜線)へ寄せるが、**海セルには峰を立てない**
(2734-2739。1° の海セルに含まれる小島の p95 が海の真ん中に 2.5km の山を生やすため)。

### 4.2 下げる因子

```
descW  = 1(|緯度| が |リッジ| − subsidenceBandEquatorwardDeg 〜 |リッジ| + 5 の帯内)
       = exp(−d²/16)(帯の外。縁は階段ではなくガウス裾で続く)
subs   = descW · (1 − subsidenceItczProtection·gI·marineW) · (1 − eastRelief) · (1 − troughRelief)
G_subs = (1 − subsidenceSuppression·subs) ^ subsidenceSuppressionExponent
```

**寒流沿岸**(2840-2850): 陸・\|緯度\| 10〜50°・海岸 300km 以内で近傍 SST 偏差が −0.8°C を下回るとき
×(1 − `coldCoastSuppression`·min(1, −偏差/2.5))。**局所雨陰**(2759): 下り勾配で
×(1 − (1 − `rainShadowFloor`)·min(1, 勾配比))。

### 4.3 沈降の地理的非対称

沈降を「緯度の帯」として一様に掛けると経度方向の実在の非対称が消える。以下はすべて幾何と
トポロジーで書いてある。

- **東岸緩和**(2799-2806): 自転方向の東に海が近い陸で沈降が緩む。`eastCoastSubsidenceRelief` ×
  東の海の SST 偏差ゲート × 供給実績ゲート(`eastReliefSupplyNorm`)× exp(−東の海までの距離/
  `eastCoastSubsidenceDecayKm`)。2 つのゲートは「暖かいが乾いた流入」の海を自動的に除外するために要る。
- **海盆非対称**(step06 990-1050, 2781-2789): 亜熱帯高気圧は海盆東側の細胞なので海盆西部で帯を開く。
  g = exp(−海盆西縁距離/`subsidenceBasinAsymDecayKm`) × 幅ゲート (海盆幅° − 35)/20。陸は東の海から
  幅ゲートを引き継ぎ、供給実績ゲートを掛ける。幅ゲートは境界流と同じ尺で、狭い縁海を自動的に外す。
- **トラフの位相**(2550-2600, 2809-2816)と**沿岸ジェット**(2517-2545, 2632-2650, 2828): 既定 0(§8)。

### 4.4 恒等 1 になっている因子

- `blockFactor`(`upwindMountainFactor` 3006-3046): 風上 `upwindBlockScanKm` を遡り稜線比高が 300m
  (**無名リテラル**)を超えたら遮蔽。`upwindBlockFloor` = 1 と `upwindBlockReliefM` = 1e9 で恒等 1。
  保存型では風上で降ったぶんが収支で既に減っており二重計上になる(外したら詳細一致率 +0.59)。
- `crhFactor`(2907-2955): exp(`crhSuppressionSharpness`·(CRH − 1))。鋭さ 0 で恒等 1。有効時の CRH は
  `crhFromWater` = 1 なので W/W_sat の厳密値を使う(代理場は使わない)。

**したがって現行の G は実効的に「持ち上げ積 × 沈降残存」だけ**である。

## §5 供給場 — G のゲートを作る第二の場

実装: `traceMoistureSupply`(step06 2319-2444)。保存型でも毎反復・全月走る。
**これは源 S ではない。** 湿潤源への**到達可能性**の無次元場であって水蒸気量ではなく、S に一切
入らない。読むのは §4 のゲートと診断だけ。混同すると水が二重に湧く。

各セルから月平均風を遡り(1 ステップ = 南北 1 セル、上限 `moistureTraceMaxKm`)、経路上で
q_s(T)/q_s(20°C) をステップ距離重みで線積分する。減衰は exp(−歩幅/L) で、L は §3 の λ と**同じ**
`moistureDecayLandKm` / `moistureDecayOceanKm`。風速 0.5 m/s 未満または減衰 0.02 未満で打ち切り。

- **陸面再循環**: 陸セルは `landRecyclingStrength`·min(1, ET/`soilPetScaleMmPerMonth`) の重みで供給源に
  なる(step06 2007-2009)。乾いた砂漠は自己湿潤せず、雨の届く内陸は再蒸発で繋がる。
- **Fetch 則**: 閉じた内海(`buildSmallWaterMask`、面積 1.2M km² 未満の海成分)からの供給は水域ごとに
  保留し、横断幅の確定時に f = clamp((min(Fetch, `fetchOpenOceanCapKm`) + 250 − 進入前陸距離)/500,
  0.12, 1) を掛ける。内海は自分の幅ぶんしか内陸を湿らせない。海峡で外洋に繋がる縁辺海は外洋と
  同成分になり対象外。**経路障壁の脱水**は `orographicDepletionM` = 1e9 で恒等 1(§8)。
- **月ブレンド**: 前/当/翌月を `SUPPLY_MONTH_BLEND_SIDE` = 0.25/0.5/0.25 で均す(`blendSupplyMonths` 850)。
  非線形変換の**前**に風向の月替わりの断絶を埋める。後処理の `precipMonthBlend` とは役割が違う。

**使い道の一覧**(供給場の存在理由): ITCZ 傘と沈降防護の marineW / 湿潤収束の湿潤ゲート / 前線の
勾配場(既定。`frontalGradientUsesWater` で W に切り替え可)/ 東岸緩和と海盆非対称の供給実績ゲート /
高温湿潤の供給ゲート / CRH の代理(`crhSupplyNormPerQSat`。既定は W から解くので未使用)/
診断の海由来・陸由来の分解。

## §6 土壌水分の季節記憶

実装: `solveSoilWater`(step06 579-700)。各陸セルに月別貯水 S(mm)を持ち、乾季へ前月までの雨を持ち越す。

```
available = 前月貯水 + 当月降水
wetness   = clamp(available / soilWaterCapacityMm, 0, 1)
ET        = min(available, potentialEtMmPerMonth(気温) × wetness)
runoff    = max(0, available − ET − 容量)
S         = clamp(available − ET, 0, 容量)
```

- 可能蒸発散は `soilPetScaleMmPerMonth` を 20°C の飽和水蒸気圧で規格化してスケールし、0°C 以下は 0(凍結)。
- 12 月 → 1 月を接続し、年間貯水変化が `SOIL_SPINUP_TOLERANCE_MM`(陸セル平均)を下回るまで空回し
  (上限 `soilSpinupYears`)。
- **解は一意ではない。** available ≥ 容量 の月は ET が貯水に依らず写像の傾きが 1 になり(陸セル月の
  33.5%)、年間縮小率が 1 のままのセルが陸の 11.15% ある。そこでは周期定常解が連続族をなす。
  **貯水を絶対値として読んではならない** — 信用してよいのは ET と流出で、大気へ渡る実蒸発散は初期値に
  依らない(面積平均の相対差 0.00%。[実験記録_土壌の縮退_2026-08-01](../実験記録_土壌の縮退_2026-08-01.md))。
- 大気への供給は**実蒸発散(質量フラックス)**に比例させる。湿り度分数での正規化は実測で悪化した
  (供給はフラックスであって湿り具合ではない)。

## §7 結合と後処理

実装: 結合反復 step06 1960-2120、後処理 `applyPostAdjust`(1810-1888)。供給 → 降水 → 土壌水分 →
蒸発散 → 供給 の輪を、**後処理まで含めた一つの演算子**の固定点として解く。反復内と最終出力で同じ
演算子を使わないと、土壌が収支に使った降水と最終降水が食い違う。

- 収束指標 `meanAbsChange` = 陸面積重み平均 \|ΔP\|、許容差 `COUPLING_TOLERANCE_MM_PER_MONTH`、上限
  `COUPLING_MAX_ITERATIONS`(較正対象外)。残差は**緩和の前**で測る(不動点への近さ F(x) − x であって
  今回どれだけ動かしたかではない)。未収束は診断に `converged: false` として残す。
- **適応緩和**: α = 1 から始め、残差が増えた回だけ半減(下限 0.1)、減った回は ×1.5 で 1 へ戻す。
  緩和は不動点を変えないので物理ではなく解き方の変更。加速は §8。
- 最終の土壌診断は収束後の最終降水場で解き直す(統合水収支が閉じる)。コンベアと前線判定は前反復の
  W を読むので、収束すれば自己整合する。

**7.1 後処理**(いずれも陸のみ・セル年総量を保存)

```
床 floorMm = min(winterFloorMaxMm, winterFloorFracOfWettest × 最多雨月)
適用月     = 正規化赤緯 < 0.5 かつ |緯度| が |リッジ|+1 〜 |極前線|+12
移転量     = min(不足合計, 余剰合計 × 0.35)   余剰月から不足月へ比例配分
月平滑     = (1−2b)·当月 + b·前月 + b·翌月,  b = precipMonthBlend(循環 3 点)
```

床は最乾月が 0mm に張り付く癖への対策で、移転上限が無いと夏の雨をほぼ全部持って行く。月平滑は
遷移月の陥没が「夏半年の最乾月」になる誤判定への対策。

**7.2 収束を要する反復と診断。** 既定で走る反復は **4 系統**(輸送 / 結合 / 土壌の周期定常 / EBM の
周期定常)。CRH 内部解法を有効にすると 5 系統目(外側反復、上限 `VIRGA_OUTER_ITERATIONS`)が加わるが
既定 off。**1 つ通ったことは他が通ったことを意味しない**ので、判定は `evaluateNumericalSoundness`
(scripts/validate_criteria.ts)の凍結済みの関門 1 か所へ集約してある。`runPipelineWithPrecipDiag` で
`condRateG`・`waterMm`・各持ち上げ因子・沈降の分解が month × cell で取れる。
不変量「最終 = 後処理前 + 後処理差分」は厳密に成り立たねばならない(門はユニットテスト)。

## 付録 B 旧(非保存)モデルとの対照

2026-08-09 より前は `降水 = (追跡供給 + 渦供給) × 持ち上げ × 風上遮蔽 × 全球係数 × √気圧` という
**倍率の積**だった。この式はもう成り立たない。旧因子の行き先:

| 旧因子 | 保存型での扱い |
| --- | --- |
| 追跡供給 | **源 S ではなく、G のゲート専用の第二の場**(§5)。ここが最も誤読された |
| 経路障壁の脱水 | 外した(輸送方程式が表す。§8) |
| 渦供給 | 未接続のまま死んでいる。拡散で繋ぐ案は棄却済み(§8) |
| 持ち上げ・抑制 | 凝結率の係数 G へ(§4)。**降水の倍率ではない** |
| 風上遮蔽 | 外した(二重計上。§8) |
| 全球係数 × √気圧 | 保存則の中に置き場所が無い。消えた |
| 結合反復・土壌水分 | そのまま(§6, §7) |

較正の実測値は `out/validate/report.json`(来歴つき)と [較正記録](../較正記録.md)を正本とする。
既知の弱点は §3 の λG 縮退(W が実物の 1/5)と、降水分布の両端が潰れていること。
