## 構成

**現行(2026-08-09 以降、`conservativeMoisture = 1`)は保存型である。**

```
∇·(u W) − ∇·(D ∇W) = S − C     C = rate · W,  rate = max(0.05, λ·G)
```

W(可降水量)を状態とする定常解を解き、その凝結項 C が降水になる。
詳細は **§7** を読むこと。

> **旧構成(2026-08-09 より前、非保存)**:
> `降水 = (追跡供給 + 渦供給) × 持ち上げ × 風上遮蔽 × 全球係数 × √気圧`
> **この式はもう成り立たない。** 保存型では降水は倍率の積では書けず、
> 輸送方程式の解である(§7)。以下 §1〜§5 は、旧式の各因子が
> **保存型のどこに入ったか / 外されたか**を対照して述べる。
> `precipScaleMmPerUnit`(全球係数)は非保存経路にのみ残存し、現行では効かない。

### 1. 追跡供給(風上トレース)

各セルから月平均風を遡り(1 ステップ = 南北 1 セル相当、最大 5200km)、
経路上の海セルで q_sat(T)/q_sat(20°C) に比例した蒸発を拾う。減衰は
海上 e^(−d/2200km)・陸上 e^(−d/1700km)。

**経路障壁の脱水(現在は無効)**: 保存型では風上の山で水が減ることを
輸送方程式そのものが表現するため、この倍率は二重計上になる
(`orographicDepletionM = 1e9` で無効化、段 2)。以下は旧経路の記述:

供給源と対象の間の「これまでの最高標高」が両端より
高い分だけ、拾いを e^(−比高/1600m)(下限 0.25)で減衰(風上斜面で雨として
落ちた分。パタゴニア・チベット風下の雨陰の主機構)。逐次複利にすると丘陵の
起伏が累積し全球が乾く(較正記録 2026-07-30 の失敗)— 最高障壁 1 本で判定。

**陸面再循環(R3 以降は土壌水分の季節記憶)**: 当初はパス 1(海のみ供給)の
降水から陸の湿りを求める無記憶方式だったが、2026-08-01 に**根群域バケツ**へ
置き換えた(下記「6. 土壌水分の季節記憶」を参照)。乾いた砂漠は
自己湿潤しない(サハラ)が、雨の届く内陸は再蒸発で繋がる(シベリア)。

**供給の月ブレンド(R2)**: 供給場を前/当/翌月で 0.25/0.5/0.25 に均す
(循環 3 点、1 月と 12 月は隣接)。月平均風の単一方向トレースは風向の月替わりで
供給が断絶するため。後段の降水場平滑(`precipMonthBlend`)とは役割が異なり、
こちらは非線形変換の**前**に断絶を埋める。

**Fetch 則(WL#32)**: 閉じた内海・湖(海の連結成分で面積 < 1.2M km²。
カスピ海・黒海級。海峡で外洋に繋がる縁辺海は外洋と同成分になり対象外)からの
供給は、水域ごとに保留して横断幅(Fetch)確定時に
f = clamp((min(Fetch, 2000km) + 250km − 進入前陸距離) / 500km, 0.3, 1)
を掛けて計上する。内海は自分の幅ぶんしか内陸を湿らせない。位相判定なので
地理中立。A/B は [../較正記録.md](../較正記録.md) 2026-07-30 参照。

### 2. 渦供給(ストームトラック帯)— **保存型では死んでいる**

> `stormSupply` は非保存の降水式にしか入っておらず、保存型の源にも凝結率にも
> 現れない(段 6 の移行漏れ)。2026-08-16 の生存性診断で
> `stormMoistureSupply` / `stormMinQRel` / `stormMoistureDecayKm` の 3 定数が
> **答えに 1 ビットも影響しない**と確認済み。
> **外すより繋ぐほうが筋**で、設計は
> [../診断_ストーム供給は保存型で死んでいる_2026-08-15.md](../診断_ストーム供給は保存型で死んでいる_2026-08-15.md)。
> 以下は旧経路の記述:

移動性低気圧による海からの水蒸気混合は月平均風では表現できない(derle の
中緯度冬雨問題)。リッジ+1°〜極前線+12° の台形帯で、
1.6 × q_sat(T_海+3°C)× e^(−海岸距離/減衰長)、寒候期 ×1.4。
- **T_海 = 近傍(±6 セル)で最も暖かい海面の気温**(冬の東岸の低気圧は
  暖流から汲む — 湾流・黒潮型。局所陸気温では一段低すぎる)。下限 qRel 0.4。
- **減衰長 = 1,400km × (0.5 + 0.5×風上海率)**(WL#31 の onshore 2,000km /
  offshore 1,000km 規則の連続化。風上 500km ウォークの海率で判定)。

### 3. 持ち上げ・抑制 → **保存型では凝結率 G を作る**(中核)

以下の倍率の積が §7 の `G` になる。**降水そのものではない** —
G は「その場でどれだけ凝結しやすいか」で、降水量は輸送方程式が決める。
`convergenceLiftBoost`(水蒸気フラックス収束による持上げ)も G の因子で、
2026-08-15 に 0 から復活させ現在 0.5。

- ITCZ 収束: ×(1 + 2.2·影響·**海洋性**)。海洋性 = min(1, 供給/1.1) —
  傘は湿潤収束が豊富なときだけ開く(乾いた内陸のトラフ直下 = アラビア型の
  熱的低気圧は乾いた低気圧のまま)。沈降防護にも同じ重みを掛ける。
- ストームトラック: ×(1 + (1.1 + 冬 0.5)·帯重み)
- 地形性: 上り勾配 ×(1 + 1.6·min(2.5, 勾配/基準))、下り(局所雨陰)
  ×max(0.35, 1−勾配比)
- 亜熱帯沈降: 下降枝全域(リッジ −16°〜+5°)×(1 − 0.68·重み)。
  ITCZ 影響下は 85% 防護。**東岸緩和**: 自転方向の東に海が近い陸は
  ×(1 − 0.8·e^(−距離/900km)) だけ沈降が緩む(亜熱帯高気圧の西翼湿潤 =
  バミューダ高気圧型。トポロジー規則であり座標決め打ちではない)。
- 寒流沿岸(|lat| 10-42°、海岸 300km 以内、近傍 SST 偏差 < −0.8°C):
  ×(1 − 0.45·強度)(ナミブ/アタカマ型)

### 4. 風上山脈の遮蔽 — **保存型では外した**

> 段 3 で外したところ**改善した**(詳細 +0.59、陸降水が観測へ +20mm)。
> 保存型では「風上の山で水が来ない」を輸送方程式が自然に表現するので、
> 遮蔽倍率は二重計上になる(`upwindBlockFloor = 1`, `upwindBlockReliefM = 1e9`)。
> **稜線標高そのものは地形性上昇(§3)で今も使う。** 以下は旧経路の記述:

風上 900km を走査し、経路最大の**稜線標高** − 自標高 > 300m から遮蔽開始、
1200m 超で最大。追跡・渦供給の双方に掛かる(パタゴニア型雨陰)。

**稜線標高 ≠ 平均標高**(2026-08-01、R5)。狭い山脈は 1° 平均で稜線が均される
ため、生の高解像度標高(ETOPO 2022 60 秒)から**セル内 p95 標高**を作り
(`scripts/build_crest_elevation.py` → `src/domain/data/earth_crest_1deg.json`)、
遮蔽・脱水にのみ使う。気温・地表状態は平均標高のまま。実測で狭い山脈と
高原を判別できる: 南部アンデス 989 → 1,734m(1.75 倍)、チベット高原
4,914 → 5,277m(1.07 倍)、アマゾン平地 33 → 43m。粗格子への集約は最大値
(遮蔽は最も高い壁で決まる)。高解像度データの無い地形(手続き生成・
簡易プリセット)では稜線標高 = 平均標高で、演算子は全惑星共通。

## 5. 結合反復(土壌 ⇄ 再循環 ⇄ 降水)

供給 → 降水 → 土壌水分 → 蒸発散 → 供給 の輪を、**後処理(冬季床の再配分・
降水の月平滑)まで含めた一つの演算子**の固定点として解く。反復内と最終出力で
同じ演算子を使わないと、土壌が収支に使った降水と最終降水が食い違う。

- 収束指標: 陸面積重み平均 |ΔP|、許容差 0.20 mm/月、
  上限 `COUPLING_MAX_ITERATIONS = 24` 回(較正対象外。2026-08-10 に 8 → 24)。
- 未収束は診断に `converged: false` として残す。
- 最終の土壌診断は収束後の最終降水場で解き直す(統合水収支が閉じる)。
- 実測(2026-08-16): 8〜9 回で収束。残差 0.11〜0.20 mm/月(許容 0.20)。
  **保存型では閉包 (P−E)/E が惑星パラメータを振っても −0.0% を保つ**
  (惑星応答の 18 水準すべてで確認、
  [../実験記録_惑星応答の初測定_2026-08-16.md](../実験記録_惑星応答の初測定_2026-08-16.md))。

## 6. 土壌水分の季節記憶(R3)

各陸セルに月別貯水 S(mm)を持ち、乾季へ前月までの雨を持ち越す。

```
available = 前月貯水 + 当月降水
wetness   = clamp(available / 容量, 0, 1)
ET        = min(available, 可能蒸発散(気温) × wetness)
runoff    = max(0, available − ET − 容量)
S         = clamp(available − ET, 0, 容量)
```

- 容量 600mm(深根系の植物利用可能水量)、可能蒸発散は 20°C で 90mm/月、
  0°C 以下は 0(凍結)。
- 12 月 → 1 月を接続し、年間貯水変化が許容差(陸セル平均 0.05mm)を下回るまで
  空回し(上限 2000 年)。乱数を使わない決定的な手順だが、
  **解そのものは一意ではない**: available ≥ 容量 の月は蒸発散が貯水に依らず
  写像の傾きが 1 になり(陸セル月の 33.5%)、年間縮小率が 1 のままのセルが
  陸の 11.15% ある。そこでは周期定常解が連続族をなし、初期貯水が残る
  (空 対 満杯で貯水は最大 600mm 違う)。
  ただし**大気へ渡る実蒸発散は初期値に依らない**(面積平均の相対差 0.00%)。
  縮退するのはまさに「蒸発散が貯水に依らない」領域だからである。
  貯水を絶対値として読んではならない。信用してよいのは蒸発散と流出。
  実測: [../実験記録_土壌の縮退_2026-08-01.md](../実験記録_土壌の縮退_2026-08-01.md)
- 大気への供給は**実蒸発散(質量フラックス)**に比例させる。湿り度分数
  S/容量 での正規化は実測で悪化した(供給はフラックスであって湿り具合ではない)。

## 7. 保存型水蒸気輸送(P2-1)— **2026-08-09 以降、これが本経路**

上記の「追跡供給」は湿潤源への**到達可能性**であって水蒸気量ではない。
可降水量 W を状態とする保存型の定常解を `src/sim/moisture_transport.ts` に
実装している(風上有限体積・共有面フラックス・凝結項は陰的)。

**`conservativeMoisture = 1`(既定)で接続済み。**
段階置換の記録は [../計画_保存則の段階的置換_2026-08-09.md](../計画_保存則の段階的置換_2026-08-09.md)。

> **訂正(2026-08-15)**: この節は 2026-08-09 の接続後も
> 「実装済・**未接続**」「接続には凝結の物理化が必要」と書かれたままだった。
> 中核の降水機構について仕様書が実装と食い違っていた状態であり、
> **保存型の定数が仕様書に 1 つも載っていない**ことを意味していた
> (禁止事項の「隠しパラメータ」に触れる)。以下に現行の姿を書く。

### 解いている式

セルごとの定常収支(源 S、凝結 C、移流 + 渦拡散):

```
∇·(u W) − ∇·(D ∇W) = S − C     C = rate · W
S = 海面蒸発 + 陸面蒸発散（実蒸発散）
rate = max(0.05, λ · G)         λ = U_ref / L   [1/月]
```

- **λ は凝結寿命の逆数**。`condensationRefWindMs`(U_ref)が 1 か月に進む距離を
  `moistureDecayLandKm` / `moistureDecayOceanKm`(L)で割る。
  非保存時代の「水が消える距離」を**凝結寿命として写した**もの。
- **G は凝結率の係数** = 風上遮蔽 × 持上げ各種 × 沈降残存 × CRH 抑制の積。
  §3 の倍率を使う。**§1 の経路障壁・§2 の渦供給・§4 の風上遮蔽は
  段 2〜6 で外した / 未接続**(冒頭の生死一覧を参照)。
  **保存型では降水は倍率の積では書けない** — 輸送方程式の解だからである。
  因子分解が意味を持つのは G までであって降水そのものではない。
- **渦拡散** `moistureEddyDiffusivityM2PerS`。
- **閾値凝結(`holdingCapacityMm`)は渡していない**ので `C = rate·W` が厳密。

### 雲底下の再蒸発(virga)

機構(Gregory 1995 の形で 失う割合 = k(1−RH)/√P、上限つきを **rate に掛けて**
解き直す外側反復)は **2026-09-06 に削除した**。2 度棄却(非保存時代と
2026-08-15)されており、既定 0 のまま経路が飛んでいたため。
**保存型では水を消さない**設計だった — 凝結しなかった水は気柱に残り、
輸送されて別の場所で降る。外側反復の機械そのものは段 25 の CRH 内部解法が
使い続けている。

### 収束を要する反復は 5 系統ある

輸送 / virga の外側反復 / 結合反復 / 土壌の周期定常 / EBM の周期定常。
**1 つ通ったことは他が通ったことを意味しない。**
未収束の解にも成績はつくので、判定は `evaluateNumericalSoundness` の
凍結済みの関門 1 か所へ集約してある(2026-08-14)。

### 診断で取り出せる場

`runPipelineWithPrecipDiag` で `condRateG`(G)と `waterMm`(W)が month × cell で
取れる。**W は凝結量と対**(virga があるときは最後に解いた W)。
道具: `scripts/diag_water_vapor.ts` / `diag_condensation_width.ts` /
`diag_water_starved.ts`。

### 既知の弱点(2026-08-15 時点)

- 南極を除き面積重みつきで見ると、**モデルの降水は観測より狭い**
  (対数標準偏差 0.429 対 0.530)。**乾いた端が作れない** —
  1% 分位がモデル 64mm に対し観測 9mm
  ([../診断_乾いた端が作れない_2026-08-15.md](../診断_乾いた端が作れない_2026-08-15.md))。
- W が 0 へ潰れているのは**南極だけ**で、遠いからではなく寒いから
  ([../診断_枯渇しているのは南極だけ_2026-08-15.md](../診断_枯渇しているのは南極だけ_2026-08-15.md))。
