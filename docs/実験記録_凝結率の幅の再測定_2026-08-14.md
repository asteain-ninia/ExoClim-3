# 実験記録: 凝結率の幅を汚染なしで測り直した(段 20 再測定)— 棄却

日付: 2026-08-14
事前登録: [事前登録_凝結率の幅の再測定](事前登録_凝結率の幅の再測定_2026-08-14.md)
前段: [診断_Wの累積汚染](診断_Wの累積汚染_2026-08-14.md)
**判定: 棄却。** ただし副産物として、汚染の読みが実測で検証された。

## 測ったもの

`crhSuppressionSharpness` を 0/1/2/3/4 で掃引。`crhFromWater = 1` 固定、
他の 62 定数は較正 v22 のまま。積算器のリセット漏れを直したうえで測った
ので、**W はどの行もその水準の値**である(段 20 の表は累積平均だった)。

```

1     154s     6.0   82.111  72.74  42.02   3.65   1.51   0.14   0.10   0.87
2     379s     9.6   78.251  71.82  39.43   2.44   1.72   0.34   0.05   0.98
3     677s    17.2   79.813  71.70  40.00   2.82   1.47   0.05   0.03   1.40
4    1346s    38.4   81.781  72.24  43.11   3.25   1.47   0.03   0.03   0.88

```

## 結合反復が発散していた(最重要。上の表は 2 行しか読めない)

掃引に結合反復の収束を印字させて測り直した。**収束の崖は鋭さ 1 と 2 の
あいだにある。**

```
鋭さ  結合反復        残差 mm/月（許容 0.2）   W(mm)   v3       判定
0     収束    8/24      0.165                 3.4    85.235   有効
1     収束    7/24      0.093                 6.0    82.111   有効
2     未収束 24/24      4.695                 9.6    78.251   適用範囲外
3     未収束 24/24     26.652                17.2    79.813   適用範囲外
4     未収束 24/24     46.608                38.4    81.781   適用範囲外
```

未収束の 3 行はいずれも上限 24/24 に張り付いており、**「ぎりぎり届かない」
ではなく完全な発散**である。反復を増やしても解には近づかない。
輸送と virga はどの水準でも未収束 0 なので、**輸送だけを見ていると
健全に見えてしまう** — これが段 20 の見落としの正体。

**有効な水準は 0 と 1 だけで、W は最大 6.0mm。実物 25mm には遠く届かない。**
この機構は W を実物へ近づける前に結合反復を壊す。

### 副産物: 現行設定の収束余裕が薄い

鋭さ 0(現行の出荷設定)の結合反復の残差は **0.165 mm/月、許容 0.2 の 83%**
である。8 反復で通っているとはいえ余裕は薄い。何か別の変更が入ったときに
静かに越える恐れがあるので、**結合反復の残差は今後も監視対象**にする。

## 予測の答え合わせ(格下げして記録する)

事前登録に「鋭さ 4 の真の W は 29.1mm より必ず大きい(見積もり 30〜45mm)。
29.1mm 以下が出たら私の汚染の読み自体が誤り」と書いた。実測は 38.4mm で
範囲に入ったが、**この 38.4mm は未収束の解から出た数字なので、
実測による裏づけとしては弱い**。同じ設定の段 20 の 29.1mm も同様に
未収束の解なので、両者の比較は「道具が何を表示するか」の比較でしかない。

累積汚染そのものは**コードを読めば動かない事実**であり(リセット関数が
項目を戻していない、掃引が同一プロセスで回す)、そちらで確定している。
実測は整合しただけで、証明ではない。**証拠の格を混ぜないこと。**

段 20 の「実物 25mm に着地した」という主張が成立しないことは変わらない
— 着地したと読んだ数字が、そもそも解ではなかった。

## 判定(事前登録の 6 条件)

判定 1 で鋭さ 2・3・4 が落ちるので、**以降の条件は鋭さ 0・1 だけで見る**
(未収束の行の W も v3 も読まない、が事前登録の規定)。

1. **収束** — 鋭さ 0・1 は輸送・virga・結合反復のすべてが収束。
   **鋭さ 2 以上は結合反復が発散し、適用範囲外。**
2. **主判定: W が 20〜30mm に入る水準がある** → **満たさない。**
   有効な水準の W は 3.4 と 6.0 のみ。実物 25mm には遠く届かない。
3. 番人(サハラ ≤ 3.5) → 鋭さ 1 は 3.65 でわずかに外れる。
4. 番人(コンゴ 1.31 ± 0.3 = 1.01〜1.61) → 鋭さ 1 は 1.51 で満たす。
5. **成績: v3 が 85.235 から 1.0 以上落ちない** → **満たさない**(鋭さ 1 で −3.12)。
6. 費用 ≤ 600 秒 → 鋭さ 0(146s)・1(149s)とも満たす。

**事前登録の規定により、判定 2 を満たす水準が無いので棄却。**
判定 3 と 5 も鋭さ 1 で外れており、**棄却は三重に確定する**。

これは事前登録に書いた「外れる筋」に近いが、実際の壊れ方はもっと早かった:

> W が鋭さに対して急峻すぎて 25mm 付近を通らずに飛ぶ。その場合、
> CRH の指数抑制は幅を作る道具として**粗すぎる**ことになり、
> 鋭さを連続の較正対象にするのではなく**別の変数を探す**。

窓を飛び越える前に、**そもそも解が存在しなくなっていた**。
非整数の鋭さを探る意味も無い — 崖は 1 と 2 のあいだにあり、
その手前の W は 6.0mm でしかない。
成績を見てから閾値を緩めない(事前登録の「やらないこと」)。

## 分かったこと(棄却でも残るもの)

- **この機構は W を実物へ近づける前に解を壊す。** 有効域(鋭さ ≤ 1)で
  届く W は 6.0mm、目標は 25mm。**性能の問題ではなく、存在の問題**である。
- **鋭さは較正の探索空間に入れてはいけない。** 1 と 2 のあいだに
  収束の崖があり、座標降下がそこを踏むと**発散した解を「良い成績」として
  拾いうる**(実際、鋭さ 4 の 81.781 は鋭さ 2 の 78.251 より「良い」)。
  未収束の解に成績がつく限り、目的関数は数値の破綻を検出できない。
  **これは較正の設計そのものへの警告**である。
- **成績は未収束の領域で非単調になる**(78.25 → 79.81 → 81.78)。
  物理的なトレードオフではなく、発散の度合いが変わっているだけと見るべき。
- **東アジアは有効域でも悪化する**(0.17 → 0.10)。段 20 で
  「東岸を直接殴る手は 7 件すべて尽きた」と結論した問題に対し、
  この機構は**逆方向に効く**。
- 費用は反復数で説明がつく(21k → 32k → 175k → 405k → 895k 反復)。
  ただし鋭さ 2 以上は発散しているので、**費用の増加の大半は空転**である。
  段 20 が「費用 6 倍なので多重格子が前提」と結論したのは、
  **収束しない設定の費用を根拠にしていた**ことになる。

## 残る本丸

**モデルの大気は実物の 7 分の 1 しか水を持っていない**(W = 3.4mm 対 25mm)
という診断そのものは**生きている**。これは `diag_water_vapor.ts` が
自前でリセットしてから測った単発値なので汚染されていない。

CRH の指数抑制はその処方として棄却されたので、**別の変数を探す**必要がある。
`P = λ·G·W` で λ と G の平均は縮退しているため、意味があるのは G の空間的な幅
だけ、という段 20 の考察は依然として正しい([考察_凝結率の意味](考察_凝結率の意味_2026-08-13.md))。

## 派生して見つかった構造的欠陥(この実験より重い)

**較正は数値の破綻を検出できない状態だった。**

収束を要する反復は 5 系統あるが、それを見ていたのは `npm run validate` だけ
だった(そこは 5 系統すべてを見ており、唯一の非零終了の対象)。

```
掃引 exp_pressure_lever.ts   2 系統だけ
較正 optimize_worker.ts      1 系統だけ（EBM の上限到達）
較正の逐次経路 optimize.ts   0。判定が 1 つも無い
```

失格の意図はコードのコメントに明記されていた —「較正が『収束しない領域』へ
逃げ込むのを防ぐ(未収束は歴史的に成績をよく見せる方向に働く)」。
**意図は正しく、実装が追いついていなかった。**

この実験がその実害を実測で示した:

```
鋭さ 2  結合反復 残差 4.695（許容の 23 倍）    v3 78.251
鋭さ 4  結合反復 残差 46.608（許容の 233 倍）  v3 81.781  ← 発散が進むほど「良い」
```

**発散が進むほど成績が良くなる。** 8 時間の探索がこの方向へ登れる状態だった。

対処: 判定を `evaluateResult` の 1 か所へ集約し、`validate` が使うのと
**同じ凍結済みの関門**(`evaluateNumericalSoundness`)を呼ぶ。両方の経路
(並列・逐次)が同じ判定を通る。5 系統それぞれが単独で関門を落とせることを
`tests/unit/sim/calibration_guard.test.ts` で守る。

現行の最良ベクトルはこの厳しくなった関門を通る(`npm run validate` で
数値的健全性 ✅ PASS。EBM 残差 2.48e-5°C / 年次ドリフト 3.19e-2°C)。
ただし**年次ドリフトの余裕は 1.6 倍しかない**ので、今後の変更で
静かに越える恐れがある。
