# 実験記録: 年較差の誤差を夏冬へ分解して、陸面の欠陥を 2 つ切り分けた

日付: 2026-08-03(較正 v12desc の最良点 v3=84.16 上で診断)
道具: `scripts/render_compare.ts` / `scripts/diag_range_vs_wetness.ts`

## きっかけ — 数値だけ見ていたら気づけなかった

較正 v12desc は目的関数 v3 を 76.10 → 84.92 まで押し上げ、気温 RMSE も
6.80 → 4.27°C と大きく改善した。しかし**年較差 RMSE だけは 8.98 → 9.77 と悪化**
したまま動かず、位相 RMS 34.4 日と地域ゲート 14 も不動だった。

「目的関数に入れているのに改善しない」= いまのパラメータ空間にその自由度が無い、
という意味なので、構造を疑うことにした。そこでモデルと観測を同じ物差しで
並べた画像を作った(`scripts/render_compare.ts`、採点と同じ 2° 集約)。

**絵にした瞬間に構造が見えた**。年較差の差分図が一様な誤差ではなく、
はっきりした二極に分かれていた:

- 中央シベリア・中央アジア・北米中央部 … 振幅が**大きすぎる**(赤)
- サハラ・アラビア・オーストラリア・北極沿岸 … **小さすぎる**(青)

陸の熱容量は全球で 1 つの定数(`landEffectiveWaterDepthM = 1.2 m` 水相当)なので、
この分布は 1 つの値では原理的に両立しない。

## 最初の仮説は外れた

「湿った土は熱容量が大きい」から、年較差の誤差は湿り具合で説明できるはず —
と考えて相関を測った(湿り具合の物差しには**観測**降水量を使う。モデルの降水を
使うと降水の誤差と気温の誤差が混ざる)。

```
面積重み付き相関 r(log 降水, 年較差の誤差) = 0.113   ← ほぼ無相関
緯度帯別 r: 熱帯 +0.72 / 亜熱帯 +0.57 / 中緯度 −0.22 / 高緯度 +0.10
```

熱帯では効いているが、**誤差が最大の中緯度では逆符号**。層別すると非単調だった:

| 観測年降水量 | 年較差の誤差 |
|---|---:|
| <100mm | −2.06°C |
| 250-500mm | +2.80°C |
| 500-800mm | +3.93°C |
| 800-1200mm | +0.13°C |
| >2000mm | +1.90°C |

**年較差という要約量が粗すぎた**。年較差は「夏のズレ」と「冬のズレ」の差なので、
原因の違う 2 つの誤差が打ち消し合ったり足し合わさったりして、
どちらの話かが消えてしまう。

## 分解したら別々の欠陥が見えた

観測の最暖月・最寒月を基準に、モデルの同じ月との差を取り直した
(モデル側で最暖月を取り直すと位相のずれが混ざるので、月は観測で揃える)。

| 層 | 最暖月のズレ | 最寒月のズレ | 年較差の誤差 |
|---|---:|---:|---:|
| 砂漠(<100mm) | **−5.11°C** | +0.44°C | −2.06°C |
| 100-250mm | −1.88°C | +0.39°C | +0.46°C |
| 250-500mm | +0.93°C | +1.34°C | +2.80°C |
| 500-800mm | +1.45°C | +1.64°C | +3.93°C |
| **中緯度半乾燥(30〜60°N, 250〜800mm)** | **+5.00°C** | +0.36°C | **+7.67°C** |
| 高緯度(50〜90°N) | +2.35°C | **+5.64°C** | +2.63°C |

**砂漠と半乾燥で夏の誤差が逆符号**である。これが決め手だった。

熱容量は夏と冬を**対称に**効かせる(容量を増やせば夏は冷え冬は暖まる)。
だから「片方は夏が暑すぎ、もう片方は夏が寒すぎる」は熱容量 1 つでは作れない。
陸面の水が関わる機構が**2 つとも欠けている**、と読んだ:

1. **蒸発冷却が丸ごと無効**(`evapCoolingWm2PerMmDay: 0`)。
   水があれば夏の熱は潜熱で逃げる。その経路が存在しないので、
   半乾燥の夏が 5°C 暑すぎる。
2. **熱容量が全球一定**。乾いた砂は水の熱容量を借りられないのに 1.2 m 相当を
   与えているので、砂漠の夏のピークが鈍って 5°C 寒すぎる。

高緯度の冬 +5.64°C はこの 2 つでは説明できない(南北熱輸送か雪氷アルベド)。
別系統として切り分け、後回しにする。

## なぜ蒸発冷却が切れていたか — 履歴を読んだ

`git log -S` でたどると de25690(2026-07-30)に理由が書いてあった。
当時これを実装して**実測で悪化**(係数 12 で気温 RMSE 4.85 → 6.76、
係数 6 でもゲート −2)、「モデル自身の降水誤差が温度誤差へ増幅される
誤差の正帰還が支配的」として係数 0 で封印し、「降水場の成熟後に再訪」と
結論していた。

**その判断は当時の情報では正しい。** ただし今回分かったのは、
繋いでいた**物理量が違った**ことである:

```ts
// 当時: 降水量の陸平均偏差を蒸発冷却の代わりに使っていた
buildEvapCoolingAnomaly(ctx, priorPrecip.monthlyPrecipMm, cg, coarse)
```

蒸発冷却は潜熱フラックス λ·ET で決まる。ET は「使える水」と「使えるエネルギー」
の**両方**に頭を押さえられる量で、可能蒸発散が上限になる。一方、降水は
月 500mm もあり得る。**代用すると入力の振れ幅が桁で変わり、そのまま温度へ
増幅される**。当時の「誤差の正帰還」の正体はこれではないか、という読みに至った。

そして**モデルは既に実際の ET を計算している**(step06 の土壌バケツの
`actualEtMm`)。使うべき量が手元にあるのに代理を繋いでいた、という形である。

## 教訓

- **要約量が粗いと、原因の違う誤差が打ち消し合って消える**。年較差は
  夏と冬の差なので、そのままでは診断に使えない。分解してから見る。
- **絵にすると誤差の「構造」が見える**。数値の RMSE は大きさしか教えない。
  今回は差分図の二極性が出発点だった。
- **無効化された機能は、無効化した理由を読んでから再訪する**。
  そして「効かなかった」の記録は「その形では効かなかった」であって、
  「その物理は要らない」ではない。今回は結線ではなく**繋いだ量**が問題だった。
- 相関がゼロでも関係が無いとは限らない(非単調・層で符号が変わる)。
  層別して符号を見る。
