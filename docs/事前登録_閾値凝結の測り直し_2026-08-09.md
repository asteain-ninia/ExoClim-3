# 事前登録: 閾値凝結と鉛直輸出を、収束するソルバで測り直す(段 7)

日付: 2026-08-09
**結果を見る前に書いている。**

## なぜ測り直すのか

2026-08-04 に閾値凝結(`holdingCapacityMm`)と鉛直輸出
(`verticalExportRatePerMonth`)を試し、いずれも不成立として
[P2-1 を棄却した](実験記録_保存型水蒸気輸送_2026-08-04.md)。

だがその実験は、**今日直したのと同じ壊れた収束判定**を使っていた。
当時の記録にはこうある:

> 1451 反復で収束し、そこから上限を 2 倍・4 倍にしても**ビット一致**

これは収束の証拠にならない。判定が「1 反復あたりの変化量」だったので、
**同じ判定で同じ反復数で止まる以上、一致するのは当たり前**である。
今日の実測では、同種の配置は点ガウス=ザイデルで 40 万掃引を要した。
1451 掃引は遠く及ばない。

したがって **2026-08-04 の棄却は、収束していない解で測った可能性が高い。**
物理の棄却だったのか数値の産物だったのかを、決着させる。

## いま何が変わっているか

| | 2026-08-04 | 今日 |
|---|---|---|
| 収束判定 | 1 反復あたりの変化量 | **方程式の残差** |
| ソルバ | 擬似時間更新の点緩和 | **経度方向の線緩和**(0.2 秒/求解) |
| 源泉 | 調整した定数(E=120 など) | **バルク式の海面蒸発**(S2 で独立に検証) |

源泉が変わっているのも重い。閾値凝結は「暑い乾燥域は W_crit が大きいので
水が通過する」という機構なので、**W の絶対値が正しくないと働かない**。

## 物差し(2026-08-04 と同じものを使う)

**砂漠の年降水 / 陸平均降水の比。** 尺度に依らないので、較正していない
状態どうしでも比べられる。当時の値:

```
観測                          0.055
現行（非保存・風上追跡）        0.085
保存型・閾値なし                0.222
保存型・閾値あり(cap=30)        0.122
保存型・鉛直輸出 15〜40         0.128 〜 0.367
```

## 判定(先に固定する)

前提: **その解が収束していること**(方程式の残差が許容差以内)。
収束していない案は比較対象にしない。

- **比 ≤ 0.09 に達する案がある** → 2026-08-04 の棄却は数値の産物だった。
  閾値凝結を採用し、段 6 の較正をこの構造の上でやり直す
- **比が 0.09〜0.12** → 判断保留。非保存(0.085)に僅差で届かないが、
  水が閉じることと季節位相の改善(−5 日)と引き換えに見合うかを別途判断する
- **比 ≥ 0.12 のまま** → **2026-08-04 の棄却は正しかった**。
  2 次元の柱収支では亜熱帯を乾かせないという結論を確定させ、
  保存型を採るなら「砂漠が濡れる」ことを承知で採るか、
  鉛直 2 層へ行くかの判断に移る

## やらないと決めていること

- **判定を見てから物差しを変えること。** 比が悪ければ「年降水では負けるが
  最乾月では勝つ」のような別の指標を探しに行かない
- **閾値の係数を目的関数で較正してから比べること。** 当時も較正していない
  状態で比べており、条件を揃える。係数は物理から決めた 2〜3 点だけ振る

## 実装上やること

閾値凝結は C = rate·max(0, W − cap) で**非線形**なので、いまの線緩和
(行の三重対角分解を反復不変として使い回す)がそのままでは使えない。
現在値から枝(W > cap かどうか)を選んで半陰的に解き、**分解は掃引ごとに作る**。
分解と求解は同じ O(W) なので、1 掃引あたりの費用は 2 倍以内に収まる。
