# 事前登録: ストーム混合を拡散の場として保存型へ繋ぐ(段 36)

日付: 2026-08-15
**結果を見る前に書いている。**
設計: [設計_ストーム供給を保存型へ繋ぐ](設計_ストーム供給を保存型へ繋ぐ_2026-08-15.md)

## 問い

`stormMoistureSupply` は**保存型で完全に死んでいた**(段 6 の移行漏れ)。
中緯度の陸へ**海から水を運ぶ**機構で、
中位の陸の正味流入(49mm/年、必要 212)に直接効く位置にある。

今日 14 回測って**中位を上げられたのは偏西風だけ**で、それも
探索空間の下端に張り付いていた量だった。
**「運ぶ側」の手はほとんど試せていない。** これがその一つ。

## 変えるもの

```
D(i) = D₀ × (1 + boost × supplyW × exp(−coastKm / decayKm))
```

`STORM_DIFFUSION.boost` を **0(既定) / 1 / 2 / 4 / 8** で掃く。
`supplyW`(ストーム帯の緯度重み)と海岸減衰は、
既存の `stormSupply` の形をそのまま使う。

**源泉には一切触らない。** 拡散は保存的なので水が湧かない。

## 実装は済んでいて、既定の不変を確認済み

- 輸送ソルバの拡散係数を**スカラー or 場**の両対応にした。
- **スカラーと「全セル同値の場」がビット一致**することをテストで守った。
- **場を渡しても全球の水収支が閉じる**(残差 < 1e-6)ことをテストで守った。
- **強い拡散の帯では W が均される**(場が実際に効いている)ことも守った。
- 既定(`boost = 0`)で v3 **85.235** / 乾いた端 **64・88・468** を実測確認。

## 予測(先に書く)

**今日 14 回外しているので、外れる筋を厚めに書く。**

- **中位が湿る。** ストーム帯(中緯度)の海岸付近で混合が強まり、
  海の水が陸へ入る。**これが主判定。**
- **乾いた端も湿るおそれがある。** 拡散を上げる手なので、
  段 31 の逆(拡散を下げると端が乾いた)が起きうる。**ここが番人。**
  ただし**場所を選んで上げる**ので、全球一律だった段 31 とは違う可能性がある。
- 湿った側(熱帯)は**動かない**。ストーム帯は緯度で切られており、
  熱帯には掛からないため。
- v3 は**あまり落ちない**か、むしろ上がりうる。
  死んでいた機構を繋ぐので、較正済みの他の定数と衝突しにくい。

**外れる筋 A**: 中位が湿らない。海岸付近だけ強めても、
**内陸(中位の陸は海岸から 568km)まで届かない**。
`decayKm`(現行 1964km)が効くので届くはずだが、**確かめていない**。
**外れる筋 B**: 乾いた端が湿って番人に掛かる(拡散を上げた副作用)。
**外れる筋 C**: 拡散を場所で 9 倍にすると輸送が解きにくくなる(未収束)。

## 判定(先に固定する。結果を見てから緩めない)

1. **既定(0)で現行と一致**。v3 **85.235**、乾いた端 **64 / 88 / 468**。**確認済み。**
2. **収束**: 5 系統すべて未収束 0。満たさない水準は**適用範囲外**。
3. **水収支**: `npm run validate` の閉包が現行と同じ桁(**1e-9 級**)。
   **これを満たさなければ、他の条件を読まずに棄却する。**
   保存則を壊す変更は、成績がどうであれ採らない。
4. **主判定**: 乾いた端の **50% 分位(中位)が 468 → 500 以上**。
5. **番人(乾いた端)**: 1% 分位が **64 から増えない**。
6. **番人(湿潤側)**: コンゴ **1.01〜1.61**、アマゾン **0.82〜1.12**。
7. **番人(成績)**: 大分類が **74.49 から 1.0 以上落ちない**。
   **段 31〜34 の 2.0 ではなく 1.0 に戻す** — これは較正が端へ押した量を
   戻す話ではなく、**死んでいた機構を繋ぐ**話なので、緩める理由が無い。
8. **費用**: 1 水準 **900 秒**以内(単独換算)。

4〜8 をすべて満たす水準があれば**採用候補**とし、再較正へ進む。
