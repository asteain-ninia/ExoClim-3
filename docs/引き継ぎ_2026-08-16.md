## 1. 目的関数 v4 — ゲートの崖を外し、分布形を入れた

### 何が問題だったか

地域ゲートは「その気候帯が地域内で**過半**(大分類)または**10% 以上**(詳細)か」を
見るだけの離散判定で、50%・10% に崖がある。v23 の採用を分解すると:

```
大分類  +0.07
ゲート  +1.10   ← 崖を一つ越えた
詳細    −0.355
--------------- 小計 +0.815
実際の fitness 増 +0.784
→ **他の連続指標は約 −0.031 悪化していた**
```

**「良くなった」のではなく、崖を一つ越えたから採用された点**だった。
較正の後半で採用が「1 ゲートずつ」の階段になっていたのは、
探索が物理ではなく**崖の位置を探していた**ためと読める。

もう 1 つ、本丸である「乾いた端が作れない」(年降水の 1% 分位がモデル 64mm 対
観測 9mm)を、**目的関数がまったく測っていなかった**。
最も乾いたセルを 7 倍湿らせても成績に一切表れない状態で較正を回していた。

### どう直したか

```
v4 = 大分類% + 0.25×詳細%
   + 1.1 × Σ_地域 share          ← 面積割合(0〜1)。上限 17 は同じなので重みは据え置き
   − 3 × precipQuantileLogErr    ← 年降水の分位 8 点の平均対数誤差(新規)
   − v3 と同じ連続誤差項
```

- 合否 `pass` は**セル数の旧定義のまま凍結**し、報告にのみ残す
  (過去の全実験記録の「ゲート n/17」と比べられなくする害のほうが大きい)。
- **版をまたいで比べるときは `continuousV3`**(ゲート項を除いた連続部分)を使う。
  fitness の絶対値は版で意味が違う。

事前登録: `docs/事前登録_目的関数v4_ゲートの崖を外し分布形を入れる_2026-08-16.md`

### 予測を 2 つとも外した

| 予測 | 実際 |
| --- | --- |
| ゲート被覆の和は 6〜9 | **11.99**(合格地域の 7 つが 98% 以上だった) |
| 分位の平均対数誤差は 0.4〜0.9 | **0.33**(ε の設計ミス。下記) |

**ε の設計ミス**: 事前登録で ε=10mm としたとき「砂漠の年降水より十分小さい」と
書いたが、**観測の 1% 分位は 9mm/年**で ε のほうが大きかった。
7.1 倍のずれが 3.9 倍に圧縮され、**新しく入れた項が測りたい対象を潰していた**。
同日 ε=1mm へ訂正(重み 3 は据え置き)。訂正の根拠は結果に依存しない事実
(観測の 1% 分位 = 9mm)に置き、経緯を実験記録に明記した。

### 測って初めて見えたこと — **分布は両端が潰れている**

```
分位    モデル/観測
 1%       7.11   ← 乾いた端が過剰
 5%       2.04
50%       0.89   ← 中位が不足
99%       0.89   ← **湿った端も不足**
```

「乾いた端が作れない」と「中位が乾いている」を別々の問題として扱っていたが、
**一つの現象の両側**の可能性が高い。拡散は勾配を均す演算子なので、
強すぎればちょうどこの形になる。監査が指摘した
「較正が渦拡散を単調に上げて上限に張り付かせた」と整合する。

→ 事前登録済み: `docs/事前登録_渦拡散が分布の両端を潰しているか_2026-08-16.md`
   掃引スクリプト `scripts/sweep_eddy_diffusivity.ts` は用意済み。**v24 の終了後に走らせる。**

## 3. 死んだ探索定数 — 判定を直しても同じ 4 件

初版の診断は降水の合計と最大値を**小数 6 桁に丸めた文字列**で比べていた
(監査の指摘)。全セル全月の最大絶対差へ直して測り直したが、**候補は同じ 4 件**だった。

```
stormMinQRel / stormMoistureSupply / stormMoistureDecayKm  … 保存型で経路が切れている
warmHumidSupplyNorm                                        … 親(warmHumidConvectiveBoost)が 0
```

丸めの緩さで拾われた偽陽性ではなく、**本当に 1 ビットも動いていない**。
監査が「SPACE がストーム 3 定数を探索しているのに配線が切れている」と
指摘したのは正しい。

**v24 の終了後に探索空間から外す。**

## 4. 理想化大陸(要件 §6-2)— **一度も実装されていなかった**

`validate.ts` に「§6-2 は別ハーネスで判定する」と書かれたまま、

作って測ると:

```
内陸乾燥帯  内陸の B 群 79.0%     ○ 出ている
地中海性帯  西岸の Cs*   9.8%     △
西岸海洋性  西岸の Cfb   7.8%     ✗
```

- **内陸乾燥が地球の海岸線なしで出た**のは、「海から遠いと乾く」が物理から

- **東岸湿潤の欠落は、地球の「中位の陸に水が来ない」と同じ形**である。
  2 つの独立な入力で同じ症状が出たので、この弱点は地形の再現の問題ではなく
  **風の場の定式化**(月平均・帯状一様で経度依存の子午面流を作れない)に由来する。

## 5. 惑星応答に「向きだけは物理で決まる 3 点」を足した

`exp_planet_response.ts` は「観測が無いので正解も無い」として判定を置いていない。
だが向きだけなら物理で決まる量がある:

```
傾斜 ↑ → 陸の気温年較差 ↑
自転 ↓ → 乾燥帯の中心緯度 ↑   (ハドレー循環が広がる = Held-Hou)
気圧 ↑ → 赤道と極の気温差 ↓
```

列として出すようにした。**判定はまだ置かない** — まず測る。
持っていない向きがあれば「地球に合わせ込んだ結果、応答が死んだ」証拠になる
(たとえば風帯が緯度で決め打ちなら、自転を変えても乾燥帯は動かない)。

## この日の教訓(`docs/教訓.md` §9 に追記済み)

- **正則化の ε は、測りたい対象のスケールを測ってから決める。**
  「十分小さい」は感覚で書いてよい言葉ではない。
- **離散の合否は、探索を「崖越え」に費やさせる。**
  合否で測る量を目的関数に入れるときは、崖があるかを必ず確かめる。
- **測っていない量は、どれだけ外れていても直らない。**
  弱点が分かったら、まず目的関数に入れる。指標を足すと症状の地図が変わる。
- **`vitest run` の並列度を絞らないと、同時に走らせた計算が全部止まる。**
- **「別ハーネスで判定する」と書いたら、その場所を作るまでが 1 つの作業。**
