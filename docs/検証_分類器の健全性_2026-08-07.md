# 検証: ケッペン分類器は正しい —「夏乾燥型が多すぎる」は降水不足の症状

日付: 2026-08-07
道具: `scripts/diag_classifier_sanity.ts`(GPU もモデルも使わない。費用ゼロ)
発端: `お手紙_ファイル図鑑屋より_2026-08-02.md` §2 が伝えた外部 AI の差分診断メモ

## 何が指摘されていたか

> 最優先で疑うべきなのは、物理パラメータを調整する前の、**ケッペン分類器における
> 夏冬判定・南北半球反転・月インデックス・s/w 判定**です。

根拠として挙がっていた症状:

- 日本・朝鮮半島で、本来の夏雨型 `w` が消えて夏乾燥型 `s` が出ている
  (観測 Cfa/Dwa/Dwb → モデル Csa/Csb/Dsa/Dfa)
- 東欧〜ロシア西部でも観測 Dfb → モデル Dsb と `f` が `s` に化けている

**もし当たっていれば、物理を一切変えないまま記号が入れ替わる**性質の指摘だった。

## 検証の方法

**観測の月別気温・降水をそのまま分類器へ通す。** モデルを介さないので、
分類器そのものの正しさだけを見られる。

1. 素通し … 観測どおりなら観測の記号が出るはず。出なければ分類器の不具合。
2. 降水だけ一様に縮める … R3 で測った「湿潤温帯の降水はモデルで観測の 21%」を
   観測データへ人工的に適用する。ここで `s` へ化けるなら降水不足の症状と確定する。

## 結果

```
地点            Beck の記号   素通し   降水 50%   降水 21%   (夏最少/冬最多 mm)
東京あたり          Cfa          Dfa      Dfa        Dfa        (142 / 215)
ソウルあたり         Dwa          Dwa      Dwa        BSk        ( 76 /  52)
上海あたり          Cfa          Cfa      BSk        BWk        ( 83 /  72)
モスクワあたり        Dfb          Dfb      Dfb        BSk        ( 35 /  62)
ワルシャワあたり       Dfb          Dfb      Dfb        BWk        ( 36 /  52)
アトランタあたり       Cfa          Cfa      Cfa        BSk        ( 93 / 149)
```

### 分類器そのものは正しい

**6 地点中 5 地点で Beck と完全一致**した。残る東京の `Cfa → Dfa` は、
気候値が 2°・Beck が 1° という**格子の差**である(2° セルは内陸を含み、
最寒月が 0°C を割って C から D へ移る)。分類器の判定ロジックの誤りではない。

閾値もコードを読んで確かめた。`s` は「夏の最少月 < 40mm かつ 冬の最多月/3 未満」、
`w` は「冬の最少月 < 夏の最多月/10」で、Peel et al. 2007 / Beck et al. 2023 と一致する。
南北半球の反転(`isNorth` を緯度から毎行判定)も、夏半年の月集合も正しい。

### 一様な降水不足は `s` ではなく `B` を作る

降水を 21% に縮めると、行き先は **BSk / BWk(乾燥帯)**であって `s` ではない。
これは R3 の測定([実験記録_温帯の乾燥化](実験記録_温帯の乾燥化_2026-08-07.md))
「観測 C の 38.8% が B 乾燥へ落ちる」と完全に一致する。

## 結論 — 原因は降水の**季節配分**

外部メモの観察(夏乾燥型が多すぎる)は本物だが、原因は分類器ではない。
一様な不足は `B` を作るので、`s` を作るには**夏の降水が選択的に足りない**必要がある。
そして R3 はまさにそれを測っていた:

```
しきい値の底上げ項      観測    モデル
  夏型(+28)             108      67     ← 41 セルが夏型から落ちた
  平均型(+14)            62     107
  冬型(+0)               11       7
```

**モンスーン型の季節集中が弱く、配分が平坦になっている。**

## これで 3 つの症状が 1 つの原因へ収束した

| 症状 | 出所 |
|---|---|
| C 温帯の大分類一致 46.8%(観測 C の 38.8% が B へ) | R3 の診断 |
| 日本・朝鮮・東欧で `f`/`w` が `s` に化ける | 外部 AI の差分診断メモ |
| 地域ゲート `east_asia_humid` 不通過(中国東部の年降水 340mm) | 2026-07-31 に凍結したゲート |

いずれも **「湿潤温帯へ夏の水が届いていない」**の別の顔である。
→ **R5 を次の標的とする**([ロードマップ](ロードマップ_2026-08-07.md))。

## 副産物: 月の原点が 11 日ずれている

モデルの月 0 は**北半球冬至起点**(`src/domain/insolation.ts`)、観測フィクスチャは暦月。
`scripts/scoring.ts` はこの差(約 11 日 = 0.355 か月)を認識しており、
**位相を比べるときだけ補正**している。1 月・7 月の RMSE は季節の極値付近なので
影響は小さいが、春秋の月では 3°C 程度の系統差になり得る。

物差しの側の欠陥なので、**地球検証のときだけモデルの軌道月を暦月へ再標本化する**案を
候補として残す(モデル本体は惑星一般のまま — 他の惑星に「1 月」は無い)。

## 教訓

- **外部からの指摘は、当たっていなくても検証する価値がある。** 今回は費用ゼロの
  検査で「分類器は正しい」と確定でき、**同じ症状の原因が既知の 1 つへ収束**した。
  指摘が外れていたことより、収束したことのほうが価値が大きい。
- **層を分けて検査する。** 「観測をそのまま分類器へ通す」ようにモデルを介さない
  検査を作れば、物理と分類器のどちらの問題かが一発で分かる。
  パイプラインの途中に**観測を差し込める口**を持っておくと安い検査ができる。
