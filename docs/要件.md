# 要件 — ExoClim-3

> ExoClim-2 要件定義書から蒸留した第 3 世代の要件。粒度は「何を満たすべきか」。
> 実現手段は [方針.md](方針.md)、各ステップの物理仕様は [spec/](spec/) に置く。

## 1. 目的と利用者

- Worldbuilding Pasta の惑星気候設計手順を、対話的に追跡できる形で実装する。
- 利用者: 架空世界の気候を設計する創作者・ワールドビルディング愛好家・教育用途。
- 利用形態: 単一利用者が手元の端末で、惑星パラメータを試行錯誤しながら
  気候区分図を得る。ネットワーク接続なしで完全動作すること。
- 対象範囲: 入力パラメータ → 気候区分図の導出と中間結果の可視化・比較。
  実時間の天候予測、主星や地質の進化、複数惑星系の同時模擬は対象外。

## 2. 入力パラメータ(利用者が UI から触れるもの)

1. **主星・軌道**: 主星光度、軌道長半径(または放射照度)、軌道離心率、
   近日点引数(季節の非対称性)。公転周期は派生量として表示する。
2. **惑星本体**: 半径、自転周期、地軸傾斜、自転方向(順行/逆行)。
3. **大気・海洋**: 表面気圧、温室効果強度、雲アルベド、海洋混合層深さ、
   熱輸送強度。
4. **地形**: プリセット選択(実在地球・理想化大陸群・全海・全陸)、
   手続き生成(乱数種子 + 制御パラメータ)。カスタム取込は将来拡張。

利用者パラメータは全て UI に露出する。モデル較正定数はここに含めない
([方針.md §3](方針.md))。

## 3. シミュレーション(7 段階パイプライン)

各段階の入出力契約と物理仕様は [spec/](spec/) に集約する。

| Step | 出力の骨子 |
| --- | --- |
| 1 ITCZ | 月別中心線と影響帯 |
| 2 風帯 | 月別卓越風・循環セル境界・気圧場・モンスーン域 |
| 3 海流 | 暖流/寒流分類・海面温度補正・海氷・流線(表示用) |
| 4 気流 | 月別地表風ベクトル場・高低気圧中心 |
| 5 気温 | 月別地表気温(°C)・季節極値・雪氷被覆 |
| 6 降水 | 月別降水量(mm)・要因別内訳(収束・地形性・前線・沈降) |
| 7 気候区分 | セル別ケッペン記号(第 3 文字まで)と判定根拠 |

- 決定性: 同一入力(乱数種子含む)→ 常に同一出力。計算層は純粋関数。
- 部分再計算: 変更が影響する段階以降のみ再計算する。
- 極端条件(傾斜 0〜90°、高離心率、逆行、全海/全陸)で破綻しない。

## 4. 表示・操作

- 円筒投影のマップに各段階の結果を重ね合わせ表示。経度方向は循環パン可能。
- 段階別オーバーレイの表示切替と凡例。月(1〜12 月)+ 年平均の切替。
- セル検査: ホバー/クリックで当該セルの緯度経度・標高・月別気温/降水・
  判定根拠を表示。
- パラメータ調整 UI(折りたたみ区分け)。変更で自動再計算(処理中表示つき)。
- 設定の保存/読込(JSON、全項目の型 + 値域検証つき)と localStorage 自動保存。
- マップの PNG 書き出し。
- UI 文言は日本語。

## 5. 性能

- 既定解像度: 表示格子 1°(180×360)。パラメータ変更から気候区分図更新まで
  数秒以内を目標(Worker 上で実行、UI は固まらない)。
- 気温モデルは粗格子で解いて降尺度してよい(決定性は維持)。

## 6. 検証(受け入れ基準)

1. **実在地球の再現**(最重要・自動採点):
   実在海岸線の地球プリセットで、
   - ケッペン主要区分(A/B/C/D/E)の陸面積比が実測(Peel et al. 2007)の
     ±10 ポイント以内。
   - 代表 20 地点前後(アマゾン・サハラ・地中海・西欧・シベリア・
     チベット・モンスーンアジア・パタゴニア等の格子セル)の主要区分一致率
     70% 以上(目標。閾値は較正の進みに応じて引き上げる)。
   - 帯状平均気温(年平均・1 月・7 月)が実測 ±5°C 程度。
2. **理想化大陸**: 西岸海洋性の楔・地中海性帯・内陸乾燥帯・東岸湿潤の
   出現を自動判定。
3. **退化条件**: 全海・全陸・傾斜 0°・逆行で NaN を出さず定性的に妥当。
4. 検証はヘッドレスハーネス(`npm run validate`)で常時実行可能とし、
   PNG と採点 JSON を出力する。
