# 事前登録: 保存則への移行 — **源泉を検証してから接続する**

日付: 2026-08-09
発端: 外部レビュー 2 件(Fable / Codex `gpt-5.6-sol`、いずれも開発の経緯を見せずに実施)
**この文書は実装・測定の前に書いて確定させる。** 後から条件を緩めない。

## 2 つのレビューが独立に同じ結論へ収束した

経緯(何を試して何を棄却したか)を一切見せずに、別々のモデルへ同じ依頼を出した。

| | Fable | Codex |
|---|---|---|
| 1 | 保存型水蒸気輸送の接続 | **水蒸気保存** |
| 2 | 温度場 → 気圧場の帰還 | **循環の質量連続** |
| 3 | EBM 移流結合の保存化 | **熱輸送保存** |

**3 つとも「保存則が無い」という同じ病名**である。乗数を足し引きする路線を
止めるべき、という点で一致した。

## 利用者からの警告(2026-08-09)— これを設計の主軸にする

> 保存ということは、**もとの量を見誤れば誤差が非常に大きくなる**ことが予想されます。

これは正しい。非保存の乗数方式では、あるセルの誤差はそのセルに留まる。
保存則を入れると**誤差が下流へ運ばれる**ので、局所誤差が非局所誤差に変わる。

そして現状は、その急所がまさに未検証である:

```
供給 q     = 風上経路の到達可能性     ← 蒸発量ではない
海面蒸発 E                          ← **存在しない**
海面水温 SST                        ← **採点されていない**（両レビューが指摘）
```

`moisture_transport.ts` が要求する入力は `S_i = 海面蒸発 + 陸面蒸発散` である。
陸面蒸発散は土壌バケツが持っているが、**海面蒸発はモデルに存在しない**。
保存型が繋がらなかった本当の理由はここにある。

**したがって順序を固定する: 源泉を作り、源泉だけで検証を通してから、輸送を繋ぐ。**

## 段取り(この順序を変えない)

### S1. 源泉の実装 — 海面蒸発 E

バルク式で作る。惑星一般で、地理を参照しない:

```
E = ρ_a · C_E · |V| · q_s(T_surf) · (1 − RH)      [kg/m²/s] → mm/月
```

- `q_s(T)` は飽和比湿(Tetens 式 + 気圧)。**気圧に依存する**ので他の惑星でも意味を持つ
- `|V|` は Step 4 の地表風
- `RH` は海上の近地表相対湿度(定数。地球で 0.8 前後)
- 陸は既存の土壌バケツの実蒸発散をそのまま使う(既に PET で頭を押さえてある)

### S2. 源泉の検証 — **ここが関門**

**S2 を通らなければ S3 へ進まない。** 事前に条件を固定する:

| 判定 | 条件 | 根拠 |
|---|---|---|
| **主判定** | 全球平均の E が **900〜1100 mm/年** | 実地球の全球平均蒸発 ≒ 全球平均降水 ≒ 1000mm/年 |
| 副判定 1 | 海の平均 E が陸の平均 E の **1.5〜3 倍** | 実地球は海 ≒1150 / 陸 ≒500mm/年 |
| 副判定 2 | E の緯度分布が**亜熱帯で最大**になる(赤道ではない) | 実地球の蒸発は亜熱帯高圧帯で最大。ここを外すと循環の駆動が逆になる |
| 副判定 3 | 現行の降水(陸平均 742mm/年)と**桁が合う** | 源泉が降水より小さければ保存則は成立しない |

**棄却条件**: 主判定を外し、かつ `C_E` と `RH` を物理的に妥当な範囲
(C_E 1.0〜1.5e-3、RH 0.75〜0.85)で動かしても入らないなら、
**バルク式では源泉を作れない**と結論して S3 を中止する。

### S3. 輸送の接続 — **置換であって追加ではない**

Fable の指摘:

> 乗算因子を残したまま接続すると二重計上になるので、**置換として設計すること**

2026-08-04 の P2-1 棄却は、**乗数を残したまま保存型を足していた**。
当時の記録が「保存則の中では抑制の乗数は水を消さず位置を変えるだけ」と
書いているのは、まさに二重計上を観測していたことになる。
**私たちは間違った試し方で棄却した可能性がある。**

置換の対象(「水が保存しないことの補償」だった乗数):

```
orographicDepletionM        風上山脈による水蒸気の枯渇
upwindBlockReliefM / Floor  同・広域の遮蔽
eastCoastSubsidenceRelief   東岸で沈降を緩める
moistureDecay*Km            距離減衰（→ 凝結の時定数へ写す）
```

保存則の中では、これらは**凝結率 G の係数**として意味を持ち直すか、
不要になる。どちらかを機構ごとに決める。

### S4. 採点の穴を埋める(S3 と並行してよい)

両レビューが挙げた未計測量のうち、**保存則の検証に必須のもの**を先に入れる:

- 全球・月別の **E − P − ΔW の閉包**(保存しているかの検査。「解けたか」とは別)
- 降水の**季節位相**(最多月・最少月の「時期」。現状は値のみ)
- 地域ゲートの**降水と気温への分解**
  (パタゴニアの ET 49% は雨陰ではなく**気温の失敗**だと Codex が指摘)

## 予測(事前に書く)

- S2 は**通ると思う**。バルク式は物理的に素直で、地球の全球平均 1000mm/年 は
  C_E ≈ 1.2e-3 / RH ≈ 0.8 で自然に出る桁である。
- ただし**緯度分布(副判定 2)が怪しい**。現行の風速場は帯状テンプレート由来なので、
  亜熱帯の貿易風が実物より弱ければ蒸発の最大が赤道へ寄る。
  ここで落ちたら、それは**風の場の検証が無いこと**(両レビューの指摘)の
  最初の実害になる。
- S3 は**一時的に成績を落とす**。乗数を外すので、較正のやり直しが要る。
  v3 が 5 ポイント落ちても、保存が閉じていて源泉が正しいなら進む。
  **ここで成績を理由に引き返さない**ことを、いま宣言しておく。

## この事前登録が守るもの

利用者の警告は「保存則は誤差を増幅する」だった。**だから源泉に独立の関門を置く。**
源泉が検証を通らないまま輸送を繋げば、増幅された誤差を成績で追いかけることになり、
それは前世代(ExoClim-2)が停止した構造そのものである。
