# 事前登録: 目的関数 v4 — ゲートの崖を外し、降水の分布形を入れる

> **これは凍結目的関数(2026-07-31)の改訂である。**

## なぜ変えるか

外部監査(Codex)が 2 点を指摘し、どちらも記録を辿って裏が取れた。

### (1) 地域ゲートは離散的な崖であり、崖越えだけの解が採用されている

実装上、ゲートは「モデルのケッペン分類が地域内で**過半**(大分類)または
**10% 以上**(詳細)か」を見るだけである。つまり全球の大分類・詳細一致率と
**同じ結果変数を地域ごとに二重計上**していて、しかも 50%・10% に崖がある。

v23 の採用を分解すると:

```
大分類  +0.07
ゲート  +1.10   ← 崖を一つ越えた
詳細    −0.355
--------------- 小計 +0.815
実際の fitness 増  +0.784
→ **他の連続指標は約 −0.031 悪化している**
```

**「良くなった」のではなく、崖を一つ越えたから採用された点**である。
較正の後半で採用が「1 ゲートずつ」の階段になっていたのは、
探索が物理ではなく**崖の位置を探していた**ためと読める。

### (2) 本丸の「乾いた端が作れない」が目的関数に入っていない

2026-08-15 に測って、モデルの弱点は**分布の形**だと分かった
(年降水の 1% 分位がモデル 64mm 対 観測 9mm、面積重み・南極抜き)。
ところが目的関数は RMSE と平均しか見ていない。
**最も乾いたセルを 7 倍湿らせていても、成績には表れない。**
測っていないものは直らない。

## どう変えるか(式を固定する)

### 変更 1: ゲート項を連続化する

```
旧: 1.1 × (合格したゲートの件数)              0〜17 の整数、崖あり
新: 1.1 × Σ_地域 share                        0〜17 の実数、崖なし
```

`share` = **期待する気候帯がその地域の陸面積に占める割合**(面積重み、0〜1)。

- 上限は 17 のままなので、**項の最大値は 18.7 で現行と変わらない**。
  重み 1.1 は据え置く(スケールを合わせるための調整をしない)。
- 合否 `pass` は**セル数の旧定義のまま凍結**し、報告にのみ残す。
  面積重みへ直すと過去の全実験記録の「ゲート n/17」と比べられなくなる。
- 面積重みを使う理由: 地域は南北に広いものがあり、セル数では高緯度が過大になる。

### 変更 2: 降水の分布形の項を足す

```
− 3 × precipQuantileLogErr

precipQuantileLogErr = mean over q ∈ {1,5,10,25,50,75,90,99}%
                         of |log((Pm(q) + 10) / (Po(q) + 10))|
```

- 面積重み、**南極(60S 以南)を除く**。観測もモデルも一律 EF で成績に出ないのに
  セル数の 28.3% を占め、分位を買い占めるため。
- 対数なので「乾いた端で 7 倍」と「湿った端で 7 倍」が同じ重みになる。
- `+10mm` は 0 割り回避。砂漠の年降水(数十 mm)より十分小さい。
- 重み 3 は `wPrecipAnnual`(年降水 RMSE)と同じ。
  **現状値を測る前に決める**(結果を見て都合よく調整する余地を残さない)。

### 変えないもの

大分類・詳細の一致率、気温 4 項、降水 3 項、陸平均、ITCZ、
数値的健全性による失格 — すべて v3 のまま。v2・v3 も併記して計算し続ける。

## 判定条件(**結果を見る前に固定する**)

v4 で再較正した解を v23(現行最良)と比べ、**次を全部満たしたら採用**する。

| # | 条件 | なぜ |
| --- | --- | --- |
| 1 | `precipQuantileLogErr` が **v23 より小さい** | 新項が実際に効いたか。効かないなら足した意味がない |
| 2 | 大分類の一致率が **v23 − 1.0 ポイント以内** | ケッペンが主目的である点は変えていない |
| 3 | 詳細の一致率が **v23 − 2.0 ポイント以内** | 同上 |
| 4 | `fitnessV3`(旧目的関数)の**連続部分**が v23 より悪化していない | 崖を外した結果、実質の物理が退化していないか |
| 5 | 数値的健全性に合格 | 既存の失格条件 |

条件 4 の「連続部分」= `fitnessV3 − 1.1×(ゲート件数)`。
ゲート項を除いた残りで比べる。**ゲート件数は減ってもよい**
(崖を外したのだから減りうる。それを咎めると変更の意味がない)。

**棄却したときにやること**: 条件を緩めない。v4 を撤回して v3 に戻し、
なぜ効かなかったかを実験記録に書く。

## 事前の予測(外したら記録する)

1. ゲート項の値は **下がる**。現行 12/17 合格に対し、share の和は 6〜9 程度と読む
   (合格地域でも share は 0.5〜0.9、不合格地域は 0〜0.4 のはず)。
   fitness の絶対値が下がるが、これは尺度が変わっただけで退化ではない。
2. `precipQuantileLogErr` の現状値は **0.4〜0.9**。1% 分位の log(64/9)=1.96 が
   1 点、他が 0.1〜0.3 程度と見て、8 点の平均。
   → 項の寄与は 3×0.6 ≈ 1.8 で、気温平均項(4×1.0 前後)よりやや軽い。
3. 再較正は**乾いた端を削る向き**に動く。その結果、中位の陸がさらに乾く恐れがある
   (2026-08-15 に 8 回踏んだ壁)。**条件 2・3 がその歯止めになる。**
