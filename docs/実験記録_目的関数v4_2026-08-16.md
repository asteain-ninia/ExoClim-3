# 実験記録: 目的関数 v4 の現状値 — 予測を 2 つとも外し、**降水の分布は両端が潰れていた**

日付: 2026-08-16
事前登録: [事前登録_目的関数v4](事前登録_目的関数v4_ゲートの崖を外し分布形を入れる_2026-08-16.md)
測定: 現行最良解(v23、`out/validate/report.json`)を新しい指標で採点

## 予測の答え合わせ — **2 つとも外した**

| # | 予測 | 実際 | 判定 |
| --- | --- | --- | --- |
| 1 | ゲート被覆の和は 6〜9 | **11.99** | ✗ 外した |
| 2 | 分位の平均対数誤差は 0.4〜0.9 | **0.33**(ε=10 のとき) | ✗ 外した |

### 予測 1 の外し方 — 地域の分類はほぼ一様だった

「合格地域でも被覆は 0.5〜0.9」と読んだが、実際は合格 13 地域のうち
**7 地域が 98% 以上**(サハラ・豪州内陸・アマゾン・コンゴ・欧露・西シベリア・
東シベリア・南極)だった。大陸規模の地域では気候帯がほぼ一様になる。

離散から連続へ移しても値がほとんど落ちない、ということは、
**合格している地域では崖の影響がもともと小さかった**ことを意味する。
崖が効いていたのは境界近くの地域だけである:

```
mediterranean_cs_present   被覆 27.1%  ← 合格(10% 以上でよい)だが実態は 1/4
california_cs_present      被覆 74.7%
tibet_cold_highland        被覆 65.4%
arabia_arid                被覆 78.7%
```

**地中海が 27% で「合格」扱いだったのは、判定が甘い側の崖の上にいたから**である。
連続版ではこの地域を伸ばす余地が正しく報われる。

一方、不合格 4 地域の内訳が処方を分ける:

```
india_tropical         26.6%   あと一歩(過半まで倍)
us_southeast_humid     38.5%   あと一歩
east_asia_humid         6.4%   遠い
patagonia_rainshadow    0.0%   **まったく無い**
```

利用者の見立て(「南中華とかアラブ・アメリカあたりが改善したらゲートが埋まる」)は
**米南東部 38.5% とインド 26.6% については当たっている**。
中国東部は 6.4% でまだ遠い。パタゴニアは 0% で、別の原因がある
(既知: 雨陰ではなく**寒すぎて ET になる**)。

### 予測 2 の外し方 — **ε の設計を誤っていた**

事前登録で `ε = 10mm` としたとき、「砂漠の年降水(数十 mm)より十分小さい」と書いた。
**これが誤りだった。** 実測すると:

```
観測の 1% 分位 = 9mm/年
```

**ε のほうが大きい。** そのため乾いた端の 7.1 倍(64 対 9)のずれが
3.9 倍((64+10)/(9+10))に圧縮され、**測りたい対象そのものを潰していた**。

ε は 0 割り回避のための数値上の配慮であって、評価の強さを決める量ではない。
同日中に **ε = 1mm** へ直した。重み 3 は事前登録のまま据え置く。

直した値(分位の値は変わらないので手計算で出る):

```
分位   モデル  観測   |log 比| (ε=1)
 1%      64      9    1.872   ← 全体の 58% をここが占める
 5%     100     49    0.703
10%     145    119    0.196
25%     274    298    0.084
50%     532    596    0.113
75%    1075   1186    0.098
90%    2001   1905    0.049
99%    3015   3393    0.118
                      -----
              平均    0.404   ← 事前予測 0.4〜0.9 の下端に入る
```

**訂正の扱いについて**: 事前登録の規定は「判定条件を後から緩めない」である。
これは判定条件ではなく式そのものの誤りなので直したが、
**直したこと自体を隠さずここに書く**。ε を変えれば項の大きさは変わるので、
「効かなかったから強くした」との区別がつかなくなるのを避けるため、
**根拠は「観測の 1% 分位より ε が大きい」という結果に依存しない事実に置く**。

## 測って初めて見えたこと — **分布は両端が潰れている**

分位の比を並べると、これまで見えていなかった形が出る:

```
分位    モデル/観測
 1%       7.11   ← 大幅に過剰(乾いた端が作れない。既知)
 5%       2.04   ← 過剰
10%       1.22
25%       0.92
50%       0.89   ← 不足(中位が乾いている。既知)
75%       0.91
90%       1.05
99%       0.89   ← **不足(最も湿った端も足りない)**
```

**乾いた端が過剰で、湿った端が不足している。**
つまり分布全体が中央へ圧縮されている。これまでは
「乾いた端が作れない」「中位が乾いている」を別々の問題として扱っていたが、
**一つの現象の両側**である可能性が高い。

過度な平滑化(拡散が強すぎる)なら、まさにこの形になる。
外部監査が「渦拡散係数が較正で単調に上昇し、上限に張り付いた」と指摘した
時系列と整合する。**独立な 2 つの証拠が同じ向きを指している。**

> ただしこれは相関であって因果ではない。2026-08-15 に
> 「数字の一致を因果と読む」失敗を 2 回踏んでいる。
> 拡散を弱めれば分布が広がるかは**測って確かめる**。
> v4 での再較正が、まさにその実験になる(分布形が目的関数に入ったので、
> 較正は拡散を弱める向きを自分で試せるようになった)。

## この測定で確定したこと

1. **ゲートの連続化は、離散の崖が実際に効いていた地域を正しく可視化した**
   (地中海 27% で「合格」)。値の総和は 13 → 11.99 でほぼ変わらない。
2. **降水の分布形は、これまで目的関数がまったく見ていなかった量である。**
   1% 分位が 7 倍ずれていても成績に一切表れなかった。
3. **分布は両端が潰れている。** 乾いた端の過剰と湿った端の不足が同時に起きている。
