## 段取り

### R1 — 蒸発冷却の陰的化 → **棄却**(2026-08-07)

[実験記録](実験記録_蒸発帰還_2026-08-07.md)。線形化の基準点がパス 1 で、
そのパス 1 は陸面結合を持たずに呼ばれていたため、
**パス 2 の答えをパス 1 へ引き戻す**だけの項になっていた。

### R1b — 陸の対流・前線雲 → **採用**(2026-08-08)

[事前登録](事前登録_陸の対流雲_2026-08-07.md)。雲アルベドの変調で
ストームトラック雲・層積雲・海峡雲がすべて `oceanFrac` 倍で入っており、
**陸の雲は ITCZ 近傍しか増えない**という構造的な欠落を埋める。
前パスの降水を飽和させて雲に足す。

棄却した場合の次善策(事前登録に明記済み): `stormTrackCloudBoost * oceanFrac` の
`oceanFrac` を外し、既に書かれているのに死んでいる陸用の分岐を生かす。

### R2 — 0 層海氷の第 2 版 → **採用**(2026-08-08)

[事前登録](事前登録_海氷アルベド_2026-08-07.md)。第 1 版(2026-08-04)には
**評価以前の不具合が 2 件**あった:

1. 陸の季節雪アルベドが丸ごと消える(氷厚は海セルにしか育たないのに
   `iceW` を氷厚の有無だけで決めていた)
2. GPU 経路に 0 層模型が無く、加速器があると黙って無効化されていた

これを直したうえで、アルベド・断熱を氷量に連続で結び、融解中は表面を
凍結点に留める。**帯状平均気温の乖離 26.4°C はここでしか解けない。**

### R3 — C 温帯が乾燥に食われる件 → **診断完了**(2026-08-07)

大分類で唯一 5 割割れ。混同行列で C→B が 5.4%、逆向き(B→C)は 1.9% なので
**系統的に乾かしすぎている**。B 判定は 1 本の不等式なので、
降水が足りないのか気温でしきい値が上がっているのかを分けられる。
`scripts/diag_temperate.ts` で仮想実験(量を 1 つずつ観測に差し替える)を行う。

**R1b の後に診断する。** 冷帯の夏が下がれば乾燥のしきい値
(気温の関数)も動くので、先に診断すると前提が変わる。

## 順序の理由

R1b を先にするのは、診断が終わっていて実装が小さく、他を壊すリスクが
構造的に低いため(降水がほぼ 0 の砂漠には効かない)。
R2 は受入ゲートに必須だが一度設計に失敗しており手数が読めない。
R3 は R1b の結果で前提が動く。

## 保留にした候補(理由つき)

- **外側の反復を 3 パス以上にする**。パス 1 が陸面結合を持たないことが
  R1 の失敗の直接原因だった。パスを増やせば基準点が最終解に近づくが、
  費用の 97.9% が EBM の時間積分なので **1 パス増える = 全体が 1.5 倍**になる。
  R1b・R2 で足りなければ検討する。
- **陸のストームトラック雲**(R1b の次善策)。幾何だけで決まり水の量を見ないので、
  大陸内部の夏の対流雲を表現できない。R1b が棄却されたときの二番手。
