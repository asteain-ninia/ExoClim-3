# 道具: 自走モニタ(2026-08-24 起票)

**利用者指示(2026-08-24)**:

> 今このプロジェクト配下の自動実行が動いているか・どのくらい進んでいるか・
> どういう状況なのかを一目で確認できる GUI を作る。パラメーター各種と、
> 各種評価値は裁定でも必要。修正のたびに対応させる必要が可能な限り少なく
> なるように。AI を消費しない機械的動作を行う。このプロジェクトの AI が
> 現状を Monitor しているか≒作業の進行時に自動で次の行動ができる状態に
> なっているかも判別したい。時間のかかる計算を開始したあと、その結果を
> 待つふりをして待っていないことが多々あるので。

## 使い方

```bash
npm run monitor      # http://127.0.0.1:7420 が開く(端末を占有する)
```

端末を閉じても残したいとき(常駐・二重起動しない):

```powershell
powershell -ExecutionPolicy Bypass -File scripts\monitor.ps1
```

- 依存ゼロ(node の標準モジュールのみ)。**AI は一切関与しない。**
- 5 秒ごとに自動更新。ブラウザのタブ名が状態を表す(`● 計算中 …` / `■ 投げっぱなし …`)。
- ブラウザを開きたくない: `EXOCLIM_MONITOR_OPEN=0 npm run monitor`
- 港を変える: `EXOCLIM_MONITOR_PORT=7500 npm run monitor`
- 実装: [scripts/monitor_server.mjs](../scripts/monitor_server.mjs)(収集と判定)、
  [scripts/monitor_ui.html](../scripts/monitor_ui.html)(表示)、
  [scripts/monitor.ps1](../scripts/monitor.ps1)(常駐起動)。
  判定の要は [tests/unit/scripts/monitor_judge.test.ts](../tests/unit/scripts/monitor_judge.test.ts) で固定。

## 「AI が監視しているか」の判定(この道具の中核)

自走の生死は**口先では判定できない**。「待っています」と書いたセッションが
実は end_turn していた、というのが前任 2 名の死因([教訓 §11](教訓.md))。
だから根拠を 1 つに絞った:

> **`run_in_background` で投げたジョブは、完了時に AI が必ず呼び戻される。
> そのとき `tasks/<id>.output` という札が、ジョブ起動の瞬間に作られる。**

札はジョブ起動時に生まれ、出力が届くたびに更新される。出力を `out/*.log` へ
逃がしたジョブは中身が空のまま古びるので、**更新時刻だけで見てはいけない**
(2026-08-14 に「動いているのに寝落ち」と誤判定した実害)。よって
**誕生時刻**と**更新時刻**の両方を使う。

ジョブ 1 件と札 1 枚を**1 対 1 で**突き合わせる:

- (a) 札の誕生がジョブ起動と ±3 分で一致 → 「起動が一致」(強い証拠)
- (b) ジョブ起動より前に生まれた札がいまも書かれている → 「出力が更新中」
- どちらも無い → **未追跡**。前景実行のまま孤児化した計算。終わっても誰も気づかない。

札を取り合わせないのは、**同じコマンドの二重起動**を 1 枚の札で
両方「追跡あり」にしないため。

### 出る判定

| 表示 | 意味 | 何をすべきか |
| --- | --- | --- |
| 計算中 N 件 — 追跡あり | 正常。完了で AI が起きる | 待ってよい |
| 計算中 — うち M 件が投げっぱなしの疑い | 前景実行が孤児化。完了は誰も受け取らない | AI に拾わせる / 結果ファイルを直接見る |
| **計算は終わっているのに AI が N 反応していない** | 札が AI の最終発話より後に書かれ、走っているジョブは無い。冷えている | 声をかけて起こす |
| 二重起動 M 件 | 同じ出力ファイルを取り合っている | 片方を殺す |
| 裁定待ち | `.claude/裁定待ち.md` がある。正当な停止 | 中身が画面に出るので裁定する |
| 停止札 | 利用者が止めた | — |
| 静止中 | 計算なし・AI 無音 | 正常な終了か、寝落ちかを最終発話で見る |

**初回起動で実物を捕まえた**: 2026-08-24 01:37 に起動した
`diag_dead_constants.ts 0 999 --write` に札が無く(01:12 の 1 本目には
札 `bhc5es1la` がある)、前景実行のまま孤児化していた。二重起動でもあった。

## 修正への追従を最小にする作り(重要)

**この道具はスキーマを持たない。** 「どこを見るか」だけを書き、
「何という指標があるか」は書いていない。

- **評価値** — `report.json` を丸ごと汎用ツリーで出す。指標が増えれば勝手に出る。
  見出しのタイルへ昇格させたいものだけ `CFG.headline` に 1 行足す
  (パスが無ければ黙って飛ばすので、消えた指標で壊れない)。
- **パラメータ** — `best_*.json` の全キーを出し、`SPACE` の正規表現解析で
  下限・上限を当てる。定数が増減しても直さない。
- **推移** — `log_*.jsonl` の各行から**半数以上の行に現れる数値キー**を
  自動で見つけて系列にする。新しい指標を吐けば勝手にグラフの選択肢に出る。
- **run** — `log_<名>.jsonl` / `state_<名>.json` / `best_<名>.json` /
  `run_<名>.meta.json` の命名から run 名を自動発見する。v34 を始めれば勝手に出る。
- **進捗** — `state` に `cursor` と `screenCursor` があれば進捗率にする。
  無ければ進捗バーを出さないだけ。

書式が変わって読めなくなった箇所は、黙って空にせず画面に警告を出す
(`SPACE` が読めない / 台帳の項目が 0 件)。

### 直す必要があるのはここだけ

| 変えたもの | 直す場所 |
| --- | --- |
| `optimize_lib.ts` の `SPACE` の書式そのもの | `parseSpace()` の正規表現 |
| 積み残し台帳の項目の書式 | `collectLedger()` の正規表現 |
| 出力先ディレクトリ(`out/optimize` 等) | `CFG` の先頭 |
| 見出しに出したい評価値 | `CFG.headline` に 1 行 |
| 新しい種類のスクリプト分類 | `CFG.procKinds`(スクリプト名にだけ当てる) |

## 既知の限界

- 追跡の対応づけは**時刻の一致**で推定している。プロセスとセッションを
  直接結ぶ識別子がハーネス側に無いため。±3 分の窓で誤対応の余地がある
  (画面には「どのセッションのどの札に当てたか」を出しているので検証できる)。
- セッションが `/clear` されたり端末が閉じられていると、札があっても
  実際には呼び戻されない。これは外から判別できない。
- プロセス一覧は PowerShell の `Get-CimInstance` を 3 秒キャッシュで叩く。
  1 回あたり 1 秒弱。5 秒間隔の更新で常時 1 プロセス分の負荷が出る。
