## 0. 全体像

支配方程式(spec §支配方程式)

```
C·dT/dt = S(t)·(1 − α) − (A_eff + B·T_sl) + ∇·(D∇T_sl) − 移流結合 + Q_ocean
```

- 状態量は**海面高度相当温度 T_sl**。標高は OLR の定数項(−B·Γ·h)として入り、
  出力時に `T_surf = T_sl − Γ·h` へ落とす(L.401, L.433, L.1855)。
- 格子は `max(ebmResolutionDeg=2°, 表示解像度)`(L.319)。陸率・標高は
  **常に 1° 地形から**集約する(L.360-365)。
- **2 パス構成**。パス 1 = 恒常氷床なしで積分 → 氷床を判定(L.1373-1424)、
  パス 2 = 氷床アルベドを入れて確定(L.1426-1433)。パス 2 はパス 1 の
  温度場と氷厚を引き継ぐ(緩和年数を実質倍にするため)。
- **CPU 経路と GPU 経路の二重実装**。CPU = 行優先ガウス=ザイデル(L.636-1041)、
  GPU = 赤黒順序(`ebm_gpu.ts` の WGSL)。同じ式を 2 か所に書いているので、
  片方だけ直すと加速器の有無で物理が変わる(本文に注意書きあり)。

時間積分は 1 年 240 ステップ(`ebmStepsPerYear`)。各ステップは陰解法で、
**線形解の打ち切りは残差基準**(許容 `EBM_SOLVE_TOLERANCE_C = 1e-3`°C)。

## 2. 桁の見積もり(紙の上の計算。実行での確認なし)

2° 格子・地球(P = 1 bar、半径比 1、熱輸送強度 1)で、行列の各項がどれくらいか。

```
dt = 3.156e7 / 240 = 1.315e5 s、dφ = 2° = 0.03491 rad、dφ² = 1.218e-3

C/dt   陸(1.1 m)          4.19e6 × 1.1 / 1.315e5   =   35   W/m²/K
       海(50 m 混合層)    4.19e6 × 52.4 / 1.315e5  = 1670   W/m²/K
       加速期は上の 1/16(陸 2.2)

B      olrBWm2PerC                                  =    2.1 W/m²/K

拡散   南北 gN = 0.4964 / 1.218e-3                  ≈  408   W/m²/K(ハドレー域は最大 2.2 倍)
       東西 gz = 0.4964 × 0.12 × metric / 1.218e-3  ≈   49   W/m²/K(高緯度は上限 2 で 98)

移流   東西 advCu = 57.28 × 9/4                     ≈  129   W/m²/K(頭打ち時)
                    57.28 × 5/4                     ≈   72   W/m²/K(u = 5 m/s)
       南北 advCv ≤ 57.28 × 5/4 × 1.0(陸)          ≈   72   W/m²/K
```

読み取れること:

1. **東西方向の熱輸送は拡散(49〜98)ではなく移流結合(72〜129)が担っている。**
   これは設計意図どおり(`zonalDiffusionFactor` の注記)。
2. **移流結合は B の 30〜60 倍。** 陸の局所エネルギー収支(C/dt = 35、B = 2.1)は
   移流に対して小さく、`landEffectiveWaterDepthM` が効かない理由がここにある
   (constants.ts の注記と一致)。
3. 移流結合を等価な拡散係数に直すと `advCu × dφ² / metric = 129 × 1.218e-3 ≈ 0.157 W/m²/K`。
   **これは `dφ²` に比例する** = 格子解像度に依存する(§3 疑い-02)。

## 3. 棚卸し — 疑い一覧(全 31 件)

重大度: **A** = 物理・目的に直接響く / **B** = 隠しパラメータ・食い違い / **C** = 記述・整理

### A. 物理と目的に直接響く(6 件)

**疑い-01(A・最重要)移流結合はエネルギーを保存しない。しかも EBM 最大の係数である。**
`advCu·(T_風上 − T_i)` はセル i を暖めるが、**風上セルは何も失わない**(L.927-944、GPU L.271-278)。
拡散は 2026-07-31 の P2-2 で界面対称化して保存的になり、Q_ocean は明示的に全球中立化されている
(L.438-456)。**保存則を持たない項はこの移流結合だけ**で、しかも係数は最大 129 W/m²/K と
モデル中で最大級(§2)。流束形(`∇·(vT)`)ではなく移流形の片側差分なので、
残差は「風の発散 × 温度差」と「結合係数の空間変化(季節弱化・逆転層・陸グリップ・
海峡係数・頭打ち)」の和になる。地球ではこの不均衡を `olrAWm2` の較正が吸収できるが、
**他の惑星では吸収先が無い**。惑星応答が 5 軸とも妥当に出ているのは、
不均衡が気圧・傾斜・自転で大きくは変わらないためと読める(未検証)。
→ 測り方: 各時間ステップで `Σ_i cosφ_i · [advCu_i(T_upU − T_i) + advCv_i(T_upV − T_i)]` を積算し、
全球平均 W/m² として出す。これが 1 W/m² 級なら `olrA` の較正はその補正をしている。

**疑い-02(A)移流結合の実効輸送が格子解像度に比例して変わる。**
拡散は `D/dφ²` と離散化されているので格子に依らないが、移流結合は
`W/m²/K` の固定値で、`dφ` で割られていない(L.905, L.919)。
等価拡散係数は `advC × dφ²` なので、**2° → 3° で 2.25 倍、2° → 1° で 1/4 になる**。
言い換えると「移流の到達距離はセル数で決まる」ので、km で測った到達距離は格子幅に比例する。
`ebmResolutionDeg = 2` は数値パラメータの顔をして**物理定数として振る舞っている**。
段 17 の実測(2026-08-13)で 2° → 3° に気温 RMSE 3.535 → 3.439、大分類 −0.48 と
**場が動いている**のは、この依存性の現れと読める(当時は「粗いほうが滑らかで観測に近い」と
解釈された)。教訓 §9 の「実装詳細が答えを決める」型そのもの。

**疑い-03(A)表面気圧が温室効果(OLR)にもアルベドにも効かない。**
`surfacePressureBar` の消費者は step05 では**熱容量(L.426, L.428)と拡散(L.549-552)だけ**
(grep で確認)。`A_base` は `olrAWm2 − greenhouseDeltaAWm2·log2(温室強度)` で、気圧を見ていない。
実物では気圧が上がると(a)圧力広がりで温室効果が強まり、(b)レイリー散乱でアルベドが上がる。
**段 40 で直したのと同じ型の欠落が、隣の軸に残っている。**
段 40 と同様に「地球 1 bar で厳密に恒等」となる規格化ができるので、
地球の成績を 1 ビットも動かさずに繋げる。
2 bar で全球 +1.6°C という応答は現状**熱の再配分と雪氷アルベド帰還だけ**で出ており、
温室効果ぶんが抜けている。

**疑い-04(A)海氷の断熱を「セル全体」の熱容量に掛けている。**
L.762-763: `capEff = heatCap × (1 − f·seaW·海率)`。`heatCap` は
`陸率·陸深さ + 海率·海深さ` の混合値(L.430)なので、**陸のぶんまで断熱の対象になる**。
正しくは海側だけに掛かるべきで、陸率 0.5・混合層 50 m・氷被覆 1 の沿岸セルなら

```
正しい形  0.5×1.1 + 0.5×52.4×(1−0.95) = 1.86 m 相当
実装      (0.5×1.1 + 0.5×52.4)×(1−0.95×0.5) = 14.0 m 相当   ← 7.5 倍
```

海率 1 のセルでは両者は一致するので、**誤差は沿岸セルに限局する**。
北極海沿岸・南極沿岸はまさに季節振幅の再現が問われる場所で、
`seaIceInsulationFactor` が探索空間の上端 0.95 に張り付いているのは
「沿岸で効きが足りないぶんを外洋で買っている」可能性がある。

**疑い-05(A)陸の大気熱容量が海と食い違い、しかも spec と実装が違う。**
海は `2.4 × P`(m 水等価)、陸は `0.5 × (P − 1)`(L.425-428)。
大気柱の熱容量は `c_p·p/g / (ρc_water) = 1004×1e5/9.81/4.19e6 = 2.44 m/bar` で、
**海側の 2.4 は正しい**。同じ空気が陸の上にもあるのに陸側だけ 0.5 で、
しかも**気圧の差分 (P−1)** に掛かっている。結果:

- 地球 1 bar で陸の大気項は **0** になり、陸の総熱容量は 1.1 m 水等価
  = 大気柱だけの 2.44 m を下回る(物理的にありえない配分)。
- 0.5 bar の惑星では陸の熱容量が **減る**(1.1 → 0.85)が、これは大気が薄くなった
  ぶんではなく式の形の副作用。
- spec §C は「陸 = … + **0.5 m/bar**」と書いており、実装の `(P−1)` と食い違う。

**疑い-06(A)極行の帯状平滑が「収束解そのもの」を変えている。**
`relaxPolarRows`(L.1809-1827)は掃引の後に毎回掛かる反復作用素の一部なので、
不動点条件 `t = 0.5t + 0.5·行平均` から**収束解の `|lat| ≥ 84°` の行は厳密に経度一様**になる。
2° 格子では南北それぞれ 3 行(85/87/89°)、全 90 行のうち 6 行。
つまり極冠の経度構造は物理ではなく平滑化が決めている。
`84°` も `0.5` も裸の数値で、**spec に一言も無い**。
大分類 E の判定と、南極・グリーンランドの評価に直接効く。

### B. 隠しパラメータ・コメントと実装の食い違い(14 件)

**疑い-07(B)初期温度場 `−20 + 48·cos(lat)`(L.653-655、GPU L.596-599)が解の分岐を選んでいる。**
ファイル冒頭に「寒冷開始は雪玉解へ落ちるため温暖側から初期化」と明記されている =
**多重平衡があることを実装者が知っている**。つまりこの初期値は数値の便宜ではなく
「どの平衡へ落とすか」の選択で、地球の値に合わせてある。
系外惑星(特に光度 0.92 のような低日射)では、どちらの枝が出るかが初期値で決まる。
spec に記載なし。

**疑い-08(B)雲の沈降帯の幅 `16°` が裸で、同じ物理が step06 では命名済み。**
step05 L.481 `descLo = |ridge| − 16` に対し、step06 L.2349 は
`K.subsidenceBandEquatorwardDeg`(= 16)を使う。2026-08-13 に「16 がベタ書き」と
気づいて命名した際、**降水側だけ直して雲側が取り残された**。
定数を動かすと降水の沈降帯だけがずれ、雲の沈降帯は 16 のまま残る。

**疑い-09(B)恒常氷床の隣接拡張の裸の数値。**
拡張の回数 `2`(L.1398)、最暖月の閾値 `3°C`(L.1409)、陸優勢 `0.5`(L.1402)。
うち閾値 3 は**本判定の `permanentIceWarmestMonthC = 2` と食い違う**
(拡張のほうが緩い)。回数 2 は氷床が核から何セル広がれるかを決めるので、
これも格子解像度に依存する量(2° なら最大 4°≈440 km、1° なら 220 km)。

**疑い-10(B)移流の裸の数値が 6 つ。**

(「基準風速 4 m/s 時」)で説明されている。

**過去に成績を見て動かされた形跡がある** = 較正つまみが裸で置かれている状態。

**疑い-11(B)雲変調の裸の数値が 9 つ。**

帯の位置はリッジ・極前線相対なので**地理中立は保たれている**(良い設計)が、

L.682-688 は「既定(years = 0 = 自動)のときは従来と同じ 2 年を使う」と書いた直後に
「ただし既定値は GPU と揃える」と続く。前半は旧仕様で、現行(L.689-690)は
`bFullYearsStart = 24` を使う。旧文が削除されずに残っている。

**疑い-16(B)移流結合の到達距離の注記が現行の値と整合しない疑い。**
`zonalAdvectionCouplingWm2PerK` の注記は「到達距離 ≈ 結合/(B+Dk²) 換算で
1500〜2500 km 相当」。減衰を B のみで見た 1 次元評価では、
1 セルあたりの減衰率が `a/(a+B) = 129/131.1 = 0.984` となり、
e 折り返しに 62 セル(2° 赤道で約 13,700 km)かかる。
拡散を含めた実効減衰で評価すればもっと短くなるはずだが、
**注記の数字がどの評価式で出たのかが書かれていない**ので検算できない。
係数が較正で 57.28 まで上がった後に注記が更新されていない可能性が高い。

**疑い-17(B)表示の雪氷マスクの閾値が陸で `−1°C` の裸の数(L.1857)。**
アルベドで使う `iceOnsetC = −6` とも、海の `seaFreezeC = −1.9` とも別。
「アルベドが白い場所」と「地図で雪氷と表示される場所」が食い違う。

**疑い-18(B)`iceOnset` を陸率で内挿しているため、沿岸の陸の雪が海の凍結点に引っ張られる。**
L.435: `iceOnsetC·陸率 + seaFreezeC·(1−陸率)`。陸率 0.5 のセルでは −3.95°C になり、
その閾値を**陸の季節雪(snowW)にも使っている**(L.739-742)。
0 層模型では海側は氷量で決まる(seaW)ので、混合セルの陸側だけが
海の凍結点の影響を受ける形になっている。物理的には陸は `iceOnsetC` のはず。

**疑い-19(B)`summerAdvectionFactor` が `constants.ts` の「Step 6 降水」節にある。**
実際の消費者は step05 だけ(grep で確認)。注記も「夏半球の偏西風移流の弱化率」と
降水側の言葉で書かれている。spec/05 には EBM 定数として載っており、
**定数ファイルと仕様書で所属が食い違っている**。

**疑い-20(B)リッジ・極前線のフォールバック値が地球の数字。**
`?? 31` / `?? −31`(L.468-469, L.798-799)、`?? 60` / `?? −60`(L.470-471)。
Step 2 が値を返さない場合にだけ効くので実害は小さいが、
地球の緯度が計算層に埋まっている点は地理中立の観点で望ましくない。

### C. 記述・整理(11 件)

**疑い-21(C)spec/05 に名前が載っていない定数が 12 件ある。**
spec は「**ここには『どの定数が計算に効くか』を漏れなく載せる**」と宣言している。
step05 が使う 54 個の `K.*` のうち、spec に名前が無いのは:
`greenhouseDeltaAWm2` / `zonalDiffusionFactor`(「東西は縮小」とだけ) /
`oceanDiffusionBoost` / `channelLandFracMax` / `channelnessLinear` /
`channelMaxAbsLatDeg` / `iceRampWidthC` / `permanentIceAnnualMeanC` /
`permanentIceWarmestMonthC` / `lapseRateCPerKm`(Γ とだけ) /
`evapFeedbackFrac` / `evapLatentWm2PerMmDay` / `ebmYears` / `ebmStepsPerYear` /
`ebmResolutionDeg`。
とくに **`evapFeedbackFrac` は spec に 1 文字も出てこない**(§1-I)。

**疑い-22(C)`landDryCapacityFrac = 1.0` で乾き補正が完全に無効。**
`landDepth = 深さ × (1 + 0×湿り)` となり湿りが消える(L.422-425)。
にもかかわらず `buildAnnualWetness`(L.1720-1754)は 2 パス目に毎回計算されている
(L.395-397 の条件は `priorSurface?.land` の有無だけで、`landDryCapacityFrac` を見ていない)。
**死んだ機構 + 無駄な計算**。spec §C は「乾いた土壌は熱容量が小さい
(`landDryCapacityFrac` で湿りとの内挿)」と、**有効であるかのように書いている**。

**疑い-23(C)`evapFeedbackFrac = 0` で蒸発帰還が完全に無効。**
`buildEvapFeedback`(72 行)と、CPU/GPU 双方の陰的な対角項(L.775-782, L.930、
GPU L.176-183, L.271)が丸ごと待機状態。唯一の消費者が止まっているので
`evapLatentWm2PerMmDay` も連鎖して無効。2026-08-07 に事前登録して入れた機構が
現在 0 に戻されている(理由は本文からは追えない)。

**疑い-24(C)「効いていないと注記されている定数」の現状。**

| --- | --- | --- |
| `landEffectiveWaterDepthM` | 「いまほとんど効いていない」「τ = C/B_eff で ωτ ≈ 0.009」 | §2 の見積もりと整合(移流 129 ≫ B 2.1)。**SPACE に残っている**が、動かしても答えはほぼ変わらない。値 1.1 は範囲 [0.5, 8] の下端寄り |
| `landDryCapacityFrac` | 「1.0 で従来と厳密に一致」 | **1.0 = 無効**(疑い-22) |

「動くが 0.08°C しか動かない」ものは死んだと判定されない。

**疑い-25(C)EBM 定数のうち 8 件が探索空間の端かその直近に張り付いている。**

**疑い-26(C)`olrAWm2` は探索空間にあるが `olrBWm2PerC` は無い。**
惑星応答の記録が明記するとおり「地球の気温分布は A と B の**組**で決まる」ので、
A だけを動かすことは B を暗黙に固定することと同じ。
現在の感度 1.36°C/日射 1% は実物の想定範囲の下端で問題ないが、
**A だけが自由という非対称は意図的に選ばれたのか、単に入れ忘れたのかが文書から追えない。**

**疑い-27(C)較正が触れない EBM 定数が 7 件ある。**
`zonalDiffusionFactor`(東西/南北の異方性そのもの)、`zonalMetricCap`、
`oceanDiffusionBoost`、`channelLandFracMax`、`channelnessLinear`、
`channelMaxAbsLatDeg`、`channelMixedLayerBoost`。
とくに `zonalDiffusionFactor = 0.12` は東西輸送の骨格を決める量で、
移流結合(探索空間にある)と**同じものを分け合っている**。片方だけ較正すると、
異方性は「較正された移流 ÷ 固定の拡散」という比で決まってしまう。

**疑い-28(C)`zonalMetricCap = 2.0` は 45° より極側で東西拡散を頭打ちにする。**
`1/cos²φ` は 80° で 33 なので、高緯度では**実効的に 16 倍の抑制**になっている。
設計意図(「等方だと大陸規模の季節モードが潰れる」)は明記されているが、
「45° より極側では東西拡散が緯度に依らない」という強い性質は spec に無い。

**疑い-29(C)GPU の `itersLate = iters/4` に CPU の対応物が無い。**
GPU は加速期を抜けたら反復を 1/4 に落とす(`ebm_gpu.ts` L.655, L.690)。
CPU は残差基準なので必要なだけ回る。**同じ答えになる保証は残差検査だけ**で、
その残差検査は CPU では動いていない(疑い-13)。
両経路の一致は `scripts/check_cpu_gpu_seaice.ts` が見ているようだが、
今回は実行していないので現状の一致度は未確認。

**疑い-30(C)`budgetHint` は計算層のモジュールレベル可変状態。**
CLAUDE.md の「計算層は純粋関数。副作用禁止」に対する明示的な例外。
「答えには影響しない」と注記され、`resetEbmBudgetHint()` も用意されているので
統制は取れているが、**同一プロセスでの実行順が予算に影響する**ことは変わらない。
較正は `adaptive = false` なので手掛かりの読み書き自体が止まる(L.1189, L.1322)ことを確認した。
