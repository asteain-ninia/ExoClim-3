# 事前登録: 加速期の熱容量倍率と反復回数は対で決まる

日付: 2026-08-11
**結果を見る前に書いている。**
前段: [実験記録_加速期だけが反復を要る](実験記録_加速期だけが反復を要る_2026-08-10.md)

## なぜやるか

昨日の測定で、**反復 512 回を要求しているのは加速期のステップだけ**だと
分かった。加速期は熱容量を 1/16 にして緩和を早める工夫だが、そのせいで
陰解法の対角項 C/dt が 16 分の 1 になり、対角優位が崩れて反復が効かない。

つまり **加速期の倍率は「速く緩和する」と「反復が効かなくなる」を
同時に買っている**。片方だけ見て 1/16 と決めた形跡があり、対で測られていない。

```
step05_temperature.ts:184  /** 加速期(熱容量 1/16)の年数。τ' = 0.2 年なので 2 年で十分 */
step05_temperature.ts:672  const capScale = step < spinupSteps ? 1 / 16 : 1;
gpu/ebm_gpu.ts             const capScale = step < spinupSteps ? 1 / 16 : 1;
```

**1/16 は名前を持たない数で、CPU と GPU に 2 か所ベタ書きされている。**
仕様書にも UI にも無く、計算には効く。教訓 §1 の言う隠しパラメータそのもの
なので、まず名前を与える(`spinupCapacityFraction`)。

## 予測(先に書く)

緩和の時定数は τ' = τ × 倍率 なので、同じだけ緩和するのに必要な年数は
**倍率に比例**する。一方、反復回数は対角優位 ∝ 1/倍率 で決まり、昨日の実測
(倍率 1/16 で 512、全熱容量で 128)から **反復 ∝ (1/倍率)^0.5** と読める。

したがって加速期の費用は

```
費用 ∝ 年数 × 反復 ∝ 倍率 × (1/倍率)^0.5 = 倍率^0.5
```

**倍率を下げるほど安くなる**という予測になる。1/32 まで下げる価値がある。
逆に 1/4 へ上げると高くつくはずである。

この予測が外れる筋も書いておく: 倍率を下げすぎると加速期の解が実際の
気候から離れすぎ、全熱容量に戻ってからの立ち上がりに余分な年数が要る
(= 全熱容量の年数が 24 から増える)可能性がある。**そこは測る。**

## 掃く組(緩和量を揃える)

年数は倍率に比例させて、加速期に得られる緩和量を揃える。

| 倍率 | 加速期の年数 | 備考 |
|---|---|---|
| 1/32 | 1 | 予測では最安 |
| 1/16 | 2 | **現行** |
| 1/8 | 4 | |
| 1/4 | 8 | 予測では最も高い |

## 判定(先に固定する)

1. **答えが変わらない。** v3 の差が ±0.05 以内(周期定常の許容差が作る
   数値の床は v3 にして 0.02〜0.03 — 2026-08-06/08-10 の実測)。
   地域の夏の正味流入が ±2 mm/年 以内。
2. **収束が保たれる。** 反復の倍化が起きない(512 のまま)、全ステップの
   最大残差 ≤ 1e-3、年次ドリフト ≤ 0.05°C。**ここは 1 件でも破れたら棄却。**
3. **全熱容量の年数が増えていない。** 24 のまま(倍率を下げすぎた副作用の検査)。
4. 1〜3 を満たす組のうち、**他プロセスを止めた壁時計が最小**のものを採る。
   現行(146.2s)を下回らなければ**現状維持**。

## やらないと決めていること

- **加速期を無くすこと。** 冷間から全熱容量で回すと 24 年で足りるか不明で、
  これは別の実験になる。今回は「倍率と年数の対」だけを動かす。
- **許容差(1e-3 / 0.05°C)を緩めること。** 費用の実験で精度の基準を動かしたら
  何を測ったか分からなくなる。
- **成績が上がったからという理由で採ること。** これは費用の実験であり、
  成績が動いたらそれは数値の揺れである(判定 1 で締める)。
