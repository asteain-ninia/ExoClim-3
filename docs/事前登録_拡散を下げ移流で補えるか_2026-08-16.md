# 事前登録: 拡散を下げたぶんを、移流(偏西風)で補えるか

日付: 2026-08-16(前段の結果を見た**直後**に書いた。組の実験はまだ走らせていない)
前段: [実験記録_渦拡散は輸送を代行していた](実験記録_渦拡散は輸送を代行していた_2026-08-16.md)

## なぜ組で打つのか

前段で分かったこと:

- 拡散を下げると**分布の両端が同時に観測へ近づく**(1% 64→21、99% 3011→3377)
- しかし**内陸が乾く**(インド 0.45→0.34、米南東 0.37→0.26)ので大分類が下がる
- **渦拡散は、移流が担うべき輸送を代行していた**

したがって単独の手にはならない。**拡散を下げたぶんの輸送を別のもので補う**必要がある。
補う候補として最も根拠があるのは偏西風である:

- 段 32 で「中位の陸を湿らせられる唯一の手」と確認した
- 段 38 で `westerlyWindMs` を探索空間から外し 9.0 に固定した
  (探索空間に残すと較正が下端 6.5 へ戻すため)
- **移流は向きを持つ**。拡散と違い、両端を削らずに内陸へ運べる可能性がある

## 測ること

拡散を 5 水準で掃引する実験を、**偏西風 12.0 m/s** で繰り返す
(現在は 9.0 m/s。前段の 5 水準がそのまま対照になる)。

```
拡散: 3.0e6 / 2.4e6 / 1.8e6 / 1.2e6 / 0.6e6
偏西風: 9.0(前段・対照)  vs  12.0(今回)
```

測る量は前段と同じ(分位 8 点・分布誤差・連続部分・大分類・地域比・数値健全性)。

## 予測(**結果を見る前に固定する**)

1. **偏西風 12 では、同じ拡散でも内陸が湿る。**
   拡散 1.2e6 での インド比が 0.38(偏西風 9)→ **0.45 以上**になると読む。
2. **分布の両端は、偏西風を上げても大きく悪化しない。**
   移流は向きを持つので、1% 分位は拡散 1.2e6 で 33 → **45 以下**に留まると読む
   (拡散 3.0e6 の 64 までは戻らない)。
3. したがって **偏西風 12・拡散 1.2e6 の組が、偏西風 9・拡散 3.0e6(現行)より
   連続部分で上回る**。現行 70.314 に対し **70.5 以上**を出すと読む。
4. 数値的健全性は全水準で保たれる。

**予測 3 が当たれば、これは半月ぶりに「分布形と成績を同時に改善する」手である。**

## 判定

- **予測 3 が当たったら**: 偏西風の固定値を 12 へ上げ、拡散の探索空間の上限を
  下げたうえで、**新しい run 名で較正をやり直す**
  (来歴の指紋が変わるので v24 は続けられない。それが正しい)。
- **予測 1 が外れたら**(偏西風を上げても内陸が湿らない): 偏西風は移流の担い手として
  不十分。拡散の代役を別の機構(収束持上げ・経度依存の風)に探す。
- **予測 2 が外れたら**(偏西風を上げると端が戻る): 移流も結局は均していることになる。
  その場合は「運ぶ」と「均す」の区別が実装で立っていない疑いを掘る
  (2026-08-15 に段 36 で一度踏んだ型)。
- **予測 3 だけが外れたら**(個々は良いが合計で届かない): 2 定数の同時最適化が要る。
  組を較正の探索空間に戻して回す設計へ進む。

**どの結果でも、目的関数の重みは動かさない。**
症状を目的関数で押さえつけるのは、まさに監査が指摘した歪みの作り方である。

## 実装メモ

`scripts/sweep_lib.ts` に環境変数 `SWEEP_OVERRIDE`(`名前=値` のカンマ区切り)を足し、
掃引の全水準に共通の定数上書きを掛けられるようにする。
**ワーカー側にも効かせる**こと(親だけに掛けると答えが変わる — 2026-08-15 に
`EBM_SOLVER.adaptive` を写し忘れて 0.024〜0.057 ずれた前科がある)。
