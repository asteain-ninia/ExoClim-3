# 実験記録: 掃引を並列化した — 答えは変わらないが、速さは「水準数ぶん」ではない

日付: 2026-08-15
前段: [引き継ぎ_2026-08-14](引き継ぎ_2026-08-14.md) §5「すぐ効くやり残し」

## やったこと

掃引(`scripts/exp_pressure_lever.ts`)は水準を**直列**に回していた。
測定と印字を `scripts/sweep_lib.ts` へ出し、`scripts/sweep_worker.ts` を
水準数ぶん立てて並列に測るようにした。既定の並列度は 4、`--parallel 1` で
以前の直列に戻る。

水準どうしが独立であることは実装から言える — パイプラインは入口で
`resetEbmSolverStats` と `resetConservativeStats` を呼ぶので、
同一プロセスの直列実行でも水準間の状態は漏れない。

## 判定 1: 答えが変わらないこと → **満たす(全桁一致)**

`crhSuppressionSharpness` を 0 と 1 で並列に測り、
2026-08-14 に**直列で**測った [実験記録_凝結率の幅の再測定](実験記録_凝結率の幅の再測定_2026-08-14.md)
の表と突き合わせた。

```
        v3       大分類  詳細   W    congo  結合反復  残差
鋭さ0  85.235   74.49  44.88  3.4   1.31   8/24    0.165   ← 記録と全桁一致
鋭さ1  82.111   72.74  42.02  6.0   1.51   7/24    0.093   ← 記録と全桁一致
```

さらに**同じ水準を 4 本同時に**走らせたところ、4 本とも
`85.259 / W 3.4 / 輸送反復 21246 / 残差 0.165` で完全に一致した。
同時実行そのものは答えを揺らさない。

## 判定 2: 速さ → **「水準数ぶん」は成り立たない**

```
1 水準を単独で        146〜149 秒
2 水準を並列度 2 で   208〜222 秒/水準  → 全体 222 秒（直列 295 秒の 1.33 倍速）
4 水準を並列度 4 で   365〜382 秒/水準  → 全体 382 秒（直列 592 秒の 1.55 倍速）
                                         ※ 別のテストと GPU を取り合った下限値
```

引き継ぎには「水準数ぶん速くなる」と書いたが、**誤りである**。
1 評価の費用は 88% が EBM = GPU 側にあり
([実験記録_評価費用の内訳](実験記録_評価費用の内訳_2026-08-10.md))、
CPU が 24 コア空いていても律速は GPU である。

**「CPU の負荷が低い」という観察は正しく、そこから引いた結論が誤っていた。**
空いている資源はボトルネックとは限らない。桁で効かせたいなら
GPU 側(多重格子)を削るしかない、という 2026-08-06 以来の結論は動かない。

利得 1.3〜1.6 倍は素で効くので採用する。副次的な利点として、水準ごとに
プロセスが分かれるぶん、モジュールの可変状態の漏れに対して直列より強い。

## 途中で自分が入れた欠陥(記録する)

最初の実装で、較正のワーカー(`optimize_worker.ts`)から
`EBM_SOLVER.adaptive = false` を**そのまま写した**。
その結果、並列で測った v3 が直列の記録と 0.024〜0.057 ずれた。

`adaptive = false` は**較正の設計**である — 収束しにくい定数領域は
「高くつく」のではなく失格にする、という意図で入っている。
掃引は設計が違う。その水準の本当の答えを出して表に載せる道具なので、
反復が足りなければ倍化して収束させるのが正しい。

危なかったのは、**ずれが「数値の床」(v3 で 0.02、
[実験記録_ウォームスタート](実験記録_ウォームスタート_2026-08-06.md) §3)と
同じ桁だった**ことである。0.024 のずれは「GPU の丸め」で説明がついてしまい、
そのまま通してもおかしく見えない。

区別できたのは、**同じ水準を 4 本走らせて完全一致を確認した**からである。
同時実行が揺らさないと分かれば、残る差は挙動の変更しかない。

一般則: **ずれが数値の床と同じ桁のときこそ、揺らぎと挙動変更を
機械的に分けること。** 「床の内だから問題ない」で通すと、
挙動を変えた覚えのない変更が静かに答えを動かす。

## 使い方

```bash
npx tsx scripts/exp_pressure_lever.ts <定数名> <値1,値2,...> [--parallel N]
```

進捗は stderr、表は stdout へ出る。表は**水準の順**に印字される
(完了順ではない)。他の掃引スクリプトも `sweep_lib.ts` の
`runSweep` を呼べば同じ形で並列化できる。
