作成日: 2026-07-31

実装担当へ: この文書を作業の正本として、P0 から順に進めること。
各項目は受入条件と必須テストを満たした時点で完了とし、判断が必要な場合は

## 0. この文書の目的

ExoClim-3 は、ワールドビルディング向けの説明可能な気候エミュレータとして
筋が良い。特に次の原則は維持すること。

- ITCZ → 風帯 → 海流 → 気流 → 気温 → 降水 → 気候区分を追跡可能にする。
- 気候区分を座標で直接塗らず、月別気温・降水から判定する。
- 計算層へ地球の地域名・座標補正を持ち込まない。
- 棄却した仮説と副作用を記録する。

一方、現在は同じ地球データを較正と最終評価の両方に使っており、モデル定数
111 個のうち 60 個を自動探索している。これ以上つまみを増やす前に、
解像度再現性・検証の独立性・再開耐久性を直す必要がある。

この FB の狙いは、地球の訓練スコアを直ちに上げることではない。
**「改善したと言える物差し」を先に作ること**である。

## 3. P0 — 次の較正前に必ず直す

### P0-1. 手続き地形を解像度不変にする

#### 問題

`src/domain/terrain.ts` の値ノイズはオクターブの大きさをセル数
`[90, 45, 22, 11, 5]` で定義している。そのため、表示解像度を変えるだけで
地形の波長と乱数格子が変わり、同じ乱数種子が別惑星になる。

これは表示設定が物理入力を変える実バグである。

#### 修正方針

- ノイズ格子を出力セル数から独立させる。
- オクターブは角度または惑星上の距離で定義する。
- 推奨は、`乱数種子 + オクターブ番号 + 固定角度格子座標` から値を得る
  座標ハッシュ方式。
- 0.5°/1°/2° は同じ連続ノイズ場を異なる密度で標本化する。
- 海水準の面積重み付き分位点という方針は維持する。

#### 受入条件

- 複数の乱数種子で 0.5°/1°/2° の陸面積率が指定値 ±1 ポイント。
- 1° と 0.5°を同じ格子へ集約した陸域 Jaccard 係数が 0.95 以上。
- 1° と 2°も、海岸の集約差を除き同じ大陸形状になる。
- 同一乱数種子・同一パラメータ・同一解像度は配列まで完全一致。
- 地球プリセットと仮想大陸プリセットを退行させない。

#### 必須テスト

`tests/unit/domain/terrain.test.ts` を追加し、決定性、陸面積率、
解像度間一致、経度継ぎ目を検証する。

### P0-2. 最適化ログと状態の再開整合性を直す

#### 問題

`scripts/optimize.ts` は評価完了ごとにログへ追記するが、`state.json` の保存は
バッチ末尾である。バッチ途中で停止すると、再開時に古い `state.evals` から
同じ評価番号を再利用する。

v1 の 364～366 番重複はこの不整合の実例である。

#### 修正方針

- 評価番号の正本を `state.evals` だけにしない。
- 起動時に有効なログ最終行・最大評価番号と state を照合する。
- 次の評価番号は必ず既存ログ最大値 + 1 から採番する。
- 状態は同一ディレクトリの一時ファイルへ書き、同期書込み後に置換する。
- 途中で切れた JSONL の最終行だけは無視可能にする。
- 中間行の破損は黙って無視せずエラーにする。
- バッチ途中の候補を再評価する場合も、評価番号は重複させない。
- 「完全無損失再開」と呼べない場合は、文書を
  「完了評価はログに保持、未確定バッチは再評価」に訂正する。

#### 受入条件

- `state.evals=363`、ログ最大番号 366 から再開した次番号が 367。
- バッチ途中終了を模擬しても評価番号が重複しない。
- 状態の途中書き込みを模擬しても、直前の正常状態または明示エラーになる。
- 既存 v1/v2 ログは変更しない。
- 学習曲線生成側は重複番号を検知し、警告する。

#### 必須テスト

最適化の永続化・ログ読込を純粋な補助関数へ分離し、一時ディレクトリを使った
ユニットテストを追加する。

### P0-3. 採点定義を一元化し、面積重みを統一する

#### 問題

`scripts/optimize_lib.ts` と `scripts/validate.ts` に地域ゲートと採点処理が
複製されている。

さらに、

- 最適化側の気温・降水 RMSE と陸平均: 緯度面積重み付き
- 標準 validate の気温・降水 RMSE と陸平均: 2°セルの単純平均

となっている。標準レポートの「陸平均 585 mm」は高緯度セルを過大に数える
単純平均で、最適化側の値と直接比較できない。

#### 修正方針

- 教師データ読込、地域ゲート、主要/詳細一致率、気温・降水 RMSE、
  ITCZ RMSE を共有モジュールへ集約する。
- 全球・陸面の場の指標は `areaWeightOfRow` を使う。
- 単純セル平均も診断として残す場合は、名前に「非面積重み」と明記する。
- `validate` と最適化器が同じ入力に対して同じ値を返すことをテストする。
- 地域ゲートは 1 箇所だけで定義する。

#### 受入条件

- 同一 `PipelineResult` に対し、最適化器と `validate` の共通指標が丸め前で一致。
- レポート JSON に指標の重み方式を明記。
- 地域ゲート定義の複製がなくなる。
- 既存目的関数の重みは変更しない。

### P0-4. `validate` を「報告」と「合否判定」に分ける

#### 問題

現在の `npm run validate` は PNG と JSON を出力するだけで、基準未達でも
終了コード 0 になる。CI では大幅な退行も成功扱いになる。

また、`docs/教訓.md` は「地域ゲートは全部通って初めて採用」としているが、
現行採用値は 14/17 である。最終受入基準と開発中の退行防止基準を分ける必要がある。

#### 修正方針

次の 2 層を設ける。

1. **退行防止ゲート**
   - 凍結した基準値から主要指標・既存 PASS 地域を悪化させない。
   - CI で使用し、失敗時は終了コードを非 0 にする。
2. **最終受入ゲート**
   - `docs/要件.md` と `docs/教訓.md` の本来の受入基準。
   - 未達項目を明示し、14/17 を「最終合格」とは扱わない。

閾値はコード中に散らさず、根拠・凍結日つきの単一設定へ置く。
結果を見て自動的に基準を緩めない。

#### 受入条件

- 退行させた固定フィクスチャで検証コマンドが非 0 終了するテスト。
- 現在の採用モデルは退行防止ゲートを通る。
- 最終受入の 3 未達地域はレポート上で未達のまま明示される。
- JSON に `regressionPass` と `acceptancePass` を分けて記録する。

## 4. P1 — 評価基盤の次に直す

### P1-1. 空間ホールドアウトを導入する

#### 問題

自動較正と標準検証が同じ Beck 気候区分、同じ月別地球平年値、
同じ地域ゲートを使用している。現在の 73%台は訓練成績であり、
未知地形・未知地域への一般化性能ではない。

#### 修正方針

- 地球格子を十分大きな空間ブロックへ分け、決定的な 5 分割を作る。
- 隣接セルが訓練と検証に細切れで混ざらないよう、ブロックは粗くする。
- 採点関数へセルマスクを渡せるようにする。
- 最適化器は指定した空間保留検証区画を目的関数から除外できるようにする。
- `validate` は訓練領域・空間保留検証領域・全球を別々に報告する。
- 地域ゲートは訓練へ入れるものと、完全に保留検証するものを事前登録する。
- 最初の実運用前に分割定義を文書で凍結する。

#### 受入条件

- `--holdout-fold N` で対象区画が目的関数から除外される。
- 区画間にセル重複がなく、全区画の和が採点対象全球になる。
- 各区画の陸面積・主要気候群が極端に偏らないことをレポートする。
- 以後は「訓練」「空間保留検証」「全球」を混同して報告しない。

注: 現行定数は全球を見て選ばれているため、空間保留検証の基盤を追加した
だけでは未見評価にならない。基盤完成後に分割を固定して再較正すること。

### P1-2. 解像度依存の「固定セル半径」を距離基準へ直す

#### 問題

`step06_precipitation.ts` に次の固定セル探索が残っている。

- 暖かい近傍海面探索: ±6 セル
- 寒流沿岸探索: ±3 セル

0.5°/1°/2°で探索距離が 4 倍変わり、惑星半径にも追従しない。

#### 修正方針

- km または角距離で探索半径を定義する。
- 行ごとの `cellWidthKm` と `cellHeightKm` から探索範囲を導出する。
- 定数化する場合は `MODEL_CONSTANTS` を増やさず、まず現在の 1°地球での
  実効距離を仕様上の固定距離へ置き換える。

#### 受入条件

- 同じ地形を0.5°/1°/2°で評価した代表地点の探索対象距離が一致する。
- 地球1°の結果を許容差内で維持する。
- `src/sim` の気候へ効く固定セル幅を検索し、同種問題が残っていない。

### P1-3. モデル適用範囲と異常診断を実装する

#### 問題

UI の各スライダーは単独では有限範囲だが、組合せによってモデルの仮定を
大きく外れる。線形 OLR と Magnus 式をそのまま外挿し、数千°C・数十億mm/月を
正常なケッペン気候として表示する。

「NaN がない」は「定性的に妥当」と同義ではない。

#### 修正方針

- モデルが扱える温度・放射・液体水条件の適用範囲を仕様に明記する。
- 入力時の事前診断と、計算後の場の診断を分ける。
- 適用範囲外は値を黙って切り詰めず、理由つきで
  「このモデルでは判定不能」とする。
- 適用範囲外のときはケッペン分類を有効な科学出力として表示しない。
- `PipelineResult` へ診断状態を追加する場合、UI とヘッドレス検証の両方で表示する。

#### 受入条件

- 上記の高加熱端が明示的な適用範囲外になる。
- 数十億mm/月を正常結果として返さない。
- 地球条件と妥当範囲内の温暖・寒冷ケースは従来どおり計算可能。
- 全海、全陸、傾斜0°、逆行の有限性・診断テストを追加する。

### P1-4. 気候パイプラインの性質テストを追加する

最低限、次を自動化する。

- 同一入力で気候場が配列まで決定的。
- 全出力配列が有限。
- 手続き地形の解像度変更で同じ惑星を保つ。
- 傾斜0°の季節対称性。
- 対称な全海惑星の経度対称性。
- 妥当範囲内で、放射照度増加により全球平均気温が低下しない。
- 妥当範囲内で、温室効果増加により全球平均気温が低下しない。
- 逆行時に東西位相規則が反転する。
- 既存の地球主要指標が凍結基準から退行しない。

`runPipeline` は純粋関数を名乗る一方、戻り値に `performance.now()` 由来の
`stepTimingsMs` を含む。同一入力の戻り値全体は決定的ではない。
物理結果と計測ラッパーを分離すること。

## 5. P2 — 構造改善として調査する

P2 は即時に定数を動かさず、まず最小再現テストを作ってから判断する。

### P2-1. 降水を「水収支」と呼べる範囲を明確にする

現在は各対象セルが独立に風上を追跡し、同じ供給源を複数セルが繰り返し利用する。
共有された大気水蒸気状態や、供給源からの水量控除はない。

短期:

- 文書では「風上供給エミュレータ」等、保存則を満たすモデルと誤認しない表現にする。
- 全球の蒸発相当、降水、再循環寄与を診断出力する。

中期候補:

- 月別の水蒸気フラックス場を状態として持つ保存型輸送。
- 海面蒸発 → 移流 → 凝結 → 残存水蒸気の順に収支を閉じる。

これは大規模変更なので、空間保留検証と回帰テスト完成前には着手しない。

### P2-2. EBM の界面係数を再点検する

`step05_temperature.ts` は界面係数を平均して保存性を確保する旨をコメントしているが、
現在セル側の `df` には冬季逆転係数が入り、隣接セル側は生の `diffFactor` のままである。
逆方向の更新と係数が一致せず、コメントどおりの対称界面になっていない可能性がある。

- 2 セルまたは小格子で拡散のみを動かす保存性テストを作る。
- 逆転係数込みの界面伝導度を両セルから一意に定義する。
- 修正前後の全球エネルギー残差を報告する。

### P2-3. 明白なコード・コメント不一致を整理する

- `step04_airflow.ts` の `bandWeight`:
  コメントは端で 0 だが、実装は端で 0.5。リッジ境界で東風と西風が急反転する。
- `step06_precipitation.ts` の `blend`:
  コメントは 0.25/0.5/0.25 だが、実装は 0/1/0 の恒等コピー。
- `constants.ts` の未使用海氷定数:
  `seaIceGrowthMPerDegDay`、`seaIceMaxThicknessM`、`seaIceLatentJPerM3` は未使用。
- `pipeline.ts` は純粋関数とされるが、戻り値へ時刻依存の計測値を入れている。

コメントを実装へ合わせるだけで済ませず、意図を仕様・較正記録から確認し、
挙動を変える場合は回帰テストを先に置くこと。

## 6. パラメータ追加・探索器改善の判断

### 6.1 先に探索器を改善する

現行は感度スクリーニング後の単一開始点・座標降下であり、強い相互作用を
持つパラメータ群では局所解に入りやすい。

P0/P1 完了後、同じ60項・同じ凍結目的関数で次を比較する。

- 複数の乱数種子・複数開始点
- ラテン超方格等による初期点の分散
- CMA-ES 等の共分散を扱える探索
- 現行座標降下

比較対象は訓練適合度だけでなく、空間保留検証の指標・探索再現性・計算回数とする。

### 6.2 新しいパラメータを増やす条件

次を全て満たすまで追加しない。

- 解像度不変テスト PASS
- 空間保留検証の基盤完成
- 再開整合性 PASS
- 退行防止 validate PASS
- 既存60項の多点探索結果が比較済み
- 追加する量に独立した物理的意味と観測可能な効果がある
- 既存パラメータとの相殺だけでスコアが上がっていない

追加候補は自由な補正つまみではなく、次のような状態・機構を優先する。

- 土壌水分状態
- 季節変化する SST・海洋熱慣性
- 保存型の大気水蒸気輸送
- セル平均で消える山脈最高標高などのサブグリッド地形
