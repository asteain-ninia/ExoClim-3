# 診断(不成立): 輸送の内訳 — **符号が合わないので数字を読まない**

日付: 2026-08-15
道具: `scripts/diag_transport_budget.ts`(新規、**未完成**)
出力: `out/diag_transport_budget.txt`

## 何をしようとしたか

段 22〜30 で 9 回測って 9 回棄却した。**すべて凝結側(G)を触る手**だった。
だが診断が示した問題は「中位の陸の正味流入が 49mm/年、必要 212」であり、
**運ぶ側**である。**輸送の内訳は一度も見ていない。**

保存型の定常収支はセルごとに

```
−∇·(uW) + D∇²W + E − rate·W = 0
```

で閉じるので、**どの項が中位で足りないか**を数えれば処方が決まるはずだった。

## なぜ不成立か

```
群              移流流入  拡散流入   源 E    凝結    残差
乾いた側          -19.1     47.5   138.1   146.8    19.7
中位             109.6   -159.5   461.4   510.0   -98.5
湿った側          474.5   -294.8  1278.9  1896.8  -438.2
```

**定常なら `移流 + 拡散 = 凝結 − E` が成り立つはず**である。中位で言えば

```
期待: 510.0 − 461.4 = **+48.6**
実測: 109.6 − 159.5 = **−49.9**
```

**符号が逆で、絶対値だけ一致している。**
偶然にしては出来すぎており、**符号規約か差分の取り方のどこかに誤りがある**。

心当たりは 2 つ:

1. **差分の取り方**が実装と違う。`solveMoistureTransport` は
   **面フラックス(共有面で一意)** で組んでいるが、この診断は
   セル中心の中心差分で組んだ。境界の扱いが違えば収支は閉じない。
2. **風の符号規約**。row 0 が北端なので `iN = (row−1)·W + col` は北だが、
   `v` が北向き正かどうかを実装で確かめていない。

**どちらにせよ、この数字を読んではいけない。**
「拡散が中位から水を奪っている」という読みは魅力的だが、
**符号が合わない診断から出た読みである。**

## 今日ここで止める理由

今日は同じ型の失敗を既に 2 回している:

- 「湿潤ゲートが 0.036 まで閉じている」→ **分位どうしを掛けた誤り**
- 「平滑幅 1.5° が相関長と一致 = 因果」→ **数字の一致を因果と読んだ**

**符号が合わない収支から「拡散が奪っている」と読むのは、同じ型の 3 回目**になる。
道具を直してから読む。

## 直し方(次のセッションへ)

`moistureConvergenceIndex` が面フラックスで組んでいるのと**同じ方法**で、
移流・拡散の流入を組み直す:

- 東西の面長は面の緯度の cos に比例、南北は一定(`cosFaceOf` の考え方)
- セル面積 `a²·dλ·dφ·cos(latC)` で割って mm/月 にする
- **`v` の符号規約を実装で確かめる**(`step04_airflow` の `bv` の作り方を読む)

そのうえで**残差が 0 になることを先に確認**してから、内訳を読むこと。
**収支が閉じない診断は、内訳を語る資格がない。**
