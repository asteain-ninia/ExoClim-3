# 事前登録: 目的関数 v6 — 位相項の帯別化(冬雨少数派の独裁を外す)

日付: 2026-08-19(実装前に書いた)
裁定: 利用者「目的関数の修正は早ければ早いほど良い。物差しを先に」(2026-08-17 裁定 1)

## 欠陥(測定済み・結果に依存しない根拠)

位相項は全球一本の RMSE(v5: wPrecipPhase=2 × RMSE/30 日)。二乗和は分散の
大きい少数集団が支配するため、**冬雨型(位相重みの 22〜25%、−72 日)が
物差しを独裁**する。実測:
- ITCZ の暦の遅れ(lag=1)は熱帯の系統誤差をほぼ消す(−28.6→−3.8 日、
  熱帯セルの 92%)のに、全球 RMSE は 72.0→70.8 しか動かない。
- v27 較正はこの勘定で lag を 3 回試して 3 回捨てた(+0.08 対 大分類 −0.13)。
物差しが「熱帯の雨季を正しくする」を報酬しないのは物差しの誤りである。

## 変更(v6)

位相項の距離を「全球 RMSE」から「**帯別 RMSE の平均**」へ置換:

```
帯 = |緯度| [0,15) / [15,35) / [35,90]
precipPhaseBandMeanDays = mean(RMSE_帯1, RMSE_帯2, RMSE_帯3)
fitness(v6) = fitnessV4 − wPrecipPhase × (precipPhaseBandMeanDays / 30)
```

- 重み・係数は動かさない(wPrecipPhase=2 のまま)。距離の定義だけ直す。
- **continuousV3 は不変**(版間比較の唯一の物差し)。全球 RMSE も
  報告値として残す。
- 変更はこの 1 点のみ(帰属を単純に保つ)。地域項の再検討は v6 の結果を
  見てから別途。

## 予測(結果を見る前に固定)

42. v27 定数での基準値: precipPhaseBandMeanDays は全球 RMSE(72.1)より
    小さい(60〜70 の間。冬雨の重みが 1/3 に規格化されるため)。
43. **酸性試験 — lag の勘定が逆転する**: v6 の fitness で
    circulationLagMonths 1 が 0 に**勝つ**(v5 では 3 回連続で負けた)。
    機構: 帯別平均では熱帯帯の RMSE 低下(見込み −15 日級)が 1/3 の重みで
    効き、+0.3 点級 > 大分類の −0.13。
44. relief×conveyor の 45c 最良格子点の順位は v6 でも大きく変わらない
    (位相はこの組でほぼ不動のため)。

## 判定

- 43 が当たったら: v6 を有効(W=V6)にして v28 較正へ
  (SPACE: +monsoonTroughSubsRelief [0,0.8]。conveyorLatPolewardDeg は
  基準点死のため除外継続)。
- 43 が外れたら: 大分類側の費用の出所を分解してから重み論に進む
  (係数はいじらない — 距離の定義の問題として扱う)。
