## 2. 面積重みの罠(私が踏んだ。次も踏む)

**1° 格子では南極が陸セルの 28.3% を占めるが、面積では 9.5% しかない。**
極はセルが小さいのに数が多い。重み無しの分位・分散は南極が買い占める。

```
                      Var(log G)   Var(log W)
重み無し・全陸           4.4%        91.2%
面積重み・全陸          14.4%        79.1%
面積重み・南極を除く    42.8%        40.8%   ← 判断はこれで
```

**「7 点平均で幅を語る」を批判した文書自身が「セル数で分位を語る」をやり、
その数字のまま commit した。** 標本の取り方の誤りは批判している側にも出る。

さらに: 南極は観測もモデルも一律 EF なので、**降水が 30 倍外れていても
成績に出ない**。成績に出ない領域が物理の結論を支配していないかを必ず見る。

## 3. 枯渇しているのは南極だけ。しかも**遠いからではなく寒いから**

[診断_枯渇しているのは南極だけ](診断_枯渇しているのは南極だけ_2026-08-15.md)。

W < 0.2mm のセルは **100% が 60°S 以南**。チベットも大陸内部も枯渇していない
(見当は外れた)。海岸距離 × 気温の 2 元表では、**列方向(寒くなる)に 250 倍
落ちるが行方向(遠くなる)には落ちない**。最も冷たい列は海岸 250km でも
0.02mm しかない。拡散長 706km の**内側**にいるので、指数減衰では説明できない。

同じ枠でモデル/観測の降水を比べると、南極以外にも系統誤差が 3 つある:

- 暑い列(25°C〜)は全域で湿りすぎ、**内陸ほどひどい**(1.07 → 1.80)。
  観測は内陸で減るのにモデルは増える。
- 2000km を超えるとどの列でも湿りすぎ(1.34〜1.89)。
- 10〜25°C の列は逆に乾かしすぎ(0.49〜0.75)。C 温帯が B に食われる症状。

**「広すぎる/狭すぎる」の一言では書けない。**

## 4. 較正の向きが物理と逆を向いている(独立な証拠)

[診断_較正が探索空間の端に張り付いている](診断_較正が探索空間の端に張り付いている_2026-08-15.md)。

62 定数のうち **20 件が探索範囲の端**にある。決定的なのは中身で、
**水を均す方向の定数が 6 つ同時に天井へ当たっている**:

```
渦拡散 99.1% / 降水の月ブレンド 100% / ハドレー追加拡散 100% /
ストーム湿気の到達距離 96.4% / 冬季床の割合 95.1% / 同上限 88.0%
```

歴代の較正結果を辿ると**時系列でも出ている**:

```
                              v15     v16cons  v20      v22
warmHumidConvectiveBoost      0.032   0.064    0.0208   0      ← 能動的に切られた
itczHemisOffsetPerC           0.453   —        0.605    0      ← 能動的に切られた
moistureEddyDiffusivityM2PerS 1.50e6  1.50e6   2.06e6   2.98e6 ← 天井へ登り続けた
```

**均す方向へ押し、構造を作る機構を 0 まで消している。**
理由も説明がつく — 目的関数はケッペン一致率で、均せば中位が当たり、
外れる端は面積が小さい。**目的関数が、物理として直したい方向と逆を向く。**

**これは次の再較正の設計に直接効く。** 乾いた端の機構を入れても、
再較正が均す定数を上げて打ち消しうる。結果は v3 だけでなく
**乾いた端の分位が保たれているか**を並べて読むこと。

## 5. 段 22 — **道具の壁に当たっている。物理の結論はまだ書けない**

掃引の結果、**virga の水準はすべて適用範囲外**だった。
外側反復が 216 / 204 か月ぶん未収束で、事前登録の判定 1 に掛かる。

```
係数   秒     v3      大分類  詳細   1%分位  5%   50%   virga未収束
 0    319s  85.235  74.49  44.88    64    88   468      0 件   ← 基準
 1    650s  84.567  73.94  44.66    35    62   454    216 件   ← 適用範囲外
 3    732s  83.068  72.93  43.78    ―     ―    ―     204 件   ← 適用範囲外
```

**1% 分位が 64 → 35 と動いてはいるが、これは未収束の解の数字なので読まない。**
事前登録の規定であり、段 20 で前任者が踏んだ穴でもある。

`VIRGA_OUTER_ITERATIONS = 6` が足りるかは**一度も確かめられていなかった**
(実装のコメント自身が「収束を確かめたうえで使う」と書いているのに)。
残差列を追うと **発散ではなく緩慢**で、隣接比 0.90〜0.94、
許容 5e-3 まで 50 回前後が要る
([診断_virgaの外側反復は緩慢](診断_virgaの外側反復は緩慢_2026-08-15.md))。

**この時点で「virga は効かない」と書いたら、道具の欠陥を物理の結論として
記録することになる。** それが前世代の最頻の死に方だった。

いま走っているのは `scripts/exp_virga_budget.ts`(上限 6/12/24/48)。
**測るのは残差ではなく「上限を変えたときに乾いた端の分位が動くか」**である。
動かなくなれば上限は答えを決めていないので、その値を既定にしてよい。

なお `VIRGA_RELAXATION = 0.6` という**緩和が既に入っている**。緩慢な収束に
対して緩和は逆効果で、比 0.906 から逆算すると素の写像は L = 0.843。
**緩和を外すだけで 46 回 → 27 回**になる見込み(未検証)。
緩和は不動点を変えないので、これは物理の変更ではなく解き方の変更である。

### 段 22 の当初の設計(参考)

[事前登録_乾いた端](事前登録_乾いた端_2026-08-15.md)。
保存型の雲底下再蒸発(`subCloudEvapCoef`、既定 0)を 0/1/3/6/12 で掃く。

選んだ理由:

- 「弱い雨ほど多く失われる」形で、**乾いた端だけを選択的に削る**演算子。
- 保存型では削った水が気柱に残って下流で降るので、
  **「乾いた端から中位へ動かす」**形になる(今まさに必要な形)。
- [計画_保存則の段階的置換](計画_保存則の段階的置換_2026-08-09.md) §1 に
  「保存型で測り直す価値がある」と書かれたまま**一度も実行されていない**。
- **較正の探索空間に入っていない**ので、0 は較正の結果ではない。
- 2026-08-04 に非保存で測った結果は**別の演算子**の結果であり、棄却根拠にならない。

判定は事前登録で固定済み。結果を見てから緩めないこと。
