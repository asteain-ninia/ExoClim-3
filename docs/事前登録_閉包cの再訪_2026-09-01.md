# 事前登録: 凝結閉包 c の再訪 — 鎖が繋がった後で「水をためる」は買われるか

日付: 2026-09-01(測る前に書いた)
文脈: v42 採用直後。冬雨型の時計分解(out/diag_winter_decomp_v42.log)で
中緯度 35-60 の宿題が確定した — **G の暦は正しい(condRateG 12.3 月・
振幅 0.48)のに、W が夏型(7.7 月・振幅 0.50)で降水を 10.8 月へ引く**。
観測ピークは 1.1 月。残差 −2.3 か月は「冬の W の崩落」が原因。

## 機構仮説(結果に依存しない)

凝結閉包(2026-08-26 実装)C = lin·W + conv·(W−cap)⁺、
lin = (1−c)·rate_old + c·bg、cap = RHcrit·W_sat(T)/G。
- c を上げるほど排水が「G 直結の rate_old」から「遅い背景 + cap 超過対流」へ
  移る。**冬は寒く(W_sat 小)G が大きいので cap が下がり、凝結効率が
  相対的に冬>夏になる** — 分解が要求する「冬の効率 2〜3 倍」の正しい住所。
- c は v36 系で SPACE にあり、v40/v42 とも **0.132** で着地。ただしその判定は
  reach(亜熱帯の冬の持ち上げ)不在の時代のもの。v42 で
  bg 凝結時定数が上限 90 日に張り付いた =「水をためたい」勾配は立っている。
- 本日の教訓(stormTrackBoost の下限剥がれ): 「均す」に負けるのは機構が
  孤立しているとき。鎖(T_bl・reach・2 温度場)が繋がった今、再掃引する価値。

## 掃引と測定

c ∈ {0.132(v42 基準), 0.4, 0.7}(1°・v42 採用定数・他は不変)。測るもの:
- 帯×季節型の位相表(35-90 冬雨の RMSE/符号が主標的)
- fitness・大分類・詳細・気温 RMSE・主要ゲート share
- 分位(乾いた端 1%/5%)— 均し戻りの監視([[exoclim3-width-is-in-w]] の教訓)

## 判定(同日): 68 ✗ — c は冬雨を殺す。機構推論の誤りを記録する

掃引実測(1°・v42 定数、out/sweep_closure_c_v42.log):

```

```

- 68 ✗✗: 冬雨は**逆方向**(さらに早く・さらに悪く)。誤りの構造:
  **rate_old ∝ G こそが「冬に効く排水」だった**(condRateG が 12.3 月ピークな
  のはこの経路)。c を上げる = (1−c) を下げる = 冬の凝結の重みを削り、
  夏に溜まった W を秋の cap 降下で吐かせる。「冬の効率」の住所を取り違えた。
- 69 ✗(118.6→121.7)。70 ✗(c=0.7 で −2.2)。71 ○(RMSE・健全性は無傷)。
- **副産物(登録外の事実、判定には使わない)**: c=0.4 で大分類 76.46・
  詳細 45.99(v42 超え)。c↑ で乾いた端が改善(1% 分位 76→59、観測 9 へ
  接近)・gobi 0.261→0.430・central_asia 0.195→0.314。代金は東岸湿潤の
  壊滅(east_asia 0.006・argentina 0.000)と位相。**「c は乾燥帯と分布の
  道具であって冬雨の道具ではない」**が正しい読み。分布・乾燥章で再訪する
  価値がある(その時は東岸を守る鎖 = 輸送の冬到達が先)。

**帰結(登録どおり ✗ 分岐)**: 35-90 冬雨の最後の容疑者は
**「輸送が冬に陸へ届かない」**。冬の W の由来分解(局所蒸発 対 移流)へ。

## ✗ 分岐の実測(同日): 輸送は届いている — 暦が秋の写し

予測(移入 ≈ 0)は**外れ** — 輸送は主役(82%)だった。不足は
(1) 移入の暦が秋(上流海洋 W の 9 月ピークの写し)、(2) DJF の量が観測の 56%。
移入 ≈ W_海 × 風。風が季節を持たなければ移入は W の暦の写しになる。
実物は冬に西風が倍増(熱風バランス: 子午温度勾配 ∝ 冬)して 12〜2 月を保つ。

**次の機構仮説: 冬の西風強化(熱風リンク)** — 2 温度場の ∂T_a/∂y から
月別の帯状風スケールを作る(地理中立・場駆動)。まず現状の西風の季節性を
実測して「風が平坦」を確認してから設計する。
亜熱帯の「夏が消えない」は別戦線(沈降・G の夏)として登録。
