# 診断: 供給ゲート 2 つが形骸化 — 「乾いた端が作れない」の一因の疑い

日付: 2026-08-17
道具: `scripts/diag_norm_saturation.ts`(新規)
出力: `out/diag_norm_saturation.txt`

## 結果

陸セル×月(|lat|≤60°、138,936 標本)で、被ゲート量の分布と norm を突き合わせた。

```
供給 supply の分布   5% 分位 0.63 / 中央 7.43 / 95% 分位 19.31

norm 定数                        値      飽和率(供給 ≥ norm)
eastReliefSupplyNorm           0.511      96.2 %   ← **形骸化**
itczLiftSupplyNorm             0.600      95.3 %   ← **形骸化**
warmHumidSupplyNorm            2.590      78.1 %      生きている
moistureConvergenceNorm        2.000      45.9 %      生きている
convergenceWetnessNorm         3.000      75.4 %      生きている
landCloudSupplyNormMm        109.1        18.6 %      生きている
```

## 何が起きているか

`min(1, 供給/norm)` 型のゲートは、norm が供給の分布の下に沈むと**常時全開**になる。

- **東岸緩和の供給ゲート**(96% 飽和): 「暖かいが乾いた流入の海(アラビア海)を
  自動除外する」ために置かれた(2026-07-31)。**その防護が事実上外れている。**
- **ITCZ 持上げの海洋性ゲート**(95% 飽和): 「傘は湿潤収束が豊富なときだけ開く
  (乾いた内陸のトラフ直下は乾いた低気圧のまま)」の設計。**これも外れている。**

原因はほぼ確実に**保存型への移行(段 6)で供給の尺度が変わった**こと。
norm は旧尺度のまま取り残された(`moistureConvergenceNorm` で 8/15 に見つけた型の
再発。あちらは直したが、全数の棚卸しを今日までしていなかった)。

**さらに悪いことに、この 2 定数は較正の探索空間に入っている**:

```
['itczLiftSupplyNorm', 0.6, 1.8]      ← 範囲全体が供給の 5% 分位(0.63)近傍以下
['eastReliefSupplyNorm', 0.4, 1.2]    ← 同上
```

範囲のどこへ動かしても飽和率はほぼ変わらない。
**v25 はいま、実質的に死んだ範囲を探索している。**

## 仮説(次の掃引で確かめる)

> **「乾いた端が作れない」(1% 分位 64mm 対 観測 9mm)の一因は、
> 乾いた場所を乾いたまま保つために置かれた供給ゲートが、
> 移行で全部開きっぱなしになったことではないか。**

ゲートを生き返らせる(norm を分布の中、例えば 3〜12 へ)と:

- 供給の薄い場所(砂漠)で ITCZ 持上げ・東岸緩和が絞られる → **乾いた端が乾く**
- 供給の厚い場所(C→B の華中型、供給 ~10)はゲート ≈ 1 のまま → **傷まない**
- 段 45(コンベア)が頼る予定だった「量の連鎖による判別」が、
  既存の配管でいくらか復活する

## 次

2. `eastReliefSupplyNorm` も同様。
3. 効くなら SPACE の範囲を分布に合わせて引き直し、v26 として較正

## 教訓(3 例目で規則化)

**尺度を持つ量の移行をしたら、その量を参照する norm・閾値を全数棚卸しする。**
`moistureConvergenceNorm`(8/15)・`eastReliefSupplyNorm`・`itczLiftSupplyNorm`(本日)
— すべて段 6 の保存型移行の取り残し。移行チェックリストに
「参照側の定数の分布照合」を入れるべきだった。`diag_norm_saturation.ts` を
移行後の定例検査として使うこと。
