## いちばん重い読み: **水を均す方向の定数が軒並み上限にある**

```
moistureEddyDiffusivityM2PerS   99.1%   水蒸気の渦拡散（空間の平滑化）
precipMonthBlend               100.0%   降水の月ブレンド（時間の平滑化）
hadleyDiffusionBoost           100.0%   ハドレー循環域の追加拡散
stormMoistureDecayKm            96.4%   ストーム由来の湿気が内陸へ届く距離
winterFloorFracOfWettest        95.1%   冬季床の再配分（最乾月を持ち上げる）
winterFloorMaxMm                88.0%   同上の上限
```

**目的関数は「もっと均せ」と言い続けて、6 つの天井に同時に当たっている。**

これは [診断_乾いた端が作れない](診断_乾いた端が作れない_2026-08-15.md) の
実測と正確に噛み合う。南極を除いた陸で、モデルの降水の対数標準偏差は
**0.429、観測は 0.530** — **モデルは既に均されすぎている**のに、
較正はさらに均す方向へ押している。

なぜそうなるかも説明がつく。目的関数は**ケッペン一致率**である。
均せば中位のセルが当たりやすくなり、外れるのは分布の端 —
**端は面積が小さいので、均すほうが得**になる。
つまり **目的関数が、物理として直したい方向と逆を向いている。**

## 次に問うこと(この診断からしか出てこない)

1. **範囲の外は物理的に妥当か。** 渦拡散 3e6 m²/s は中緯度の総観規模輸送
   としては既に大きい側である。**上限を上げるべきではない。**
   むしろ上限に当たっていること自体が、他の欠陥の補償である疑いを強める。
2. **その定数は別の欠陥を補償していないか。** 補償なら範囲を広げても直らず、
   補償される側の欠陥が残るだけである。
   渦拡散が最大なのは「乾いた端を作る機構が無いので、せめて中位を当てる」
   という補償に見える。段 22 で乾いた端の機構を入れたとき、
   **再較正が渦拡散を下げるかどうか**が、この読みの検証になる。
3. **機構が丸ごと切られている 2 件**(`warmHumidConvectiveBoost` = 0、
   `itczHemisOffsetPerC` = 0)は、切られたのか一度も動かされなかったのかを
   分けていなかった。**歴代の `out/optimize/best_*.json` を辿って確かめた
   (同日中)** — どちらも**較正が能動的に 0 まで押し下げている**。

```
                              v15      v16cons    v20        v22
warmHumidConvectiveBoost      0.032    0.064      0.0208     0      ← 切られた
itczHemisOffsetPerC           0.453    —          0.605      0      ← 切られた
moistureEddyDiffusivityM2PerS 1.50e6   1.50e6     2.06e6     2.98e6 ← 天井へ登り続けている
```

**これは snapshot ではなく時系列なので、上の読みの証拠として格が高い。**
渦拡散は 1.50e6 → 2.06e6 → 2.98e6 と**単調に上がり続けて天井に当たった**。
同時に、局所の構造を作る機構(高温湿潤の対流増幅・ITCZ の半球オフセット)は
**0 まで消された**。

**均す方向へ押し、構造を作る方向を消す** — 目的関数の向きが 2 つの独立な
形で現れている。

## 段 22 への含意(先に書いておく)

**再較正で打ち消される可能性が高い。** 目的関数は均す方向を好み、

`landRecyclingStrength` 66.1% など)。
