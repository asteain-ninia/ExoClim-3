## `landCloudBoost` を探索空間へ入れない理由

v3 は boost を上げると**単調に下がる**:

```
boost   0      0.15    0.3     0.5
v3      85.77  85.34   83.60   75.45
```

一方で詳細一致・第 3 文字・年較差は改善する。低下しているのは大分類で、
原因は「効きすぎる帯で D が E へ落ちる」こと。**他の定数(移流結合・OLR・拡散)
が平均を戻せば取り返せる性質の低下**である。

しかし探索空間へ入れると、座標降下は**補償が見つかる前に boost を 0 へ戻す**。
これは既知の失敗様式で、教訓 §9 に「座標降下は谷を渡れない」として
記録がある(陸の熱容量と東西移流結合で同じことが起きた)。

したがって:

- **強さ `landCloudBoost` は構造として固定**(0.2)。
- **効く場所の分布を決める `landCloudSupplyNormMm` は探索空間へ入れる**
  (範囲 40〜200mm/月)。60〜70°N の効きすぎを緩める向きに動けるようにする。

0.2 を選んだのは、単発で詳細一致が純増した 0.15 と、主判定を満たす 0.3 の
中間だから。**この値は隠しパラメータではない** — constants.ts に根拠つきで
書かれ、この文書に選定理由が残る。

## 較正後に必ずやる確認

較正が収束したら、**`landCloudBoost` を探索空間へ入れて短い降下を追加する**。
そこで目的関数が boost を 0 へ押し戻すなら、
「他の定数で補償してもなお v3 は雲を欲しがっていない」ということなので、
その事実ごと記録して採否を考え直す。押し戻さないなら谷を渡れていたことになる。

## 採否の判断

従来どおり 5 点で総合判断する。単発の主判定成立は採用ではない。

1. 数値的健全性(必須): EBM 残差 < 1e-3、年次ドリフト < 0.05
2. 新旧両目的関数(v3 と v2)
3. 季節指標(年較差 RMSE・季節位相・第 3 文字の一致)
4. 地域ゲート 17 件
5. 未見評価(空間ホールドアウト 5 区画)
