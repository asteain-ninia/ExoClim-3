# 実験記録: 段 1 — 降水を「凝結」から作る。**水が閉じた**

日付: 2026-08-09
計画: [docs/計画_保存則の段階的置換_2026-08-09.md](計画_保存則の段階的置換_2026-08-09.md)
道具: `scripts/exp_conservative_stage1.ts`

## 段 0 で判明したこと — 現行モデルは水を 64% 創っていた

```
段 0（現行・非保存）
  E 全球  913 mm/年（海 1076 / 陸 513）
  P 全球 1497 mm/年（海 1812 / 陸  719）
  閉包 (P−E)/E = +63.9%
```

**蒸発した量より 64% 多く降っている。** 海上では蒸発 1076 に対し降水 1812 で **1.7 倍**。

この量はこれまで一度も測っていなかった。非保存であることは分かっていても、
**どれだけ非保存なのか**は誰も知らなかった。

意味を考えると重い。降水は `供給 × 乗数 × precipScaleMmPerUnit` で作られ、
その換算定数は**陸の降水が観測に合うよう較正されている**。つまり:

- 陸(742mm、観測 794)は合わせ込んである
- **その代償として海が 1.7 倍になっている**
- 海の降水は採点されていないので、誰も気づかなかった

外部レビュー(Fable、2026-08-09)の

> 海が一切採点されていない。海が全部間違っていても陸の帳尻で 75% は出せる

は、**この現象そのものだった**。実際に帳尻が合わされていて、余った水は海に捨てられていた。

## 段 1 の結果

```
                     段 0（非保存）      段 1（保存型）
E 全球                 913 mm/年         909 mm/年
P 全球                1497 mm/年         909 mm/年
閉包                  +63.9%  ×          −0.0%  ○
海の降水              1812              1031（蒸発 1084 とほぼ釣合い）

v3                    86.180            80.428   −5.75
大分類                 75.36             71.50   −3.86
詳細                   45.00             41.20   −3.80
ゲート                    14                13   −1
陸平均降水               742               608   （観測 794）
**降水の季節位相**      77.18 日          71.80 日  **−5.4 日**
```

### 水は完全に閉じた

**64% の水の創造が消えた。** 換算定数 `precipScaleMmPerUnit` は保存則の中では
置き場所が無いので、降水の絶対量は収支だけで決まっている。

### 成績は予告どおり落ちた

事前登録で「v3 が 5 ポイント落ちても、保存が閉じていて源泉が正しいなら進む」と
宣言した、ちょうどその範囲。**ここで引き返さない。**

### 季節位相が改善した — 保存則を入れる価値の最初の証拠

**乗数を 1 つも外していない段階で、輸送を入れただけで 5.4 日縮んだ。**

位相は「いつ降るか」なので、乗数の積では原理的に作れない
(乗数は「どれだけ降るか」を変えるが、水がいつそこに在るかは輸送が決める)。
段 1 は乗数を一切触っていないので、**この 5.4 日は純粋に輸送の寄与**である。

## 追記: 収束を確認した — 判定 1 は完全に通った

反復上限を 4000 → 20000 へ上げて回し直した:

```
                  上限 4000        上限 20000
収束しなかった月      84 件            **0 件**
最悪の残差         3.84e-5           0.00e+0
v3                80.428            80.413   （差 0.015）
季節位相           71.80 日          71.68 日
```

**上限を 5 倍にしても答えが変わらない**(v3 の差 0.015 は目的関数の数値的な床
0.02 未満)。反復上限が答えを決めていないことが確認できたので、
**段 1 の数字は正式なものとして扱える**。

段 1 の確定値:

```
                段 0        段 1
閉包            +63.9% ×    −0.0% ○
v3              86.180      80.413
大分類           75.36       71.49
詳細             45.00       41.19
季節位相         77.18 日    71.68 日   −5.5 日
陸平均降水        742         608（観測 794）
```

## 判定 1 の経緯(記録) — 最初は未収束だった

```
収束しなかった月 84 件 / 最悪の残差 3.84e-5 / 反復合計 457573
```

閉包は完璧だが、輸送が既定の反復上限(4000)内で収束していない。
残差 3.84e-5 は許容差 1e-5 の 4 倍で実質ほぼ収束しているが、
**「収束していない解は採点しない」という規律に従えば、上の成績はまだ正式な数字ではない。**

EBM で 3 回踏んだ「上限が答えを決める」隠しパラメータと同じ型なので、
上限を 20000 へ上げて収束させ、成績が変わらないことを確認する。

## 途中で踏んだ誤り

`conservativeMonth` を `soil` の宣言より前に置いたため、TDZ で
`Cannot access 'soil' before initialization` になり 1 回目が落ちた。
宣言を前へ出して解決。**型検査は通るので、実行するまで気づけない**種類。

## 次

1. 反復上限を上げて収束を確認(成績が変わらないことを確かめる)
2. 段 2〜5: 補償だった乗数を 1 つずつ外す(`exp_conservative_stages.ts` で用意済み)

**外したのに悪化しない乗数は、保存の欠落を補っていた**ことの証明になる。
