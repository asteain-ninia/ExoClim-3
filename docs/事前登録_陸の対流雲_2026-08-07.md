# 事前登録: 陸の対流・前線雲(R1b)

日付: 2026-08-07
対象: 冷帯の夏が +5°C 暑すぎる問題への第 2 の手
**結果を見る前に書いて確定させる。**

## R1(蒸発帰還)がなぜ届かなかったか

∂LE/∂T を EBM の対角へ入れる案は、frac = 0.5 で
**40〜50°N が +4.77 → +4.98、50〜60°N が +5.38 → +5.47 と逆方向**に動いた。

理由は着想の側にある。線形化した項

```
k·(T − T_ref)
```

は **前パスの気温 T_ref へ引き戻す項**であって、冷やす項ではない。
外側の反復が収束すれば T → T_ref となり、項そのものが消える。
数値的な安定化にはなるが、**平衡状態を動かす力を持たない**。

## 見つかった構造的な欠落

`step05_temperature.ts` の雲アルベドの変調を読み直したところ、
**海側の項がすべて `oceanFrac` 倍で入っていた**:

```ts
K.stormTrackCloudBoost * stormW * oceanFrac      // 陸は 0
K.stratocumulusBoostPerNegC * ... * oceanFrac    // 陸は 0
K.channelCloudBoost * oceanFrac                  // 陸は 0
```

陸で雲が増えるのは ITCZ 近傍(`convectiveCloudBoost * itczInf`)だけ。
つまり **中高緯度の夏の大陸は、月 100mm 以上降っていても雲が基準値のまま**になる。
実在の夏のシベリア・カナダの雲量は 6〜7 割ある。

これは既に測った事実と符合する:

```
50〜60°N  最暖月ずれ +5.38°C   夏の降水 235 → 336mm(+43%)   湿り 0.928
```

**水は届きすぎているのに冷えない。足りないのは日射を削る側だった。**

## 何を変えるか

前パスの降水を**飽和させて**雲の因子に足す:

```
landCloud = landCloudBoost · 陸率 · min(1, 月降水 / landCloudSupplyNormMm)
factor += landCloud
```

飽和させるのは、**降水の誤差がそのまま温度の誤差へ増幅されるのを防ぐ**ため。
2026-07-30 に蒸発冷却を降水で代用して破綻した罠を繰り返さない造りにする。
`landCloudSupplyNormMm = 80` は「月 80mm 降れば雲は飽和」という意味で、
これを超える過大な降水は雲を増やさない。

地理中立である: 局所の陸率と降水の関数で、緯度も大陸も見ない。
他の惑星でも「よく降る陸は曇る」は成り立つ。

雲アルベドは CPU で作って GPU へ渡す場なので、WGSL の変更は要らない。

## 予測(事前に書く)

- 効くのは**夏の中高緯度の陸**。冬は降水が少なく、日射も小さいので動かない。
- **砂漠は動かない**(降水がほぼ 0 なので飽和項が 0)。乾燥ゲートは維持されるはず。
- 熱帯は既に `convectiveCloudBoost * itczInf` で曇っているので、
  二重に曇らせて冷やしすぎる恐れがある。**アマゾン・コンゴのゲートを見る。**
- 大きさの見積り: 基準雲アルベド ≈ 0.2 に対し boost 0.4 で 0.28。
  惑星アルベドの差 ≈ 0.07、夏の 55°N の日射 ≈ 400 W/m² で 28 W/m²。
  大陸規模の実効減衰を 5〜10 W/m²/K とすると **3〜6°C** の冷却。桁は合う。

## 判定条件

### 主判定

- 観測 D 帯の最暖月ずれが **40〜50°N と 50〜60°N の両方で +3.0°C 以下**
  (現在 +4.77 / +5.38)

### 副判定

- **D の第 3 文字の一致が 45% 以上**(現在 31.3%)
- **乾燥ゲート 3 件を維持**(sahara / arabia / australia)
- **熱帯ゲート 2 件を維持**(amazon / congo)— 二重に曇らせていないことの確認
- **数値的健全性**: EBM 残差 < 1e-3°C、年次ドリフト < 0.05°C

### 棄却条件

- `landCloudBoost` を **0.15 / 0.3 / 0.5** の 3 段階試して主判定に届かなければ棄却。
  そのときは「冷帯の夏は雲でも動かない」と結論し、
  `diag_boreal_levers.ts` の感度表から次の候補を選ぶ。
- 乾燥ゲートまたは熱帯ゲートが落ちたら、その設定は不採用。

### 棄却した場合の次善策(先に書いておく)

コードには**陸の雲を意図した痕跡が残っている**:

```ts
const stormSeason = isStormWinter ? 1 : 0.35 + (K.stormCloudSummerOcean - 0.35) * oceanFrac;
...
K.stormTrackCloudBoost * stormW * oceanFrac   // ← 外側で 0 倍される
```

`stormSeason` は陸(oceanFrac = 0)でも 0.35、冬なら 1 を返すよう書かれているのに、
使う側が `oceanFrac` を掛けるので**陸では必ず 0 になる**。書いた本人の意図と
実際の効きが食い違ったまま残っている死んだ分岐である。

R1b が棄却された場合は、この `* oceanFrac` を外して陸にもストームトラック雲を
効かせる案(定数 1 つで陸の残存率を持つ)を次に試す。ただし
**幾何だけで決まり水の量を見ない**ので、大陸内部の夏の対流雲は表現できない。
先に降水駆動(R1b)を試すのはそのため。
