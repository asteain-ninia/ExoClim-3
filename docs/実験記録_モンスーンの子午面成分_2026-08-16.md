日付: 2026-08-16

## まず配線を 1 度間違えた

初版の掃引は**全 4 水準がビット一致**した。原因は駆動源の選択で、

```
crossEq  = crossEquatorialMonsoon(既定 0) × disp × turn   → 常に 0
meridRev = 1 − 2 × crossEq × 新定数                        → 常に 1
```

**新しい定数は「0 に何を掛けるか」でしかなかった。**
さらに `crossEq` の適用範囲は「赤道と ITCZ の間」で、ITCZ は夏でも 20〜25° までしか
北上しないため、**狙った亜熱帯(30〜37°)には最初から届かない**設計だった。

駆動源を **ITCZ の変位そのもの**へ、適用範囲を **ITCZ の極側からリッジまで**へ直した。
教訓 §9 に「新しい定数を既存の量に掛けるとき、その量が 0 でないかを確かめる」として追記。

## なぜ成績が伸びなかったか — **「運ぶ」ではなく「均す」機構だった**

分布の動き方が答えを示している。

```
係数 0.0 → 1.0 で
  1% 分位   64 → 74     観測 9 から**遠ざかる**
  50% 分位 532 → 553    観測 596 へ近づく
  99% 分位 3015 → 2924  観測 3393 から**遠ざかる**
  分布誤差 0.404 → 0.439（悪化）
```

**両端が中央へ寄っている。** これは 2026-08-16 の渦拡散の掃引で見た形と
**符号まで同じ**である(拡散を強めると両端が潰れる)。

地域比はすべて改善している(インド +0.04、米南東 +0.02、東アジア +0.02)。
**乾いた地域が一様に湿り、湿った地域が少し乾く** — つまりこの機構は
水を「特定の場所へ運ぶ」のではなく、**全体をならしている**。

### なぜ均しになったか

子午面成分の反転を**貿易風帯の全経度に一様に掛けた**ためと考えられる。
実物のモンスーンは**大陸の東岸という特定の経度**で強く、海上では弱い。
モデルは ITCZ の変位(経度ごとに違う)で強さを変えてはいるが、
**海陸のコントラストそのものは見ていない**。

その結果、海の上でも一様に極向き流が立ち、水蒸気が帯状に広く配られる。
これは拡散と同じ「勾配を均す」作用になる。

## 得られたもの(採用しなくても価値がある)

1. **半月間どの機構も動かせなかった「亜熱帯の夏の南風」を、初めて動かせた。**
   風の定義に手を入れれば動くと分かったこと自体が前進である。
2. **「風を直せば成績が上がる」わけではないと分かった。**
   風は物理的に正しくなった(赤道向き → 中立)のに、目的関数は下がる。
   運ぶ向きだけでなく**運ぶ場所の選択性**が要る。
3. **今日 3 つの機構が同じ壁に当たった。**

   | 機構 | 何をした | 結果 |
   | --- | --- | --- |
   | 渦拡散を下げる | 均すのをやめる | 両端は直るが内陸が乾く |
   | 段 39 西方張り出し | 局所の気圧を上げる | 副作用は無いが桁が足りない |
   | 段 41 子午面反転 | 風の向きを直す | 風は直るが**均しになる** |

   **共通するのは「経度方向の選択性」が無いこと。** 拡散は選択性がゼロ、
   段 39 は選択性はあるが振幅が足りず、段 41 は振幅はあるが選択性がない。
   **次に作るべきは「振幅があり、かつ海陸で効き方が変わる」機構**である。

## 次(設計の方向)

段 41 の骨格は残し、**強さを海陸のコントラストで変調する**のが素直な次の一手。
`troughLandFrac`(経度列の熱帯陸割合)は既に step02 が計算しており、
モンスーントラフの増深に使われている。同じ量で子午面反転を変調すれば、
**陸の多い経度でだけ極向き流が立つ**。配管の追加は小さい。

ただし**今日はここまでにする**。同じ日に 3 つの機構を試して 3 つとも
「向きは正しいが足りない」で終わっており、**設計の当てずっぽうを続ける段階ではない**。
次は測定から入る — 実物のモンスーンが「どの経度で、どれだけの子午面風を持つか」を
観測データ(教師データの降水の季節性)から逆算し、**目標値を先に決めてから**設計する。
